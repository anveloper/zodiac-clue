## 2. 아키텍처 / 배포 방침 (논의 결론)

### 2.1 레포 & 배포
- **레포는 public 확정** — 과제가 public 권장 + 링크 접근유지 요구. private는 배포 유료화·심사계정 초대 부담만 큼.
- 배포 방식은 게임 형태에 따라:
  - **정적(클라이언트 only)** → 조직 공개 레포 + **GitHub Pages** (무료, 팀 협업 관리 편함)
  - **런타임 백엔드 필요** → **개인 공개 레포 + Vercel Hobby** (조직 GitHub 레포는 Hobby에서 마찰 가능)

### 2.2 실시간 AI & 콜드스타트
- **프레임 단위 실시간** → 서버리스 부적합. 온디바이스(WebLLM/transformers.js/WebGPU)로 콜드스타트 원천 제거(정적 배포 가능)
- **이벤트 단위(턴·대화·생성)** → 서버리스로 충분. 콜드스타트 완화책:
  1. Vercel **Fluid Compute**(warm 유지) 2. **Edge Runtime**(콜드스타트 ~0) 3. **스트리밍**(체감지연↓) 4. **워밍업**(로딩 화면 예열) 5. AI를 핫루프에서 빼는 **설계 회피**
- 현실적으로 이벤트 단위에선 콜드스타트보다 **LLM TTFT**가 더 큰 병목 → 스트리밍+워밍업이 체감 효과 큼

### 2.3 AI 제공자 — Gemini 무료티어 기준
- **전 구간 무료 사용 원칙**. 1차로 **Gemini API 무료티어** 내에서 설계.
- 데모 안정성이 진짜 관건(심사자가 직접 플레이 → 한도 걸리면 게임 죽은 것처럼 보임):
  1. **RPM/RPD/TPM 한도** 내 설계 (배포 전 최신 한도 재확인 필수 — 자주 바뀜). Flash/Flash-Lite 계열이 무료 한도 넉넉.
  2. **호출 최소화**: 매 프레임 ❌ → 이산 이벤트 + 디바운스/캐시
  3. **레이트리밋 graceful fallback**: 429 시 규칙기반 대체로 끊김 없이
  4. **키 클라 노출 금지**: public 레포 → 키는 서버리스(Edge) env 로만, 커밋 금지
  5. 무료티어는 입력이 모델 개선에 쓰일 수 있음 → 민감정보 금지(게임이라 대개 무방)

## 3. 게임 아이디어 방향

> ✅ **2026-07-18 2차 회의에서 방향 Ⓖ(클루 기반 소규모 퍼즐 추리 + AI NPC)로 컨셉 확정.** 상세·미확정 항목은 `docs/meetings/20260718-meeting-notes.md` 참고. 이전 유력안(Ⓕ 방치 홀덤)은 보류.

### 방향 A — "하루 한 번 생성" AI 랜덤 요소 기반 게임
- 포맷 후보: **퍼즐 / 방탈출 / 글자 맞추기(Wordle류)**
- AI가 하루 1회 정도 콘텐츠(문제·시나리오·정답)를 **생성**하고, 그날 모든 플레이어가 공유
- ✅ 장점:
  - **무료티어와 궁합 최상** — 생성 1회/일 → 사전 생성 후 정적 서빙 가능. 레이트리밋·콜드스타트 거의 무관.
  - Wordle/"오늘의 문제" 형식 = 익숙하고 바이럴성 있음
  - GitHub Pages 정적 배포로도 성립 (생성은 cron/오프라인, 결과만 배포)
- ⚠️ 고려:
  - AI 런타임 풋프린트가 작음(1회/일) → "AI가 코어다"라는 인상을 어떻게 확실히 줄지 설계 필요
  - 심사자가 1세션만 플레이 → "매일 바뀐다"는 매력이 그 자리에서 안 보일 수 있음 → 생성 데모/즉석 재생성 버튼 등으로 보완

### 방향 B — 게임 속 NPC 랜덤성 대화 요소
- NPC 대사·반응을 런타임에 AI로 생성 (랜덤성·상황반응)
- ✅ 장점: "살아있는 AI"가 눈에 잘 보임 → 심사 인상에 직접적
- ⚠️ 고려: 상호작용마다 호출 → 레이트리밋·latency 노출 큼. 캐시·프리페치·fallback 설계 중요.

### 하이브리드 후보 (메모)
- **하루 생성(코어 콘텐츠) + 플레이 중 AI 힌트/심판**: 안정성(A) + 라이브감(B) 절충
- **일일 시드 + AI NPC 안내자**: 방탈출에 NPC가 문맥형 힌트 제공

### 방향 E — "포커 + 방치형 경제(부속 컨텐츠)" ★추가(2026-07-15, 제안: 2jonghun)
- **문제의식**: 포커 게임 이탈의 주원인 = **게임머니 소진 → 충전 장벽**. 잃으면 그만두게 됨.
- **해법(핵심)**: 포커로 번 게임머니로 **부속 컨텐츠**를 매입해 **소량 게임머니를 지속 수급**하는 인프라 구축 → 잔고 0 방지 → 리텐션↑.
  - 예: **"비트코인 채굴기"(방치형/아이들) 매입 → 시간당 소량 게임머니 생성.** (타르코프의 은신처 업그레이드로 자원 생성하는 루프 참조)
  - 채굴기 외 확장: 상점/거래소/업그레이드 트리 등 메타 경제 레이어.
- **NHN 정합 최상**: 포커=NHN 캐시카우(웹보드) 본업 그대로. 리텐션 개선은 NHN이 실제로 원하는 지표.
- **⚠️ AI 코어 연결 (해커톤 요건)**: 이 기능 자체는 경제/리텐션 설계라 **AI가 코어가 아님** → load-bearing 하려면 AI를 얹어야:
  - (a) **AI 포커 상대** — 성격·블러핑·"눈치보며 훔쳐보는" NPC (anveloper 초기 아이디어와 연결). AI 없이 못 만드는 상대 AI.
  - (b) **AI 시뮬 경제** — 채굴기 수익률이 AI가 굴리는 가상 시장/이벤트로 동적 변동, AI 트레이더 NPC와 흥정.
  - (c) **AI 코치** — 핸드 리뷰·전략 코칭·튜터.
- **⚠️ 규제 주의**: 게임머니는 반드시 **가상재화(현금 환전·현금 구매 없음)** 로 설계 → NHN 웹보드 '사행성' 규제 민감성 회피. '비트코인'은 **테마 명칭일 뿐 실제 암호화폐 아님**을 명확히.

### 방향 F — "NHN 주력 × 방치형(Idle) 하이브리드" ★추가(2026-07-15, 제안: 2jonghun)
- **시장 근거**: 방치형 게임 매출 비중 **2020년 1.7% → 2024년 16%(4년 10배)**, 방치형 RPG 1.6%→7.1%. 메이플키우기(구글 매출 1위), 세븐나이츠 키우기(하이브리드), 버섯커 키우기(세계 매출 ~5,200억, 한국 34%). → **플레이스토어 매출 상단의 메타 = 방치형**. (핵심 동력 = '자동플레이', 피로도 해소, 장르 융합)
- **방향**: NHN 주력(웹보드/포커/퍼즐/IP) × 방치형 편의성 결합. 세븐나이츠 키우기의 "기존 재미 + 방치 편의" **하이브리드 전략** 벤치마크.
  - 예: "한게임 포커/맞고 × 방치형 성장"(방향 E의 일반화), "방치형 보드 수집", "퍼즐 IP × 방치 성장 루프".
- **NHN 정합**: 본업(웹보드/캐주얼) + 지금 매출 상단을 먹는 방치형 트렌드를 얹음 = "매출 감각 + 당사 포트폴리오 이해" 동시 어필.
- **⚠️ AI 코어 연결(해커톤 요건)**: 방치형은 '자동플레이'가 핵심 → **AI를 자동플레이/성장의 두뇌로**:
  - (a) **AI 자동플레이 디렉터** — 플레이어가 자연어로 전략을 지시하면 AI가 방치 중 그 전략대로 운영·의사결정 (→ "AI를 디렉팅하는" NHN 철학 정확히 부합)
  - (b) **AI 동적 콘텐츠** — 방치 중 발생하는 이벤트/내러티브/퀘스트를 AI가 생성 (매번 다른 방치 경험)
  - (c) **AI 밸런싱** — 성장 곡선·보상을 AI가 개인화 조절
- **관계**: 방향 **E(포커+방치경제)** 의 상위 일반화. E를 F의 한 인스턴스로 볼 수 있음.

### 방향 D — "AI 규칙 추리 게임" (Zendo류 / AI가 심판) ★추가(2026-07-15)
- **코어 루프**: AI가 **비밀 규칙**을 하나 생성해 숨김 → 플레이어가 예시(카드 조합·단어·도형 등)를 제출 → AI가 "규칙에 맞음/틀림" **판정**(+선택적 힌트) → 플레이어가 규칙을 추론해 맞히면 클리어.
- **AI 역할 = load-bearing 끝판왕**: ① 열린 규칙 생성 ② 플레이어의 **자유형 입력을 규칙에 비추어 판정**. 입력이 자유형이라 규칙기반 하드코딩이 불가능 → **LLM만 가능. AI 빼면 게임 자체가 성립 안 함.**
- **무료티어 안정성**: 규칙 생성 1회/세션(또는 일일). 판정은 턴당 1콜(디바운스·캐시), 429 시 "판정 대기" 우아 처리. **프레임 호출 없음** → Gemini 무료 한도 안에서 안전.
- **NHN 정합**: 보드/추리/캐주얼 + 짧은 세션 + 매일 새 규칙(리플레이) → 웹보드·캐주얼 결과 정합.
- **차별화**: "AI가 심판인 추리 보드" = AI를 도구가 아니라 **게임 엔진**으로 설계 → NHN "AI 디렉터" 철학에 정확히 부합. NHN이 이미 잘 만드는 3매치 답습이 아님.
- **리스크 & 완화**: 판정 일관성(환각) → 규칙을 **구조화(JSON)** 해 프롬프트 고정 + 판정 근거 로깅/검증(제출물 ④ AI 기술문서에 그대로 서술 가능, CTO가 강조한 '환각 검증'과 연결).

### 방향 G — "AI 증인 추리 — 클루(Cluedo) 변형" ★확정(2026-07-18 2차 회의)
- **기반**: 보드게임 **클루**의 소거 추리(누가·무엇으로·어디서) 구조. **불완전 정보 + 소거 추리**가 코어.
- **차별점 = load-bearing AI**: 고정 카드 대신 **AI NPC 증인**이 정보원. 자유 심문(자연어) → NPC가 자연어 답변. **거짓말/은폐(정직|뇌물)** 축을 얹어 "믿을 수 없는 증언" 레이어 추가 → 클루보다 추리 깊이↑. 자유 심문 판정은 하드코딩 불가 → **LLM만 가능.**
- **컨셉안(미확정)**: 호랑이 생신 잔치, 동물들이 선물 도둑 → **반전: 진범은 호랑이 본인**(AI로 개입해 모른 척). 아트=전원 산적처럼 우락부락(다 범인 같아 보임).
- **디자인**: 소규모, 액티브 요소 적음. 2D 상하좌우 이동(귀귀살전 스타일), 맵=작은 대감집 규모.
- **⚠️ 안전 패턴**: 정답(진범·수법·장소)은 시작 시 **결정론적으로 고정** → AI는 정답을 아는 채 **일관되게** 정직/거짓 연기(진실값은 규칙엔진 관리, LLM은 말투·연기만) → 환각으로 "정답 없는 사건" 방지. 제출물 ④에 그대로 서술 가능.
- **⚠️ 열린 리스크**: **멀티 소켓 서버** 필요성 재검토(심사자 혼자 플레이·무료티어·스코프 충돌 → 싱글/비동기 우선 권장, 상세는 회의록 §3).
