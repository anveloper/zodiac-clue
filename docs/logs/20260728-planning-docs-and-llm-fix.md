# 20260728 — 기획 문서 세트 구축 + 배포 노출 차단 + LLM 폴백 장애 해결

> 07-27 낮 ~ 07-28 오전. 서브에이전트 병렬 검수 6라운드(에이전트 18개)로 기획을 갈아엎고,
> 그 결과를 문서로 확정한 뒤 배포까지 마쳤다. 마지막에 **배포본에서 LLM이 죽어 있던 원인**을 찾아 고쳤다.

## fix

### NPC 대사가 전부 규칙 폴백으로 나가던 문제 (`477c88b`)
라이브 서버에 직접 접속해 솔로 1판을 돌린 결과 **NPC 대사 5/5가 `fallbackLine`**이었다.
폴백 접미 `…아니라니 하나 지웠군`이 5건 바이트 동일했고 지연이 0.2~0.6초였다(LLM 경로는 ~1s).

원인 추적 순서:

| 검증 | 결과 | 해석 |
|---|---|---|
| `GET /v1beta/models` | `200` · 56개 | 키 정상 — 쿼터·인증 문제 아님 |
| `gemini-flash-lite-latest` + `thinkingConfig.thinkingBudget: 0` | **`400` INVALID_ARGUMENT** | ← 범인 |
| 동일 모델, `thinkingConfig` 미지정 | `200` · 정상 대사 (실프롬프트 5/5) | |
| `thinkingBudget: -1`(동적) | `200`이나 생각 토큰이 64 예산을 먹어 문장 잘림 | 0을 쓴 원래 이유가 이것 |
| `gemini-2.5-flash-lite`로 고정 | `404` 제공 종료 | 구버전 고정도 해법 아님 |
| `gemini-2.0-flash-lite` | `429` 쿼터 소진 | |

**`-latest` 별칭이 `thinkingBudget: 0`을 거부하는 세대로 이동**한 것이 근본 원인이다.
`if (!res.ok) return null` → 호출부가 폴백으로 대체 → **전 대사가 규칙 대사**.
코드 주석("flash 계열은 thinking 모델이라 꺼야 빈 응답을 막는다")은 이전 모델에선 옳았지만 지금은 파라미터 자체가 무효다.

**발견이 늦은 이유**가 더 중요하다 — 실패 로그가 `[narrate] HTTP 400`으로 **상태코드만** 남겼고,
폴백이 설계상 "캐릭터색을 유지"하므로 **육안으로 구분되지 않았다.** 조용한 폴백이 장애를 숨겼다.

조치: `thinkingConfig` 제거 + 실패 로그에 응답 본문 앞부분 포함.
배포 후 라이브 재검증 **12/12 LLM · 폴백 0**.

> 호랑이 대감: "어디 감히 토끼 낭자가 부엌에서 금고를 건드렸단 말이냐, 당장 그 허황된 소리를 거두거라!"

### 배포 산출물에서 내부 문서 제외 (`d4205f7`)
매니페스트에서 빼도 `cp -r docs`가 전체를 복사해 **직접 URL로 접근이 가능**했다.
제출물 ③의 CTA가 심사자를 이 트리로 안내하므로 실제 노출 경로였다.
`scripts/docs-private.mjs`(제외 목록 단일 소스) + `copy-public-docs.mjs`(필터 복사)로 교체.
배포 후 실제 URL 검증 — 공개 문서 `200` / 내부 문서 `404`.

## 회고
- **폴백은 가용성 장치이지 성과가 아니다.** 이번 장애는 폴백이 너무 잘 만들어져서 숨겨졌다.
  ④ §4(관측 가능성)를 "있으면 좋은 것"으로 적어뒀는데, 실제로는 이 장애를 즉시 잡았을 조건이었다.
- **에이전트가 내 산술 오류를 잡았다** — 4뷰 매트릭스 집계를 `6/10/6/6`(합 28)로 썼는데 표는 25행이었다.
- 문서를 만들수록 **문서 자신이 노출 위험**이 됐다. 자기 결함 목록을 심사자에게 링크로 건네는 구조를
  마지막에야 발견했다. 산출물이 늘면 노출 경계도 같이 설계해야 한다.
