## 설계 — 3층 → **기본 + 데스크톱 예외** 2층 (검수 뒤 값)
- 기본: `width: **380px**` — 한 토큰만 바꾼다. `.card`·`.goal-card`와 같은 축.
- 데스크톱: `width: 448px` — **손대지 않는다.**
- 폰·짧은 화면: 폭 선언 **삭제**(기본과 같다). 남는 차이는 패딩뿐이다
  (20 vs 18/16 → 콘텐츠 338 vs 346 · select 278 vs 286 — 좁은 화면은 여백을 줄인다).

⚠️ **기본에 상한(`max-width`)을 심지 않는다.** 초안은 `min(100%, 380px)`로 썼는데,
그 상한이 분기의 `width: 448px`를 **이겨** 데스크톱을 380으로 깎았고 그래서 분기에도
상한을 적어야 했다. `width`만 올리면 기존 `max-width: 100%`가 «오버레이를 넘지 않는다»를
그대로 맡고 **분기는 건드릴 필요가 없다** — 15개 뷰포트에서 두 방식의 렌더가 동일하다.

## 🔴 검수가 뒤집은 판단
1. **🔴 더 작은 등가 수정이 있었다.** 나는 기본에 `max-width: min(100%, 380px)`를 심고
   → 데스크톱이 깎여 → 분기에도 상한을 넣는 **3단계**를 밟았다. 그런데 기본의 `width`만
   300 → 380으로 올리면 **분기를 손대지 않고 같은 결과**가 나온다(15뷰포트 실측 동일).
   내 방식은 「`.modal`에 층을 더할 때마다 `max-width`를 다시 적어야 하는」 **함정을 영구히
   남겼다** — 이번 회차가 없앤 것과 같은 종류다. → 대안으로 교체.
2. **🔴 근본 원인은 「기본값 300」이 아니라 근거 없는 `min-height: 660`이고, 내 변경은 그걸 덮었다.**
