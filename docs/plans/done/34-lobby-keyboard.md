# plan: 대기실 — 키보드로 캐릭터를 고를 수 있게 (+ 포커스가 실제로 보이게)

status: done(2026-08-27) · created: 2026-08-27 · src: 개선 루프 14회차 (플랜 33 큐 1번 🔴)

## goal
**키보드만으로는 캐릭터를 아예 못 골랐다** — `.char`가 `onclick`만 있는 `<div>`라 focusable이 **0개**였다
(WCAG 2.1.1 A). 상용 게임이 마우스 없이는 시작조차 안 되는 상태였다.

## 결함 ① — `<div>` + `onclick`
저장소에 **옳은 패턴이 이미 있다**: 액션 바는 실제 `<button>` + `aria-disabled`이고,
그 주석이 「`disabled`는 title도 이벤트도 죽이므로 액션 버튼엔 쓰지 않는다」고 근거까지 적어 뒀다.
캐릭터 격자만 그 패턴 밖에 있었다.

## 결함 ② — 고쳐도 안 보인다: **포커스 링이 1.68:1**
`<button>`으로 바꾸면 포커스 링이 생기는데, 전역 링이 `--wds-accent`(#E3B873)였다.
이 테마의 면은 **전부 밝다**:

| 면 | accent(전) | primary-strong(후) |
|---|---|---|
| 카드 `#FBF3E7` | **1.68:1** ❌ | **6.65:1** ✅ |
| 모달 `#FFF8EF` | 1.75:1 ❌ | 6.95:1 ✅ |
| 배경음 컨트롤(어두움) | **7.34:1** ✅ | 1.85:1 ❌ |
| **도감 오버레이**(어두움) | **7.88:1** ✅ | **1.99:1** ❌ |

**WCAG 2.4.11/1.4.11은 비텍스트 ≥3.0**이다 — 즉 **키보드 사용자에게 포커스가 전 화면 어디에도 안 보였다.**
그리고 이 축은 **화면 게이트가 원리적으로 안 잡는다**(«평상 상태만» 잰다 — §사람 확인).
어두운 면에서는 두 색의 **우열이 뒤집히므로** 전역은 `primary-strong`, `.bgm-ctrl` 안만 `accent`로 되돌린다.

## 설계
- `.char` → **`<button type="button">`**. 포커스·Enter/Space·역할이 전부 따라온다.
- 잠긴 칸은 **`aria-disabled`**(`disabled` 아님) — **포커스에 남아야** «이미 나갔다»를 읽을 수 있다.
  액션 바가 같은 이유로 같은 선택을 한다.
- 선택된 칸 `aria-current="true"`.
- **호버 미리보기의 키보드 짝** — `focus`에서도 직업 풀이가 뜬다(마우스만 되던 것).
- 전역 `button` 스타일(primary 배경·흰 글자·600·13px·라운딩)을 `.char`가 전부 눌러 둔다.
  ⚠️ **`font-family`는 폼 컨트롤이 상속하지 않는다** — 명시 안 하면 카드만 다른 서체가 된다.

## 🔴 검수가 잡은 것 — **고치려던 결함을 옆 화면에 새로 만들 뻔했다**
1. **🔴 «어두운 면은 배경음 컨트롤 하나뿐»이 거짓이었다.** **도감 오버레이**(`.codex-overlay` —
   어두운 배경 이미지 + 0.5 스크림)에 실제 포커스 대상이 있다(`#codexClose`).
   내 변경으로 그 링이 **7.88 → 1.99:1**, 이미지 밝은 지점에선 **1.01:1**(문자 그대로 안 보임)로 떨어졌다.
   **1.4.11 통과를 미달로 되돌린 것**이고, 이번 회차가 고치려던 결함과 **글자 그대로 같은 종류**다.
   → `.codex-overlay`도 예외에 추가. **교훈: «유일한 X»라고 쓰기 전에 전수로 세라.**
2. **🔴 키보드로 «고르면» 포커스가 사라진다 — 내 변경이 활성화한 결함.**
   `renderLobby`는 **모든 state patch마다** 격자를 `innerHTML=""`로 통째로 재생성한다.
   카드가 `<div>`였을 땐 focusable이 0이라 안 드러났는데, `<button>`이 되자
   **내 선택이 유발한 patch가 내 포커스를 죽였다**(Enter/Space → `activeElement`가 `<body>`).
   키보드 사용자는 선택 한 번에 처음부터 12번 Tab 해야 했다. → 재생성 전 인덱스를 기억했다가 복원.
3. **🔴 `onfocus` 미리보기에 짝이 없었다.** ① `blur` 복귀가 없어 격자를 떠나도 **남의 캐릭터가
   대형 일러스트로 계속 떠 있었다.** ② `grid.onmouseleave`가 **포커스를 무시하고 덮어써서**
   마우스를 움직이기만 해도 «포커스된 칸»과 «미리보기»가 서로 다른 캐릭터를 가리켰다.
   → `focusout`(격자를 **떠날 때만**) 복귀 + `mouseleave`에 포커스 가드.
4. **🔴 잠긴 칸 주석이 선례를 반만 인용했다.** 액션 바가 `aria-disabled`를 쓰는 이유는
   «포커스 유지»가 아니라 **클릭 시 `showBanner()`로 사유를 말하기 위해서**다.
   여기선 Enter가 **침묵한다** — 대기실에 메시지 자리가 없기 때문이다(`#fxBanner`는 `#gameScreen`
   안이고 `#lobbyMsg`는 §9.1 **선행**). 없는 근거를 대는 대신 **사실대로 적었다.**
5. **🟠 `aria-current="true"`가 Chrome AX 트리에 아무 속성도 노출하지 않았다**(검수 실측).
   스펙상 «항목 집합 안의 현재 항목»이고 여기는 12지 중 1개 선택이다 → **`aria-pressed`**로 교체.
   격자에 그룹 의미도 없었다(`role=generic`) → `role="group" aria-label="캐릭터 고르기"`
   (저장소 선례: D패드가 `role="group" aria-label="이동"`).
6. **🟠 `title`이 이름을 두 번 읽히게 했다.** `<div>`에서는 무해했는데 `<button>`이 되며
   **정식 accessible description**이 됐다 — 지난 회차가 §9.0에 「이름이 두 번 읽힌다」고
   적어 두고 피했던 바로 그 문제를 **역할 변경으로 되살렸다.** → `title`에서 이름 제거.
7. **🟠 `addEventListener`를 쓸 뻔했다** — 이 함수는 state patch마다 도므로 **리스너가 쌓인다.**
   속성 대입(`onfocusout`)으로 멱등하게. (내가 타입 오류를 피하려다 잘못 잡은 것을 스스로 되돌렸다.)
8. **🟠 §1.5 신설로 기존 §1.5(길이 제약)가 §1.5.1로 밀렸는데 참조 6곳이 안 고쳐졌다** —
   `ui-copy` 5곳 + **다른 문서**(`20260729-mafia-content-design`) 2곳. 전부 갱신.
   (변경 이력의 §1.5와 `view-contract-spec §1.5`는 **다른 대상**이라 그대로 둔다.)
9. **🟠 배경음 컨트롤의 기본 배경은 완전 투명**이고 0.18s 트랜지션이 있다 —
   포커스 직후 그 시간 동안 링이 밝은 씬 위에 그려진다. 7.34는 «펼쳐진 뒤» 값임을 문서에 명시.

### 검수가 뒤집은 «원리적으로»
「포커스 축은 게이트가 **원리적으로** 못 잰다」는 과했다 — 게이트는 이미 CDP를 쓰고
`CSS.forcePseudoState`가 `focus-visible`도 받는다. **원리 문제가 아니라 미구현**이다(큐 2번).

### 반영하지 않은 것
- **`.cx-thumb`(도감 캐러셀 14칸)에 같은 결함이 그대로 있다** — `<div>` + `cursor:pointer`.
  **범위 밖**이라 `ui-copy` §9.0에 `[주의]`로 남기고 큐에 올렸다. 같은 처방이면 된다.
- **Safari/iOS 실기 · 실제 스크린리더 발화는 미확인.** 대신 `appearance: none`을 명시해
  «`<button>` UA 렌더 차이»라는 축 자체를 제거했다(검수가 남은 유일한 실질 diff로 지목).
