# plan: 게이트가 «평상 상태»만 재는 구멍을 메운다 — hover·focus 대비

status: done(2026-08-28) · created: 2026-08-28 · src: 개선 루프 27회차 (플랜 46 큐 1번)

## goal
25회차에 `button:hover`가 `.evi-hit`로 새어 상자 전체가 진갈색이 되고 글자 대비가
**1.16~1.98:1**로 떨어졌다. **게이트는 그걸 원리적으로 못 봤다** — 자기 리포트에
「§사람 확인: `:hover`/`:active`/`:focus` 상태의 색(게이트는 **평상 상태만** 잰다)」이라고
스스로 인쇄한다. 검수 서브에이전트가 잡아 줬을 뿐이고, 다음에도 그러리란 보장이 없다.

`SKILL.md`도 이 구멍을 «알려진 한계»로 못 박아 뒀다. 메운다.

## 가설 (착수 시점)
- CDP `CSS.forcePseudoState`로 노드마다 `:hover`/`:focus-visible`을 **강제**할 수 있다.
- 강제 전후 `getComputedStyle`을 비교하면 «상태에서 색이 바뀌는 요소»만 골라낼 수 있고,
  그 부분집합에만 S6와 같은 합성 대비 계산을 돌리면 비용이 작다.
- 이 저장소에 **이미 있는 결함이 여럿 드러날 것**이다(전역 `button:hover`가 여러 커스텀
  버튼에 새고 있을 가능성).

## 구현 — 가설을 하나 버렸다
착수 시 가설은 `CSS.forcePseudoState`였다. **버렸다** — `Input.dispatchMouseEvent`로
**진짜 마우스를 움직이는** 편이 낫다:
- 브라우저 **자신의 히트 테스트**를 쓰므로 «그 요소에 실제로 hover가 걸리는가»까지 같이 검증된다.
- `DOM`/`CSS` 도메인을 열 필요가 없다 — 이 게이트는 지금까지 `Runtime.evaluate` 하나로만 살았다.

```
pageProbe → window.__zcState = { hoverable(), candidates(), measure(x,y,rest) }
probeHoverStates(sid) → 후보마다 [mouseMoved → measure] · 끝나면 커서를 화면 밖으로
judge() → S9 (하한은 S6와 **같은 함수**)
```
- **색 계산을 복붙하지 않았다** — S6가 쓰는 `bgBehind`/`contrast`/`over`를 그대로 내준다.
  갈라 두면 언젠가 한쪽만 고쳐진다. `floorOf`도 블록 밖으로 올려 공유한다.
- **«색이 바뀐 것»만 잰다** — 안 바뀌면 S6가 이미 쟀다. 또 세면 같은 위반을 두 번 세고
  어느 검사가 잡은 것인지 흐려진다.
- **손가락 뷰포트는 SKIP + 사유** — `(hover: hover)`가 거짓이면 브라우저가 hover를 안 만든다.
  PASS로 찍으면 «쟀는데 괜찮다»로 읽힌다. 실기 폰에도 hover가 없으므로 SKIP이 정답이다.

`--self-test`에 `F2b-hover만깨짐`(평상은 멀쩡하고 hover에서만 두 색이 붙는 결함)을 넣었다 →
`실제 S9:FAIL · 지문 6건(기준선 0건)`.
그 과정에서 자기검사가 **폰에 고정**돼 있어 hover 결함을 못 돌린다는 것을 발견했다 —

## 🔴 검수가 뒤집은 것 ① — 기준선과 계측 대상이 **다른 요소**였다
`stateCand`는 쉬는 값을 **조작 요소**에서 떴는데 `measure`는 `elementFromPoint`가 준
**안쪽 span**을 쟀다. 정적인 색 차이가 «hover에서 바뀌었다»로 잡힌다 —
검수가 hover 규칙이 **아닌** 정적 색을 주입해 **12건 오탐**을 실증했다.
그리고 그 값이 4.5 미만이었다면 S6와 **이중 계상**된다 — 주석이 피하겠다고 선언한 바로 그것.
→ 쉬는 값도 `elementFromPoint`로 뜬다. 양쪽이 **같은 방식**이어야 «바뀌었다»가 참이다.

## 🔴 검수가 뒤집은 것 ② — 전이 때문에 **못 잡고, 잔상이 다음 후보에 섞였다**
`mouseMoved` 직후 정착 없이 쟀다. `.bgm-ctrl`은 `transition: background .18s`라
**출하 설정에서 한 번도 안 잡힌다**(정착 300ms를 주면 잡히지만 화면 하나가 2.0s → **10.1s**).
더 나쁜 것은 전 후보의 전이 잔상이 **다음** 후보 계측에 실린다는 것(검수 실측).
→ `sleep`이 아니라 **전이·애니메이션을 끈다**(S9 패스 동안만). 추가 비용 0.

## 🔴 검수가 뒤집은 것 ③ — 「S3와 같은 집합」은 사실이 아니었고, S6의 면제를 하나도 안 물려받았다
`aria-disabled`(§`textExempt`)·글자 없는 요소(이모지)를 안 걸렀다.
그 결과 **자기검사 안에서 F8과 F2b가 반대 주장**을 했다 — F8은 「`aria-disabled`는 잡히면
안 된다(1.4.3 예외)」를 지키는 검사인데 F2b의 증거 줄이 `aria-disabled` 버튼을 잡고 있었다.
→ S6의 면제 규칙(`textExempt` · 글자 여부 · `-webkit-text-fill-color`)을 그대로 물려받는다.
「S3와 같은 집합」이라는 주석도 지웠다 — 두 검사는 **같은 뷰포트에서 절대 함께 안 돈다**
(S3는 coarse, S9는 hover).

## 🔴 검수가 찾은 것 ④ — **결과 화면 6건이 «없음»으로 조용히 빠졌다**
`grab()`이 `probeHoverStates`를 안 부르고, `judge`는 `data.hover`가 없으면 **체크를 아예 안
만들었다.** 이 파일 머리글이 「**은폐된 미측정이 회귀보다 위험하다**」고 못 박는데 그걸 어겼다.
24회차의 «0건 측정 · PASS» 함정과 같은 종류다.
→ `data.hover`가 없거나(`SKIP`) `unavailable`이거나 후보 0개면 **전부 SKIP + 사유**.
그리고 계측 루프의 예외가 **화면 전체를 «도달 실패»로 만들던 것**도 막았다(S1~S6가 통째로 버려졌다).

## 🔴 검수가 뒤집은 것 ⑤ — 자기검사 지문이 «아무 S9 위반»이었다
