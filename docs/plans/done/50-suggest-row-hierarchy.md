## 🔴 발견 1 — 왼쪽 테두리는 아무 신호도 안 나르고 있었다
`.sg-row`의 기본값이 이미 `--wds-primary-normal`인데 `.sg-row.sg-mine`이 **같은 값**으로
override하고 있었다 → **모든 행에서 no-op.** 그 옆 주석은 「«내 제안»의 식별은 이 테두리와
«나» 배지가 **실제로 져야 한다**」고 적혀 있었는데, 테두리는 한 번도 진 적이 없다.
→ 채널을 가른다: **테두리 = 결과**(기본 line-normal 3.43 · 미반증 primary-strong 5.77) ·
**배경 + 배지 + inset 링(4.38) = 소유**.

## 🔴 발견 2 — 조합의 아이콘 3종이 **처음부터 죽어 있었다**
서버가 `label(suggestion.suspect)`로 **한글 라벨**을 보냈고(타입 주석도 「한글 라벨」),
클라가 그 문자열에 `faceIc()`/`cardIcon()`을 걸었다 —
`FACE_IDS.has("토끼 낭자")`도 `ROOM_SET.has("대청마루")`도 **늘 거짓**이라 빈 문자열이 나왔다.
`.sg-combo .face-ic` CSS는 **존재하지 않는 요소**를 겨냥하고 있었다.
→ 서버가 **카드 키**를 보내고 표시는 받는 쪽이 `label()`로 만든다. 소비자는 `sugRow` 하나뿐(전수 확인).
§4.1 «색 단독 금지»의 2차 단서가 이 아이콘이므로, 이건 표기 문제가 아니라 **접근성 결함**이었다.

## 🔴 발견 3 — 게이트는 미반증 행을 **한 번도 못 본다**
좌석 사슬이 제안 6건을 만드는데 **그 6건이 전부 반증된다**(probe 덤프 실측 — 미반증 **0행**).
AA 미달 4.08:1이 오래 살아남은 이유가 그것이다. **무계측이 무결함이 아니다.**
새로 붙인 계측조차 이 행은 못 본다 → `knownUnmeasured`에 사유를 적어 매 실행 인쇄한다.
내 변경이 커버리지를 실제보다 넓게 주장하지 않게 «해소»가 아니라 **«절반 해소»**로 적었다.

## 🔴 발견 4 — 주석이 존재하지 않는 검증을 주장하고 있었다
`combo.innerHTML`에 「값이 모두 검증된 카드 키라 innerHTML 안전」이라 적혀 있었는데,
`readSuggestEntry`는 **`typeof === "string"`만** 보고 `label()`은 모르는 값을 **그대로 돌려준다.**
즉 서버 문자열이 그대로 innerHTML에 들어갔다. (아이콘 쪽은 실제로 안전하다 —
`emoji()`가 `EMOJI[v] ?? ""`라 미지의 값에서 빈 문자열이 나오고, `faceIc`의 URL 분기는
`FACE_IDS` 소속일 때만 탄다.)
→ **이름은 텍스트 노드로.** 버리지 않고 텍스트로 넣는 이유는 **배포 시차**다 —
키 검증으로 행을 드롭하면 새 클라 ↔ 옛 서버 구간에서 표가 통째로 빈다
(클라 Vercel · 서버 OCI로 배포가 원자적이지 않다).

2. **🔴 「테두리 = 결과 채널」이 성립하지 않았다.** `line-normal` ↔ `primary-strong`의
   **상호 대비가 1.68:1**이다. 각각의 배경 대비(3.43·5.77)만 확인하고 «채널»이라 적었는데,
   **각 색이 배경에 통과하는 것과 두 상태가 서로 구별되는 것은 다른 명제**다.
   회색조로 동일하고 둘 다 따뜻한 갈색이라 색각 이상에서 더 나쁘다.
   → 미반증을 `label-strong`으로 (상호 **3.33**). 세 문서에 세 번 적어 둔 주장이 거짓이었다.
3. **🔴 서버가 제안 카드의 어휘를 검증하지 않았다.** `handleSuggest`는 턴·방·재진입만 보고
   `msg.suspect`/`msg.weapon`을 **그대로** `Suggestion`에 담았다 → 클라이언트가 보낸 임의
   문자열이 `suggestLog`에 **저장**되고 전원 브로드캐스트 + 재접속·관전 리플레이에 남았다.
   「진실값은 서버 규칙 엔진에만」인데 **규칙 엔진이 자기 어휘 밖의 값을 상태에 적고 있었다.**
   → `SUSPECT_KEYS`/`WEAPON_KEYS` 소속 검사. 손패 검증이 아니라 어휘 검증이다.
4. **🔴 「기호 단독」이 열려 있었다.** 스크린리더가 `🔍`/`🛡`을 「돋보기」/「방패」로 읽어
   한 행에서 **같은 이름이 «용의자 카드»와 «반증자»로 두 번** 나오는데 구분어가 없었다.
   §4.5는 「DOM 순서가 곧 읽는 순서」까지만 말하고 멈췄다. → `.ec-sr` 낱말(`제안`·`반증`·`결과`).
5. **🔴 `keep-all`은 공백에서의 줄바꿈을 막지 않는다.** 「항목 단위로만 접힌다」는 거짓이었다 —
   이름 **안**에 공백이 있다(`고양이 밤손님`·`잔치 선물`). 현 카드셋에서는 아직 발화하지
   않지만 이름이 한 글자만 길어져도 무너진다. → `label(key).replace(/ /g, NBSP)`.
