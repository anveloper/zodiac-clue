# plan: S12 «조판 분기» — 게이트가 «들어가는가»만 재고 «어느 조판으로 섰는가»는 안 쟀다

status: done(2026-08-31) · created: 2026-08-31 · src: 개선 루프 48회차

## goal
플랜 67 큐 1번. 47회차가 실증했다 — `.card` 데스크톱 가드를 600 → 660으로 **되돌려도
게이트가 침묵한다.** 카드가 «더 작은» 폰 조판으로 떨어질 뿐 **여전히 들어가기** 때문이다.

S1~S11은 전부 「들어가는가 · 가려졌는가 · 읽히는가」를 잰다.
**«의도한 조판이 섰는가»는 아무도 안 쟀다** — 그런데 **39~47회차가 내내 다툰 것이
정확히 그 경계값들**(가드·tier·폭 하한)이고, 그 값은 **회귀해도 화면이 깨지지 않고 그냥 나빠진다.**

## 설계 — 선언은 설정에, 계측은 «읽기»만
`layoutRules`가 「이 뷰포트 조건에서 이 선택자의 이 속성은 이 값이어야 한다」를 선언한다.
프로브는 **계산된 스타일을 읽기만** 한다 — 34·37·38회차가 「재는 쪽이 식을 쓰면 틀린다」를
세 번 증명했다.

- **`equal-tracks` 모드** — 배치가 끝난 grid의 `grid-template-columns`는 선언 문자열이 아니라
  **실제 트랙 폭**으로 계산된다. 「균등분할인가」라는 의도는 값으로 못 적으므로 따로 잰다.
- **안 그려진 요소는 판정문에 남긴다**(조용히 빼지 않는다 — 은폐된 미측정 금지).

## 🔴 «첫 매치»가 아니라 «첫 그려진 매치»
처음엔 되주입한 회귀가 **안 잡혔다.** `.card`는 랜딩·대기실 양쪽에 있고
`querySelector`가 **숨은 랜딩 카드**를 먼저 집어, 대기실 화면에서 규칙이 «안 그려짐»으로 빠졌다.
→ 첫 «그려진» 매치로 고치자 곧바로 `기대 520px · 실제 380px`을 잡았다.

## 🔴 균등분할은 두 장치가 함께 만든다
`minmax(0,…)`만 되돌리면 `white-space: normal`이 메워서 **S12도 S3도 안 운다**(되주입 확인).
둘 다 되돌리면 **S12가 S3보다 먼저 운다** — `[?]`가 아직 44 이상인 뷰포트에서도
트랙 차 10.9px을 잡는다. **증상이 아니라 원인을 재기 때문**이다.

## 🔴 검수가 뒤집은 판단
1. **🔴 명분 자체가 절반만 참이었다 — «경계값»은 여전히 무계측이었다.** 규칙의 조건이
   **CSS 미디어 조건의 복사본**이라 규칙은 «경계 «안쪽»의 값»만 지키고 «경계가 어디냐»는 못 본다.
   검수가 가드 600 → **629**, tier 719 → **684**(47회차가 얻은 여유를 거의 다 먹는 크기)를
   동시에 넣었더니 **전건 PASS**였다. 47회차의 「되돌리면 곧바로 FAIL」과 **같은 종류의 과대주장**이다.
   → **경계 그 자체를 뷰포트로** 뒀다(`cardGuard 1024×600` · `tierTop 1024×719`).
   되주입해 **둘 다 FAIL이 나는 것을 확인**했다.
2. **🔴 「첫 그려진 매치」 처방이 거꾸로였다.** `display: none` 요소도 `width`·`top` 같은
   **절대 길이는 계산값이 그대로 나온다**(배치가 필요 없다). 렌더 게이트가 필요한 것은
   `equal-tracks` 하나뿐인데 **모든 규칙에 걸어 커버리지를 깎았다**(3/3 → 2/3 + notRendered 1).
   **자기가 만든 구멍을 자기 안에서 메운 것**이다.
3. **🔴 조건을 «숫자로 재구현»했다** — 34·37·38회차가 세 번 지적받은 「재는 쪽이 식을 쓰면
   오진한다」다. 게다가 `innerWidth`와 CSS 레이아웃 뷰포트는 스크롤바가 있으면 갈린다.
   → **CSS 문자열 그대로 `matchMedia`**에 묻는다. 검수자가 CSS와 문자 단위로 대조할 수도 있다.
4. **🔴 `notRendered`가 «조용한 PASS»였다** — 규칙 평가 **88건 중 50건(57%)**이 그것이었는데
   출력이 PASS면 접혀서 **사람 눈에 한 번도 안 닿았다.** S8이 같은 이유로 `always`를 박아 뒀다.
   → `always: true` + **화면 스코프**(`screen: [...]`)로 소음 자체를 없앴다(이제 0건).
5. **🔴 규칙 3이 «결과값»이었다** — `top: 62px`은 `6 + 44 + 12`의 결과라, 바 높이가 바뀌면
   **규칙은 통과하면서 겹침이 자란다.** → **관계로** 적었다(`.hud-ctrl` 아래 여유 ≥ 12px).
6. **🔴 자기시험이 진짜 회귀를 재현하지 않았다** — `F19`가 높이 조건 없이 «모든 높이에서 380»을
   강제했고 뷰포트도 `desktop`이었다. 실제 가드 회귀는 **높이 600~659에서만** 나타난다.
   → 조건을 붙이고 뷰포트를 `cardGuard`로.
7. **🟠 `tracks ?? t.length`가 무력했다** — 안 적으면 칸 수 검사가 **항상 참**이 된다. → 필수로.
8. **🟠 머리글을 손상시켰다** — S12를 끼워 넣으면서 **S11 설명이 S12의 것으로 읽히게** 됐고,
   고치다가 S9 설명까지 S12 뒤로 밀렸다. 세 항목을 제자리로 복구했다.
