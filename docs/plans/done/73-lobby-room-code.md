# plan: 대기실의 주인공을 «방 코드»로 — 호스트만 자기 코드를 못 보고 있었다

status: done(2026-09-01) · created: 2026-09-01 · src: 개선 루프 53회차

## goal
캡처를 열고 정했다(축: 화면 완성도 우선). `n320`에서 초대 줄이
`http://127.0.0.1:65273/room/jMN…`으로 **잘린다** — 「초대 링크를 친구에게 공유하세요」라고
써 놓고 **정작 링크를 읽을 수 없다.** 잘리는 지점이 하필 **방 코드가 시작되는 자리**다.

**방 코드는 참가 경로의 1급 시민이다** — 랜딩에 `초대 코드` 입력칸이 있고(`#codeInput`),
`[참가]`가 그 값으로 붙는다(`main.ts:3466`). 그런데 **그 코드를 만드는 사람(호스트)에게만
코드가 안 보인다.** 옆 사람에게 불러 줄 수도, 받아 적게 할 수도 없다.

## 설계 — 읽는 것과 보내는 것을 가른다
| 자리 | 무엇 | 왜 |
|---|---|---|
| 1층 | **방 코드**(대형·자간·`user-select: all`) | **읽어 주는** 정보 — 잘리면 안 된다 |
| 2층 | `[링크 복사]` | **보내는** 행동 — 지금 `[복사]`는 무엇을 복사하는지 안 말한다 |
| 3층 | 링크 원문(**크기 그대로**) | 확인용. 여기서 잘리는 것은 무해하다 |

- **동작은 안 늘린다.** 코드는 «읽고 부르는» 것이고 링크는 «보내는» 것 — 버튼 하나가
  무엇을 복사하는지만 분명해지면 된다. 큰 코드 옆에 «복사»가 링크를 복사하면 **더 헷갈린다.**
- 색은 **새로 만들지 않는다** — 기존 토큰만 쓰고 S6로 재확인한다.

## 🔴 검수가 뒤집은 판단
검수가 게이트·픽셀 차분·헤드리스 렌더까지 직접 돌렸다. **조판은 깨끗했고 논거가 틀렸다.**

1. **🔴 «받아 적으라»고 해 놓고 받는 칸을 안 고쳤다.** 방 코드는 `nanoid(9)`이고 알파벳 64자 중
   **소문자가 26자**라 첫 글자가 소문자일 확률이 **40.6%**다(실측 `aE5sox2sU`·`gkzuKFC5_`).
   모바일 소프트 키보드는 text input의 첫 글자를 올리므로 `aE5…` → `AE5…`가 되어 참가가
   **실패한다.** 그런데 실패 문안은 대소문자 구분을 **한 마디도 안 했다.**
   → `autocapitalize/autocorrect/spellcheck` off + 문안 정정.
2. **🔴 `#codeInput`·`#inviteLink`는 Arial이었다** — 폼 컨트롤은 `font-family`를 상속하지 않고,
   이 파일은 그 함정을 **두 번 적어 두고 `select`에만** 고쳐 뒀다. Arial에서 `I`와 `l`은
   **같은 막대**다(검수 픽셀 차분: `<input>` ↔ Arial = 완전 동일).
   즉 이번 회차의 핵심 논거가 **경로의 절반에만** 걸려 있었다 — 호스트 화면에서만 갈라지고
   손님이 받아 적는 칸에서 도로 붙었다. → `input { font-family: inherit }` + `#codeInput` 등폭.
   🔴 그 변경이 `[참가]`를 **41×48**로 눌렀다(하한 44) — `flex` 항목의 바닥이 내용 폭이라서다.
   `min-width: 0` + `flex: none`으로 해소(이 파일이 `select`에서 이미 겪은 함정이다).
3. **🔴 `slashed-zero`는 아무 일도 안 했다** — 검수가 있음/없음 두 줄을 렌더해 픽셀 차분을
   냈더니 **완전 동일**했다. 이 스택의 기본 `0`이 이미 슬래시다. 자랑한 근거가 뒤집혔다 → 제거.
4. **🔴 남은 위험을 축소해 적었다** — «`0O1lI` 혼동»으로만 썼는데 **주축은 대소문자와 `-`·`_`**다.
   9자 중 하나라도 `-`/`_`를 포함할 확률 **24.8%**(실측 `gkzuKFC5_`는 밑줄로 끝난다).
   한국어로 불러 줄 자연스러운 말이 없다 — **서체로는 절대 해결 안 되는 축**이다.
5. **🔴 새 주인공이 게이트 계약에 없었다** — `protect`에 `#roomCode`가 없어 「잘리면 안 된다」를
   지키는 장치가 **0**이었다. 41·44회차가 `#hostHint`로 정확히 같은 실수를 했다. → 추가.
6. **🟠 라벨 11px은 저장소에 없는 일회성 값** — 이 파일의 라벨 축은 12px이고 데스크톱 분기는
   13/15px로 올린다. 로비에서 `.subtitle`이 사라지며 그 규칙이 죽어 「방 코드」가
   **카드에서 가장 작은 글자**가 됐다. → 12px + 데스크톱 13px.
7. **🟠 `-webkit-user-select` 누락** — 같은 파일 세 곳이 접두를 병기해 둔 규약을 어겼다.
   목적이 «모바일에서 한 번의 탭»인데 구형 WebKit에서 그 목적을 못 이룬다.
8. **🟠 «호스트가 코드를 못 본다»는 넓은 화면에서 거짓** — `desktop 1440×900`은 링크가 코드까지
   다 보인다. 주소창에도 코드가 있다. → 「**좁은 폭에서 잘린다**」로 좁혀 적었다.
   (⚠️ 잘림 자체는 `n320`에서 재현 확인 — 다만 「하필 코드가 시작되는 자리」는 오리진 길이에
   딸린 우연이다.)

### 검수가 실측으로 확인해 준 것
카드 높이 **자란 뷰포트 0개**(14개 중 0 ~ **−6px**, 오히려 줄었다) · 대비 **13.78:1** / **5.97:1**
(테마 분기는 존재하지 않는다) · 등폭 pitch 데스크톱 13.2px·좁은 폭 10.56px · `—` 초기값 노출 없음
(`wireRoom`이 `show("lobby")` 전에 동기적으로 채운다) · 죽은 `.subtitle` 규칙 없음(랜딩이 계속 쓴다).

### 안 한 것과 그 이유
**«코드만 복사» 버튼을 안 넣었다.** `#copyBtn`이 링크를 복사하는데 버튼을 하나 더 놓으면
«무엇을 복사하는가»가 다시 흐려진다 — 이번 회차가 `복사` → `링크 복사`로 없앤 바로 그 모호함이다.
`#roomCode`가 키보드로 도달 불가한 것과 함께 **큐로 넘긴다.**
