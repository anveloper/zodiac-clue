# plan: 도감 — 키보드로 열고·고르고·닫는다

status: done(2026-08-27) · created: 2026-08-27 · src: 개선 루프 15회차 (플랜 34 큐 1번 🔴)

## goal
14회차가 대기실을 고치며 **30줄 옆에 같은 결함이 그대로 있다**고 기록했다 —
도감 캐러셀 `.cx-thumb` **15칸**이 `cursor: pointer`만 있는 `<div>`라 **키보드로 조작 불가**(WCAG 2.1.1 A).
**랜딩에서 바로 닿는 화면**이다.

## 결함 — 둘이 붙어 있다
1. `.cx-thumb` × 15가 `<div>` + `onclick`. **focusable 0개.**
2. **모달이 포커스를 관리하지 않는다.** 열어도 `activeElement`가 트리거 버튼에 남는다 →
   **버튼으로 바꾸는 것만으로는 아무것도 나아지지 않는다.** 오버레이가 덮어서 **보이지도 않는**
   랜딩 컨트롤 전체를 Tab으로 지나야 도감 안에 닿기 때문이다.

## 설계
- `.cx-thumb` → **`<button type="button">`** · 레일에 `role="group"`(대기실 격자와 같은 선례).
- **열 때** 포커스를 기본 선택(호랑이 대감)으로, **닫을 때** 연 자리로 되돌린다.
- **Tab을 모달 안에서 순환**시킨다 — `aria-modal="true"`는 보조 기술에만 말할 뿐
  시퀀셜 포커스를 막지 않는다. 리스너는 **초기화 때 한 번만** 건다(`renderCodex`는 열 때마다 돈다).
- `aria-modal="true"` 추가(원래 `role="dialog"`만 있었다).

## 🔴 내가 «결함»을 잘못 진단했다 — 재기 전에 단정했다
초안은 이렇게 적었다: 「`.cx-thumb` 블록이 전역 `button`보다 위에 있고 특이도가 무승부라
`button:hover`가 이겨 **호버 시 주황으로 칠해진다**」. **거짓이다.**
`:hover`는 **클래스 열**에 들어가므로 `.cx-thumb:hover`는 **(0,2,0)**이고 `button:hover`(0,1,1)를
**특이도로 이긴다.** 순서는 애초에 관여하지 않는다 — 검수가 «변경 전 CSS + `<button>` 태그» 상태를
재현해 실측했고 호버색은 **원래대로**였다.

**방법론 결함이 원인이다**: «전» 상태를 재보지 않고 **특이도 계산만으로 결함을 단정**한 뒤
«후»만 재고 «✅ 주황 아님»으로 마무리했다. 이 루프가 매 회차 경고하는 바로 그 실패다.
→ 불필요했던 `.cx-rail` 접두사를 **되돌리고** 주석을 사실대로 고쳤다.

**다만 절반은 맞았다**(검수 실측): `font-family`가 **UA 기본 Arial**로 새고,
`font-weight: 600`이 `.tn`까지 상속됐다. 배경·색·테두리·패딩·라운딩은 안 샌다.
`appearance`는 «전역 button 값»이 아니라 **UA 기본**이다 — 주석을 정정했다.

## 🔴 검수가 잡은 나머지 — 트랩에 **실제로 재현되는 구멍**이 있었다
1. **🔴 포커스 트랩이 새고 있었다.** 리스너를 `#codex`에 걸었는데, 모달 안의 **포커스 불가 영역**
   (레일 좌우 여백 — 데스크톱 1280에서 각 ~60px, 캐러셀로 손이 가는 자리)을 클릭하면
   `activeElement`가 `<body>`가 되고 keydown이 `#codex`를 **거치지 않는다** →
   **오버레이가 덮어서 보이지도 않는 배경 컨트롤로 그대로 빠져나갔다**(검수 실측:
   Shift+Tab → `#bgmToggle` → `#bgmVol` → BODY. 배경 focusable 10개).
   **이번 회차가 «고쳤다»고 문서에 쓴 바로 그 증상**이었다.
   → `document`에 걸고 «모달 밖이면 안으로 끌어온다» 분기 추가.
   재검증: `activeElement`를 `<body>`로 만든 뒤 Shift+Tab → **모달 안으로 복귀**(안드로이드 → 고양이 → 쿼카).
2. **🔴 «같은 선례»를 따르지 않았다.** 플랜이 「대기실 격자와 같은 선례」라고 써 놓고
   그 격자가 내린 결론(`aria-current`는 AX에 안 나오므로 `aria-pressed`)을 **적용하지 않았다** —
   선택이 **색으로만** 전달되고 있었다(1.4.1 / 4.1.2). → `aria-pressed` 추가.
3. **🔴 상세 패널이 침묵했다.** 썸네일을 고르면 `#cxInfo`가 통째로 바뀌는데 `aria-live`가 없어
   보조 기술에 아무 통지가 없다 → **«키보드로 도감을 볼 수 있다»가 아니라 «이름 15개를 넘길 수
   있다»까지만 달성**이었다. → `aria-live="polite"`.
4. **🟠 복원 대상이 사라지면 조용히 실패한다** — `codexReturn`이 DOM에서 제거된 경우
   포커스가 `display:none`이 된 요소에 남았다(실측). → `isConnected` 가드 + 기본 트리거 폴백.
5. **🟠 주석이 «14칸»이라고 했는데 실제는 15칸**이다(`CODEX_IDS` = 12지 + 쿼카·고양이·안드로이드).
   같은 회차의 §9.0은 15로 고쳐 놓고 코드 주석만 옛 오류를 물려받았다.
6. **🟠 §1.5.2가 §1.5.1보다 위**에 놓여 편집 사고처럼 읽혔다 → **§1.6**으로 옮겼다.
7. **🟠 `-webkit-tap-highlight-color`가 문서에 근거 없이 들어갔다** — 터치 피드백을 없애는
   UX 변경이므로 주석에 사유를 남겼다.
