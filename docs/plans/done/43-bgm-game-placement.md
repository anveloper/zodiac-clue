# plan: 배경음 컨트롤을 우측 컬럼에서 떼어낸다 — 그리고 옮긴 자리의 대가를 갚는다

status: done(2026-08-28) · created: 2026-08-28 · src: 개선 루프 23회차 (플랜 42 큐 1번 · 3회차째 대기)

## goal
게임 화면에서 배경음 스피커가 **우측 컬럼(`#rightPanel`)을 덮고 있었다.**
22회차가 맨 위 패널(🤖 AI 대사)을 정리하고 나니 **그 자리에 남은 유일한 결함**이었다.

## 진단 — 오른쪽에서 «값을 고르는» 문제가 아니었다
- `.rp-col`은 `position: fixed`로 오른쪽 **전체 높이**를 쓰고, 폭이 **220~680px**로
  사용자가 드래그해 바뀐다(`main.ts` 리사이저 · 인라인 `style.width`).
- z-index로도 못 피한다 — `#gameScreen`이 `position: fixed`라 스택 컨텍스트를 만들어
  `<body>` 직계인 컨트롤이 컬럼 **위에** 칠해진다(19·21회차와 같은 구조).

**18회차부터 세 회차가 이 항목을 큐에 남긴 이유가 이것이다 — 매번 `right` 값을 만졌다.**
답은 «오른쪽을 떠나는» 것이었다.

### 🔴 검수가 뒤집은 것 ① — «유일한 답»이 아니다
초안 주석과 게이트 사유에 「왼쪽 배치가 **유일한** 답」이라고 박았다. **거짓이다.**
- 리사이저가 폭을 CSS 변수로 내보내면 `right: calc(var(--rp-w) + 32px)`가 컬럼을 **정확히** 따라간다.
- `#bgmCtrl`을 `#gameScreen` 안으로 옮기면 z-index가 정상 동작한다.

둘 다 **기각한 이유가 따로 있다**(자리가 컬럼 폭에 묶인다 · 화면마다 DOM을 옮기는 새 축이 생긴다).
**기각하지 않은 대안을 «없다»고 적는 것은 다음 회차에게 거짓을 물려주는 것**이라 주석·사유를 고쳤다.

## 처방 — 게임 화면에서만 **왼쪽 세로 줄**로
```css
body.no-scroll .bgm-ctrl { top: 120px; left: 16px; right: auto; }
```
왼쪽 줄: `.hud-ctrl`(실측 y 6~**50**) · `.hud-turnface`(실측 y 52~**108**) · **배경음(120~)**.
카드 화면(랜딩·대기실)은 컬럼이 없으므로 **그대로 우상단**이다.

## 옮긴 자리의 대가 — 검수가 찾아낸 것들
### 🔴 ② 대비 회귀 — 옛 자리는 **크림 패널 위**, 새 자리는 **보드 위**
비문자 경계 대비(24방향 픽셀 실측) **데스크톱 중앙값 6.08 → 1.50**.
테두리 `rgba(255,255,255,0.28)`은 갈색 방바닥에서 **1.00:1**로 사라진다.
⚠️ **어떤 단색으로도 3.0을 못 맞춘다** — 보드가 어두운 벽(74,50,32)부터 노란 돗자리
(214,178,88)까지 걸쳐 있다(직접 계산: 어두운 면 최악 1.53 · 크림 면 최악 1.92).
→ «색»이 아니라 **크롬**으로 푼다. 보드 위에 뜨는 다른 HUD 카드(`.hud`)가 이미 쓰는
«크림 0.9 + 1px 테두리 + 드리운 그림자»를 그대로 입혔다 — 바로 위 「지금 차례」와 같은 모양이라
**일관성도 같이 얻는다.** ⚠️ S6는 글자만 재므로 이 축은 게이트가 원리적으로 못 본다.

### 🔴 ③ 포커스 링이 **면과 함께 뒤집혔다**
§1.5는 배경음 컨트롤을 «어두운 면»으로 분류해 `--wds-accent` 예외를 준다. 크림을 입히면서
그 전제가 깨졌다(크림 위 `accent` 최악 **1.47**).
게다가 기본 `outline-offset: 2px`는 링을 **컨트롤 밖(=보드 위)**에 그리는데
**어느 색도 3.0을 못 맞춘다**(`accent` 1.10 · `primary-strong` 1.09).
→ 게임 화면에서는 링을 **면 안쪽**으로(`offset: -2px` · `primary-strong` **5.84**).
**«면이 어두운가»보다 «링이 어디에 그려지는가»가 먼저다** — §1.5에 그렇게 적었다.

### 🔴 ④ 탭 순서가 시각과 반대가 됐다
마크업이 `[슬라이더][아이콘]` 순서라, 왼쪽 정렬에 `row-reverse`를 쓰니 **탭이 오른쪽→왼쪽**이 됐다.
게다가 첫 Tab이 **보이지 않는 슬라이더**에 먼저 들어가 컨트롤이 소리 없이 펼쳐졌다.
→ **마크업을 `[버튼][슬라이더]`로 뒤집고** `row-reverse`를 **카드 화면 쪽으로** 옮겼다.
주 컨트롤(음소거)이 DOM 첫 번째가 된다. 실측 탭 순서 `bgmToggle → bgmVol`.
`role="group"`도 붙였다 — role 없는 `div`의 `aria-label`은 보조기술이 **무시한다**.

### 🔴 ⑤ 보이지 않는 22px — 크림 면을 입히니 **눈에 보이는 빈 여백**이 됐다
`.bgm-vol { width: 0 }`인데 전역 `input { padding: 8px 10px; border: 1px }` 때문에
실측 **22×18**이 남고 `elementFromPoint`가 그걸 잡았다(38회차부터 큐에 있던 항목).
→ `padding: 0; border: 0; min-width: 0` — 실측 **0×4**. 컨트롤 폭 72 → **52px**.

### 🔴 ⑥ 폰에서 컬럼을 열면 **왼쪽도 안전하지 않다**
컬럼이 `min(86vw,300px)`라 390px 화면에서 x82~382을 덮는다 — 남는 왼쪽 띠가 x0~82뿐이라
평상 8px, 슬라이더가 펼쳐지면 **88px** 겹치고, 그때 덮이는 것이 `.rp-hand`
(**폰에서 「내 손패」를 보여 주는 유일한 줄** — 플로팅 `.hud-hand`는 폰에서 `display:none`).
→ 모달과 같은 처방(19회차 §1.6): 컬럼이 떠 있는 동안에는 **끈다.**
⚠️ **폰 블록 안에만** 둔다 — 데스크톱은 컬럼이 늘 열려 있어 밖에 두면 컨트롤이 **영영 사라진다.**
초안이 실제로 그랬고, **21회차가 넣은 «켜는 검사»(`GAME_PROTECT`의 `#bgmToggle`)가 그걸 잡았다.**

## 게이트
| 쌍 | 수정 전 | 수정 후 |
|---|---|---|
| `#bgmCtrl` ↔ `#rightPanel` | **FAIL** `68×40 = 2720px²` · 히트 `#bgmToggle` | PASS |
| `#bgmCtrl` ↔ `.hud-turnface` | **FAIL** `72×8 = 576px²`(초안 `top:100`) | PASS |

**그 두 번째 쌍이 바로 내 실수를 잡았다.** 초안은 `.hud-turnface` 높이를 40으로 **계산해**
`top: 100`을 넣었는데 실측 바닥은 **108**이었다.

🔴 **`["#bgmCtrl", ".hud-hand"]` 쌍은 넣었다가 뺐다** — 어느 뷰포트에서도 **발화할 수 없다**
(폰은 `display:none`이라 `shown()`이 거르고, 데스크톱은 손패가 좌하단이라 **682px** 떨어져 있다).
사유 문구에 「폰에서 바로 위 이웃」이라 적었는데 **사실의 반대**였다.
**발화 불가능한 검사는 커버리지 착시를 만든다** — 없는 것보다 나쁘다.

🔴 **「높이가 내용에 따라 변한다」도 거짓이었다** — `.hud-turnface` 높이는 `faceIc(..., 44)`의
**고정 44px 원**이 지배하고, 40자 이름을 넣어도 **폭만** 늘고 높이는 그대로다(검수 실측).
실제로 이 값이 깨지는 조건은 `.tf-tx`가 **3줄**이 될 때다 — 주석을 그렇게 고쳤다.
