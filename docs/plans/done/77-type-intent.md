# plan: S15 «글자 크기 의도» — 요소를 겨냥한 선언이 타입 선언에 지는 것을 잡는다

status: done(2026-09-01) · created: 2026-09-01 · src: 개선 루프 57회차 (플랜 76 큐 1번)

## goal
56회차의 **치명 결함이 게이트 전건 초록으로 통과했다.** `#roomCode`를 `<strong>` → `<button>`으로
바꾸자 데스크톱 tier의 `.card button:not(.char)`(0,2,1)가 `.inv-code-v`(0,1,0)를 이겨
코드가 **20px → 15px**로 깎였다 — 「코드는 이 카드의 1층」이라는 위계가 무너졌는데 아무도 안 쟀다.

**같은 함정이 이미 한 번 있었다**: `.char`(캐릭터 칸)가 `<button>`이라 `.card button`이
12px 의도를 15px로 덮었고, 그때는 `:not(.char)`로 막았다. 즉 **두 번째**다.
세 번째를 사람이 다시 눈으로 잡을 이유가 없다.

## 왜 S5로는 못 잡나
S5는 **글자 크기 하한**(10px)이고 `pointer: coarse`에서만 돈다. 15px은 하한을 안 어긴다 —
어긴 것은 **하한이 아니라 의도**다. S6(대비)·S3(터치)도 같은 이유로 못 본다.

## 설계 — **특이도를 계산하지 않는다**
계산하면 «재는 쪽이 식을 쓰면 틀린다»(34·37·38회차)를 또 하게 된다. 대신 **브라우저에게 묻는다**:
- 승자는 `getComputedStyle(el).fontSize` 하나다. 계산 없음.
- 진 선언은 `document.styleSheets`를 훑어 «이 요소에 매치되고 `font-size`를 선언했는데
  계산값과 다른 것»으로 찾는다.
- **판정은 «주어»로 한다.** 선택자의 마지막 컴파운드(`.card button:not(.char)` → `button`)에서
  `:not(...)` 속을 걷어내고 클래스·ID가 남는지 본다.
  - 진 쪽이 **클래스/ID로 이 요소를 겨냥**했고
  - 이긴 쪽이 **타입만**(`button`·`input`·`select`) 겨냥했으면 → **FAIL**
- 그 반대(더 구체적인 클래스 규칙이 이기는 것)는 **정상 캐스케이드**라 안 잡는다.

## 🖼 켜자마자 **세 번째 사례**를 찾았다
`[잔치 시작]`이 `.card .full`의 **16px** 의도를 잃고 2차 버튼과 같은 **15px**로 그려지고 있었다 —
바로 위 주석이 「1차 행동은 카드에서 **가장 큰 컨트롤**이어야 한다」고 선언한 그 버튼이다.
검수 실측: 11뷰포트 × 2화면 = 22조합 diff가 **8건 전부 `.full`뿐**, 상자 크기·카드 높이·문서 높이
변화 **0** — 글자만 15 → 16px.

## 🔴 검수가 뒤집은 판단 — **이 검사를 끄는 세 가지 방법을 실증했다**
1. **🔴🔴 `:not(a, b)` 하나로 검사가 꺼진다.** 선택자 리스트를 `split(",")`로 잘라
   괄호 속 쉼표에 규칙이 조각나고, `el.matches`가 던져 **그 규칙이 통째로 사라졌다**.
   같은 결함이 `:not(.a):not(.b)`면 FAIL, `:not(.a, .b)`면 **PASS**였다.
   🔴 **하필 이번 회차가 `index.html`에 「이 `:not()` 목록이 길어지는 것 자체가 냄새다 …
   다음에 하나 더 붙으면 규칙을 다시 짜라」고 적었다** — 그 «다시 짜기»의 가장 자연스러운
   형태가 **이 검사를 끄는 형태**다. → 괄호를 세며 자른다 + `F26`.
2. **🔴🔴 `0.9375rem`(=15px)이면 못 잡는다.** 선언 문자열과 계산값을 **문자로** 비교했다.
   → 단위를 푼다(root·부모는 브라우저에게 묻는다) + `F27`.
   그리고 반대 방향 오탐 예비군이 이미 있었다 — `.evi-hit { font: inherit }` **21개**가
   `lost=inherit` 상태였고, 값이 안 겹쳐서 **오늘만** 조용했다.
3. **🔴 중첩 그룹 규칙에서 바깥 조건을 잃었다.** 안쪽이 바깥을 **대체**해서
   오탐(바깥 거짓·안쪽 참인 선언을 잡음)과 미탐(`@supports`를 `matchMedia`에 넣어 놓침)이
   **동시에** 실측됐다. 이 저장소에 중첩 `@media`가 이미 둘 있고 `gap 720×620`에서
   「바깥 거짓·안쪽 참」이 실제로 성립한다. → 조건 누적 + `CSS.supports()`.
4. **🔴 판정이 선택자 «가지 순서»에 좌우됐다** — `button, .card .full`은 FAIL,
   `.card .full, button`은 PASS(`find()`로 첫 가지만 봤다). → 모든 가지를 본다.
5. **🔴 CSS 중첩(`&`)을 「본다」고 주석에 적었는데 실제로는 조용히 샜다** — 주석이 코드보다
   앞서 나갔다. → 합성은 안 하되 **«못 쟀다»고 센다.**
6. **🔴 은폐된 미측정** — 크기 0인 요소를 조용히 건너뛰었다(랜딩 140개 중 **100개**).
   이 파일이 스스로 「은폐된 미측정이 가장 위험하다」고 적어 둔 규약 위반이다.
   → 요약줄에 검사·제외·못 읽은 선언·조건 불일치를 전부 인쇄한다.
7. **🔴 헤더 주석 삽입이 S12 설명을 삼켰다** — S15 3줄이 S12 항목 한가운데 들어가
   그 아래 6줄이 S15 설명으로 읽혔다. → S14 뒤로 옮겼다.
8. **🔴 내 커밋이 `index.html`의 줄번호 참조 11개를 밀었다** — 새로 쓴 참조는
   **태어날 때부터 틀렸다**(「아래 :512」인데 이미 :526). → `git diff` 헝크로 옛→새 매핑을
   만들어 **내용 일치를 확인한 뒤** 옮겼고, 내가 쓴 셋은 **선택자 참조**로 바꿨다.
9. **🔴 게이트가 매 실행 인쇄하는 PASS 문안이 같은 커밋과 모순됐다**(「두 번」 vs 「세 번」).
10. **🟠 «의도 명시»가 죽은 선언을 만든다** — `.card .seg-btn { font-size: 15px }`는
    특이도상 항상 져서 **오직 프로브를 달래려고** 존재한다. → 별도 규칙 대신
    **같은 선언의 선택자 목록에** 넣었다(죽은 줄 0 · 뜻은 같다).
