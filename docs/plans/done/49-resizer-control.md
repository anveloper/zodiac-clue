# plan: 패널 리사이저를 진짜 컨트롤로 — 11px 손잡이는 마우스로도 못 잡는다

status: done(2026-08-29) · created: 2026-08-29 · src: 개선 루프 28회차 큐 2번

## goal
우측 컬럼의 크기 조절 손잡이 4개가 **어느 축으로도 컨트롤이 아니다**(실측):

| 대상 | 크기 | 문제 |
|---|---|---|
| `#colWResizer` (너비) | **11×868** | 11px 폭 — 마우스로도 조준이 어렵다 |
| `.rp-hresizer` ×3 (높이) | **260×14** · 폰 **9px** | 손가락으로 9px은 **불가능**하다 |

넷 다:
- **키보드로 못 쓴다** — `makeDrag`가 `pointerdown`만 듣는다. 포인터가 없으면 기능이 **0**이다.
- **`aria-hidden="true"`** — 보조기술 사용자는 «패널 크기를 바꿀 수 있다»는 사실 자체를 모른다.
- **게이트가 못 본다** — `<div>` + role 없음이라 `OPERABLE` 밖이다.
  **45회차가 `.evi-row`에서 고친 구멍의 정확한 재발**이고, 28회차가 S3를 마우스로 넓혔는데도
  이건 여전히 안 잡힌다(원리적으로 후보가 아니다).

## 가설 (착수 시점 · 틀리면 그대로 기록한다)
- ARIA **window splitter**(`role="separator"` + `tabindex="0"` + `aria-valuenow/min/max`)가
  정확히 이 모양이다. 방향키로 조절 · `Home`/`End`로 양끝.
- **너비 손잡이는 공짜다** — `position: absolute`라 11 → 24px으로 키워도 레이아웃 비용이 0이다.
- **높이 손잡이는 공짜가 아니다** — `.rp-col`의 flex 아이템이라 14 → 24면 3개 × 10px = **30px**을
  패널에서 뺏는다. 다만 컬럼 `gap: 8px`(6칸 = 48px)을 줄이면 **상쇄되거나 남을** 수 있다.
- 폰은 하한이 44라 3개 × 44 = **132px**이다. 이게 감당 가능한지는 **재 보고 정한다** —
  안 되면 «폰에서 무엇을 포기하는가»를 근거와 함께 적는다(9px을 그냥 두는 것도 선택지가 아니다).

## 🔴 검수가 찾은 것 ① — **내가 기능을 부쉈다.** 초기화가 숨은 패널에 높이를 구워 넣었다
초안은 초기화에서도 `applyPanelH(…, 현재 높이)`를 불렀다. 그런데 `#aiPanel`·`#sugPanel`은
그 시점에 `.hidden`이라 높이가 **0**이고, `min` 72로 clamp돼 **`style.height="72px"`가 영구히
박혔다.** 나중에 `.hidden`만 떼므로 제안 기록표가 **228 → 72px**(실제로 보이는 본문 **34px**)에
갇혔다. 데스크톱도 같이 망가졌다.

🔴 **게이트는 이걸 못 잡았다 — 오히려 더 쉽게 통과시켰다.** S8 래칫은 📜 기록/알림만 보는데,
잃은 156px이 전부 제안 기록표에서 나오면서 기록/알림은 160 → **281px로 늘었다.**
「래칫이 통과했다」가 「배분이 멀쩡하다」가 아니다.
→ **«값을 쓰는 것»과 «알리는 것»을 갈랐다.** 초기화는 `publishH`(aria만)를 부르고,
안 그려진 패널에는 **아무것도 쓰지 않는다.** 실측 재확인: 네 패널 모두 인라인 높이 **없음**.

## 🔴 검수가 뒤집은 것 ② — 포커스 링이 **보드 위**에 그려졌다(최악 1.16:1)
손잡이를 포커스 가능하게 만들면서 **보드 위에 포커스 대상을 새로 놓은 것**인데,
기본 `outline-offset: 2px`가 링을 손잡이 **밖**에 그린다. 보드 팔레트 대비 실측
`grid 1.16 · wood 1.25 · roomEdge 1.28` — **1.4.11/2.4.11(3:1) 미달**.
이 파일이 §포커스 주석에 **이미 적어 둔 함정**이다(플랜 43·47이 배경음 컨트롤에서 겪었다).
→ 손잡이를 **불투명 면**(`--wds-bg-elevated` + 테두리)으로 하고 링을 **면 안쪽**으로
(`outline-offset: -3px`). 링 **6.95** · 그립 **4.92**로 둘 다 계산해 둘 수 있게 됐다.

## 🔴 검수가 뒤집은 것 ③ — 폰의 «숨 쉴 자리»는 **보드가 비치는 구멍**이었다
`background: none`으로 44px 상자를 투명하게 뒀는데, 그러면 패널 사이로 **보드가 132px 보이고**
보이는 단서는 그립 40×3 = 상자의 **0.9%**뿐이다. 그립 색의 보드 대비도 `1.11~3.05`로 대부분 미달.
그리고 **게이트는 이걸 원리적으로 못 본다** — S3는 상자만 잰다. 즉 «투명한 44px»은
**보이지 않는 컨트롤이면서 PASS**다. 「게이트가 이제 넷을 본다」는 참이지만 **본 것은 상자였다.**
→ 불투명 면을 양쪽 뷰포트에 똑같이 쓴다.

## 🔴 검수가 뒤집은 것 ④ — `aria-valuenow`가 거짓말을 했다
`.rp-ai { max-height: 40vh }`가 인라인 `height`를 **이긴다**(의도된 동작인데 안 봤다).
초안은 clamp 전 `max`로만 잘라 aria를 써서 실측 `valuenow 671` vs **렌더 325**였다 —
키보드 사용자는 «아무 일도 안 일어나는 방향키»를 22번 누르고 SR은 계속 커지는 값을 읽는다.
→ 쓴 **뒤에 다시 읽어** 렌더값을 알리고, `max`도 `max-height` 캡으로 자른다.
실측 재확인: `End` → 렌더 360 · `valuenow=360` · `valuemax=360`.
`aria-valuetext`(「높이 360픽셀」)도 붙였다 — 숫자만으로는 «72»가 무엇인지 전달되지 않는다.

## 그 밖에 고친 것
- **수정자 키를 안 걸렀다** — `Alt+←`(브라우저 뒤로)를 먹었다 → `plainKey` 가드.
- **`Home`/`End`가 두 축에서 반대**였다(높이 Home=최소 / 너비 Home=최대).
  APG대로 **Home = 최소 · End = 최대**로 통일 — 같은 role이 같은 키에 반대로 반응하면 못 배운다.
- **`aria-controls` 누락**(APG 필수) → 네 손잡이 모두.
- **이름에 이모지·무관한 부제가 들어갔다** — `"🔍 증거 노트 (나만 봄) 높이 조절"`.
  `.rp-head`의 `textContent`를 쓴 대가 → 마크업이 `data-resize-of`로 **선언**한다.
- **`aria-orientation="horizontal"`은 기본값이라 중복** → 세로 손잡이만 명시.
- **게이트 선택자가 `tabindex="-1"`도 잡았다**(주석과 코드가 어긋남) → `:not([tabindex="-1"])`.
- **hover 배경이 반투명**이라 보드가 비쳤다 → `--wds-tint-primary`(불투명).
- **`Record<string, number>` 인덱싱이 프로토타입을 탄다**(`go["constructor"]`) → `Object.hasOwn`.
- **회차 번호 오기** — 「29·28·45회차」는 전부 **플랜 번호**(49·48·45)다. 기존 오기를 복제했다.
- **커밋 노이즈** — `eval-narrator-report.md`(타임스탬프 2줄)를 되돌렸다.

## 🟡 검수 지적 중 안 고친 것
- **`focus` 이벤트로 aria를 내지 않는다** — 헤드리스는 문서가 포커스를 안 가지면 `.focus()`가
  `activeElement`만 바꾸고 **이벤트를 안 쏜다**(실측). 검증 못 하는 경로에 기대지 않고
  `ResizeObserver`로 «크기가 실제로 바뀌는 순간»에 낸다. 실측: `now=66`으로 렌더값과 일치.
- **`Enter`(접기/복원)** — APG 선택 동작. 이번 단위 밖이라 큐로.
- **데스크톱 24px이 하한과 정확히 같다**(여유 0) — 스펙 값이라 그대로 두되 기록한다.
- **폰에서 컬럼을 스크롤한 뒤 `max`가 널뛴다** — `colBottom`이 뷰포트 기준이다. 큐로.
