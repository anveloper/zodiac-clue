# plan: 오버레이 버스 — 모달만 포커스를 가져간다

status: done(2026-08-27) · created: 2026-08-27 · src: 개선 루프 16회차 (플랜 35 큐 1번 🔴)

## goal
15회차가 도감을 고치며 **«같은 결함이 더 큰 표면에 남아 있다»**고 기록했다 —
`showOverlay` 버스가 포커스를 관리하지 않는다. 그 경로에 **목표 카드**(첫 진입 온보딩)와
**결과 화면**(모든 판의 끝)이 있다. 둘 다 «여기서 나가는 길이 버튼뿐»인 대화상자다.

## 핵심 판단 — **버스의 넷이 다 모달은 아니다**
| 오버레이 | 포커스 대상 | 처리 |
|---|---|---|
| `goal` (#goalCard) | `[알겠어요]` | **모달** — 포커스를 가져간다 |
| `end` (#endOverlay) | `[다시 하기]` `[메인으로]` | **모달** |
| `dice` | **없음** (`pointer-events: none`) | 건드리지 않는다 |
| `interstitial` (로딩) | **없음** | 건드리지 않는다 |

**«오버레이니까 포커스를 옮긴다»는 틀렸다** — 주사위·로딩으로 포커스를 옮기면 **갈 곳이 없다**
(포커스 대상이 0개라 Tab이 죽는다). 그래서 `focusablesIn(el).length > 0`일 때만 모달로 다룬다.
⚠️ 초안이 근거를 «`pointer-events: none`이라서»라고 적었는데 **틀렸다** — 그건 `.dice-overlay`뿐이고
`#viewLoad`는 **클릭을 전부 삼키는 전면 스크림**이다(아래 «뒤집은 판단» 3번).
이 판정은 선언이 아니라 **DOM에서 읽는다** — 나중에 버튼이 생기면 자동으로 모달이 된다.

## 설계 — 도감과 **같은 코드**
15회차가 도감에 쓴 것을 모듈 스코프 헬퍼로 올리고 **양쪽이 함께 쓴다**.
검수가 15회차에 「선택자를 그대로 복사하면 그때 터진다」고 경고한 그 지점이다.
- `FOCUSABLE_SEL` / `focusablesIn()` — `getClientRects()`로 숨은 것 제외
- `cycleTab(ev, box)` — 순환 + **«밖에 있으면 안으로 끌어온다»** 분기
  (15회차 실측: 모달 안 포커스 불가 영역을 클릭하면 `activeElement`가 `<body>`가 되어
   리스너가 모달을 안 거친다 → 배경으로 샌다. 그래서 `document`에 건다.)
- `runOverlay` → 포커스 대상이 있으면 캡처 + 첫 대상으로 이동
- `hideOverlay` → **우리가 옮겼을 때만** 복원(`isConnected` 가드)
- `#endOverlay`에 `role="dialog" aria-modal="true" aria-labelledby="endTitle"`(원래 없었다)

## 실측 (실제 앱 · `pnpm dev` + CDP — 게이트는 이 축을 안 잰다)
| 단계 | `activeElement` | 판정 |
|---|---|---|
| 솔로 진입 직후 | **`BUTTON#goalOk`** (카드 **안**) | ✅ |
| Tab / Shift+Tab | `#goalOk` 유지 | ✅ 안에 머문다 |
| 카드 닫은 직후 (주사위 표시 중) | `BODY` · **`inDice: false`** | ✅ 전환 오버레이가 **안 가져간다** |
| 주사위 종료 후 | `BODY` | ✅ |

닫은 뒤 `BODY`인 것은 **정확하다** — 새로 연 페이지라 이전 포커스가 없었다(복원할 자리가 `BODY`).

## 🔴 검수가 뒤집은 판단
1. **🔴 초기 포커스를 «첫 버튼»에 두는 것이 위험했다.** 결과 화면의 첫 버튼은 `[다시 하기]`이고
   **누르는 즉시 `rematch`를 보낸다** — 판이 끝나는 순간 포커스를 거기 두면 **Enter 한 번이 새 판**이다.
   APG Dialog는 「되돌리기 어려운 동작이 있으면 **가장 덜 파괴적인 요소**」라고 말한다.
   → 마크업이 `[data-initial-focus]`로 선언하고, 결과 화면은 **제목**(`tabindex="-1"`)에 둔다.
   덤으로 `aria-labelledby`만 있어 스크린리더가 **제목만** 받고 있었다(부제·정답 봉투 3장은 침묵) →
   `aria-describedby="endSub endCards"`.
2. **🔴 복원 판정이 이 앱의 실제 실패 모드를 못 잡았다.** `isConnected`만 봤는데,
   이 앱은 화면을 **제거하지 않고** `display:none`으로 끈다 — 그런 요소는 `isConnected === true`인데
   `focus()`가 **조용히 no-op**이다. 게다가 되돌릴 자리가 실제로 사라지는 경로가 있다:
   증거 노트 메모 `<input>`은 `onblur`가 `renderMemo()`를 불러 **자기 자신을 떼어낸다** —
   메모 입력 중 판이 끝나면 정확히 그 케이스다. → `getClientRects()`로 «보이는가»를 보고
   `preventScroll`도 붙였다(복원이 화면을 움직일 이유가 없다).
3. **🔴 근거로 든 사실이 틀렸다.** «주사위·로딩은 `pointer-events: none`이라» —
   그건 `.dice-overlay`뿐이고 **`#viewLoad`는 `rgba(255,248,239,0.86)` 전면 스크림**이다.
   결론(포커스를 안 옮긴다)은 살지만 **근거는 «포커스 대상 0개» 하나**다. 문서 3곳을 정정했다.
   덤으로 드러난 부채: `#viewLoad`는 **마우스만 막고 키보드는 안 막는다**(정답은 `inert`).
4. **🟠 `document` 리스너 두 벌이 서로 싸운다.** 버스(모듈 스코프)가 먼저 등록되고 **둘 다
   `preventDefault`를 쓰는데 `defaultPrevented`를 안 봤다** → 도감이 열린 채 버스 모달이 뜨면
   **모든 Tab이 `#codexClose`로 리셋되는 키보드 트랩**이 된다. 도달성은 낮지만 잠복이다.
   **선택자 중복은 막아 놓고 리스너에서 같은 실수를 다시 했다.** → 양쪽에 가드.
5. **🟠 `runOverlay`가 `req.run` 전에 focusables를 읽는다** — «run이 내용을 만드는» 오버레이가
   이미 있다(주사위). 앞으로 run이 버튼을 만드는 모달을 추가하면 **조용히 모달 취급이 안 된다.**
   방향은 맞지만 **언제 읽는가가 계약**이라 주석으로 못 박았다.
6. **🟠 §1.6의 ✅가 남은 표면을 덮었다.** `#turnCircle`(턴 순서)은 `inset:0`·`z-index:45`·스크림까지
   있는 **완전한 전면 모달**인데 버스를 안 타고 포커스를 넣지도·가두지도·되돌리지도 않고
   **Esc로도 안 닫힌다**. 15회차 `[주의]`가 가리킨 «더 큰 표면»에 이것도 들어가는데
   내 ✅가 그 줄을 **대체해 버려** 문서에서 사라졌다 → `[주의]`로 되살렸다.
   결과 화면이 Esc로 안 닫히는 것도 **의도된 예외**임을 명시(§1.6 본문과 3자 불일치였다).
7. **🟠 «공유 리팩터링»인데 번들이 늘었다.** 초기 로드 JS **48.52 → 49.16 kB(+640 B)** —
   B1 래칫은 이미 red고 초과폭이 그만큼 커졌다. dedupe 이득보다 선택자 확장·가시성 필터·
   리스너·복원 로직이 크다. **「코드가 한 벌이 된다」는 유지보수 이득이지 바이트 이득이 아니다.**

### 검수가 확인해 준 것
**(C) preempt 체인이 안전하다** — `showOverlay`가 `hideOverlay()`를 **먼저** 부르므로 복원 후
`runOverlay`가 다시 캡처해 **원 자리가 이어진다**. 주사위→목표→주사위 재개도 안전(dice는 focusable 0).
`hideOverlay` 조기 반환 누수 없음(`overlayReturn ≠ null ⟹ activeOverlay ≠ null` 성립).
`focusablesIn(#endOverlay)` = 버튼 둘뿐(`.ec-card`는 `<span>` — 맞다).
모듈 로드 시 `addEventListener`는 선례가 이미 있다(SSR 없음·번들 분할 영향 없음).
포커스 링 대비 6.95:1 — 도감 예외를 확장할 필요 없다.

### 남은 미확인 / 부채
- **결과 화면(`end`)의 포커스는 실제로 재현하지 못했다** — 판을 끝까지 몰아야 한다.
  목표 카드와 **같은 `runOverlay` 경로**이고 `[data-initial-focus]`가 마크업에 있다는 것까지만 확인.
- `focusablesIn`이 `getClientRects()`를 쓰므로 **jsdom 단위 테스트로는 재현 불가**(항상 빈 배열).
- `visibility: hidden`은 못 거른다(현재 그런 오버레이 없음).
