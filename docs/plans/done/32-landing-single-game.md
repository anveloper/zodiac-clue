## 🔴 큐 항목 두 개가 «성립하지 않는다»로 판명 — 만들기 전에 확인해서 살았다
이번 회차는 큐 위쪽 두 항목을 실제로 열어 보고 **둘 다 폐기**했다.
1. **«결과 화면에 누가 무엇으로 이겼는지가 없다»(플랜 31 큐 2번) — 성립하지 않는다.**
   2번 «사건 종결»의 승자는 **신고에 성공해서** 이긴 사람이므로 그 신고 3장은 **정의상 정답 봉투와 같다.**
   3′번(최후 생존)은 아예 신고를 안 했다. 즉 «승자의 신고»를 실어도 **새 정보가 0**이다.
2. **«액션 바 위계가 색뿐이고 형태가 없다»(여러 회차 큐) — 이미 해결돼 있었다.**
   활성은 테두리 + `label-strong`, 비활성은 테두리 없음 + 흐린 글자다(캡처로 확인).
   게다가 `index.html:1191`의 긴 주석이 **비활성에 테두리를 주면 안 되는 이유**를 이미 적어 뒀다 —
   그러면 «중립 활성»과 «비활성»이 폰에서 배경 1.01:1로 붙어 구분이 글자색 하나로 줄고,
   관전 중 유일하게 누를 수 있는 `[?]`가 못 누르는 5개와 똑같아 보인다.
   **큐 메모를 근거로 «형태를 주자»고 했으면 이미 고쳐 둔 결함을 되살릴 뻔했다.**

**교훈: 큐 항목도 «인용»이다.** 착수 전에 현재 화면·현재 코드로 다시 봐야 한다.

## goal
랜딩 첫 화면은 신규 유입의 **첫인상**인데, **선택지가 하나뿐인 «게임» 셀렉터**가 ~180px를 쓰면서
바로 위 `<h1>`과 **제목·이모지를 글자 그대로 반복**하고 있었다.
고를 것이 없는 자리를 «고르는 UI»로 그리면 제품이 아니라 **설정 폼**으로 읽힌다.

## 설계 — 지우지 않고 «접는다»
```css
#landing:has(#gameSelect > .game-item:only-child) #gameField { display: none; }
#landing:not(:has(#gameSelect > .game-item:only-child)) #gameMeta { display: none; }
```
- **선택 UI는 지우지 않는다** — 콘텐츠 교체가 이 저장소의 설계 목표다(`CLAUDE.md`).
  항목 수로 갈라 두면 **두 번째 게임이 들어오는 순간 자동으로 되살아난다.**
- 접힌 동안 소개 한 줄은 `#gameMeta`가 진다. 문안은 `.gi-sub`와 **글자 그대로 같다.**
- **JS 0바이트** — 초기 로드 JS는 §9.1 **B1 래칫** 예산이고 지금 red다(**47.26** / 한도 43.65 · 재실측).
  빌드 산출물 `dist/index.html`은 **+363 B(gzip +92)** — 소스 +1,677 B 중 대부분이 주석이라 Vite가 턴다.
- `:has()` 미지원 브라우저는 **둘 다 보인다** — 중복이지 정보 손실이 아니다(안전한 폴백).
- `#gameSelect`·`.game-item`은 **`main.ts`가 읽지 않는다**(순수 장식) — 접어도 동작 영향 0. 확인함.

## 🔴 검수가 잡은 것
1. **🔴 `:only-child`를 «자손»으로 걸어 실패 방향이 위험했다.** `#gameSelect .game-item:only-child`는
   항목이 래퍼에 감싸이는 순간 **각각이 자기 래퍼의 `:only-child`**가 되어
   **게임이 둘인데도 접힌 채**로 남는다 → 두 번째 게임에 **도달 불가**(검수 실측:
   래퍼 2개 → `gameField` 여전히 `none`).
   → **자식 결합자 `>`**로 교정. 실패 방향이 «접힌 채 도달 불가» → «셀렉터가 도로 나온다»(무해)로 뒤집히고,
   «항목은 직계 자식»이라는 마크업 계약을 **선택자가 스스로 말하게** 된다.
   덤으로 앵커도 `.card`(랜딩·대기실 공용) → **`#landing`**으로 좁혔다.
2. **🟠 «두 번째 게임이 들어오면 자동으로 되살아난다»가 과장이었다.** `.game-item`엔
   `role`·`tabindex`·클릭 핸들러가 **없고**, 방 생성 프로토콜에 **게임 식별자 필드 자체가 없다**
   (`network.ts`의 `create(roomType, { isPublic, demo })` · `gameId`는 저장소 전체 0건).
   되살아나는 것은 **껍데기뿐**이고 동작은 그때 붙여야 한다.
   내가 같은 과장을 **마크업 주석·`.md`·`.html` 세 곳에 복제**했다 → 전부 교정.
3. **🟠 여백이 의도와 반대로 말하고 있었다.** 초안 `margin: -2px 0 14px`은 실측상
   부제와 **18px**, 폼과 **14px**이라 «제목 블록의 소개 한 줄»이 아니라 **헤더와 폼 사이의 고아 줄**로
   읽혔다. → `-14px 0 20px`(위 6 / 아래 20) — 메타가 부제에 붙고 원래의 헤더→폼 20px 분리가 복원된다.
4. **🟠 `:has()` 폴백이 안전한 이유를 안 적었다.** 그것은 우연이 아니라 **`:not()`이 forgiving이
   아니어서** 두 규칙이 **함께** 죽기 때문이다(검수가 대역 실험으로 실증). `:is(:has(…))`로 썼다면
   폴백이 **뒤집혀 `#gameMeta`가 영구히 숨었을** 것이다. **그 한 절이 이 규칙 전체의 하중을 진다** → 주석에 명시.
5. **🟠 플랜이 B1을 «46.79»로 인용했는데 실측은 47.26 kB**였다. red인 건 맞지만 숫자가 낡았다.
   («인용 전에 재확인» 규칙을 이 회차에서 두 번 지키고 한 번 어겼다.)
