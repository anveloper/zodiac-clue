# plan: 패널 스크롤 경계 신호 — «더 있다»를 화면에 남긴다

status: done(2026-08-26) · created: 2026-08-26 · src: 개선 루프 9회차 (플랜 28 «다음 회차 후보» 1번 · 화면 1순위)

## goal
우측 패널 3개(증거 노트·제안 기록표·기록/알림)가 스크롤 경계에서 줄을 **중간에서 잘랐다.**
«더 있다»는 신호가 없어 상용 UI로 읽히지 않는다 — **macOS 오버레이 스크롤바는 쉬는 동안 숨으므로
정지 화면에는 단서가 0이다**(캡처 실측: 잘린 행만 보이고 스크롤바 없음).

## 설계 — CSS만, JS 0바이트
```
.rp-body    { scroll-timeline: --rp-y block; }          /* 타임라인 발행 */
.rp-panel   { position: relative; timeline-scope: --rp-y; }
.rp-panel::after { position:absolute; bottom:0; height:16px; pointer-events:none; opacity:0;
                   background: linear-gradient(to top, rgba(58,42,26,.30), transparent); }
@keyframes rp-scroll-edge { 0%,90% { opacity:1 } 100% { opacity:0 } }
```
- **내용이 넘치지 않으면 타임라인이 비활성** → 애니메이션 미적용 → `opacity: 0` 그대로.
  미지원 브라우저도 같다(오버레이가 아예 안 보인다).
- **JS를 안 쓴 이유**: 초기 로드 JS는 §9.1 **B1 래칫** 예산이고 지금 이미 red다(46.79 kB / 한도 43.65).
- `animation` 단축속성이 `animation-timeline`을 **초기화**하므로 longhand가 뒤에 와야 한다 — 주석으로 못 박았다.

## 🔴 1차 구현(마스크 페이드)을 검수가 무너뜨렸다 — **접근 자체가 틀렸다**
처음엔 `.rp-body`에 `mask-image`로 **글자를 흐리게** 했다. 세 가지로 무너졌다.

1. **대비 예산이 성립하지 않는다(결정적).** 본문 `rgb(43,37,33)` on 패널 `rgb(244,236,226)`에서
   AA 4.5:1을 지키려면 알파 **≥ 0.67**이 필요하다. 0.67~1.0 구간의 페이드는 «더 있다»로 읽히지 않는다 —
   **읽히면 신호가 아니고, 신호면 안 읽힌다.** 페이드 길이를 줄이는 걸로는 **원리적으로 못 푼다.**
2. **넘침이 작을 때 온전한 줄을 지운다.** 페이드는 넘침량과 무관하게 고정 길이라 **10px만 넘쳐도
   35px 줄 하나가 사라진다**(검수 실측: 마지막 줄 획 대비 12.92 → 상단 9.06 · 중간 3.45 · **하단 1.57:1**).
   📜 기록/알림은 **한 줄씩 자라므로 그 상태를 매번 통과한다** — 방금 도착한 최신 사건이 가장 안 읽히는 줄이 된다.
3. **마스크는 히트 테스트를 안 바꾼다 — 안 보이는데 눌린다.** 증거 노트 칩은 `row.onclick`이
   상태를 순환시키고(`없음→제외→의심`) `saveEvi()`로 **localStorage에 영구 저장**한다(`main.ts:2264`).
   즉 하단 띠가 «보이지 않는데 누르면 내 추리 노트가 조용히 바뀌는» 영역이 된다.
   `enableDragScroll`의 click 삼킴은 **3px 이상 드래그**에서만 도므로 그냥 탭은 못 막는다.
   **변경 전에는 잘린 칩이라도 보였다.**

→ **글자를 건드리지 않는 오버레이**로 전면 교체. `pointer-events: none`이라 3번이 원천 차단되고,
알파를 안 건드리니 1·2번이 사라진다.

## 🔴 검수가 뒤집은 나머지 판단
4. **«미지원 브라우저는 지금 동작 그대로»가 거짓이었다.** `@supports`가 **애니메이션만** 감싸고
   `mask-image`는 밖에 있었다 → 파이어폭스는 **이득 0 + 합성 레이어 비용만** 얻는다.
   실측: 마스크 유/무 스크린샷이 **1053픽셀 다르다**(글자 행에만 분포). 「없는 것과 같다」가 아니다.
   (파이어폭스는 152까지 `animation-timeline`이 **플래그 뒤**다.)
5. **«번들 증가 0»이 거짓이었다.** JS는 0바이트가 맞지만 **`index.html`도 초기 로드 자산**이다.
   마스크판 **+730 B**(gzip +212). 최종 오버레이판은 **+437 B**. B1 래칫이 JS만 재서 FAIL이 안 날 뿐이다.
6. **«S6 영향 0»은 «계측 불가»로 다시 써야 한다.** S6가 `getComputedStyle` 기반인 건 맞지만,
   바로 그래서 **1차 구현이 만든 실제 대비 저하(12.92 → 1.57:1)를 원리적으로 못 본다.**
   S3(44px 터치)도 상자만 재므로 3번을 못 본다. **게이트가 절대 못 잡는 결함을 새로 넣을 뻔했다.**
7. **페이드 길이 20 → 14px의 근거가 틀렸다.** 「증거 노트가 «지운 카드»를 흐리게 표시해 혼동된다」고
   적었는데, `.evi-chip.cleared`는 `opacity: 0.4` **+ `text-decoration: line-through`**이고
   `.own`은 `border-style: dashed`까지 붙는다(`index.html:957·959`) — 취소선·점선이 구분한다.
   **혼동 위험은 근거 없이 지어낸 것이었다.**
8. **`#aiDetail`·`.room-list`도 같은 문제를 가진 스크롤러인데 신호가 없다** — `.rp-body`가 아니라
   빠졌다. 이번엔 **의도적으로 두고** 다음 회차 후보로 넘긴다(둘 다 기본 접힘·별도 화면).

### 검수도 못 잡은 것 / 남은 미확인
- 실기 LCD 서브픽셀 AA에서 글자가 얇아지는지는 **헤드리스로 확인 불가**(마스크판 한정 이슈라 이제 무의미).
- 오버레이판의 **스크롤 중 style recalc 비용**은 재지 않았다. 마스크판은 60프레임에 60회(총 8ms)였다.
  `opacity`는 컴포지터 속성이라 더 쌀 것으로 보이나 **미측정**.
