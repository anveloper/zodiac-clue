# plan: 방 코드를 «부를 수 있는» 코드로 — roomId 자체를 바꾼다

status: done(2026-09-01) · created: 2026-09-01 · src: 개선 루프 54회차 (플랜 73 큐 1번)

## goal
53회차가 방 코드를 대기실 1층으로 올려 놓고 **부를 수 없는 값**을 올렸다. 검수 실측:
- Colyseus 기본 id는 `nanoid(9)` — 알파벳 64자에 **대소문자가 섞이고 `-`·`_`가 둘 다 있다.**
- 9자 중 하나라도 `-`/`_`를 포함할 확률 **24.8%**(실측 `gkzuKFC5_`는 밑줄로 끝난다).
- 「대문자 케이 / 소문자 지 / 밑줄」— **한국어로 불러 줄 자연스러운 말이 없다.**
등폭 서체는 `0`/`O` 같은 **모양** 혼동만 줄인다. 이 축은 서체로 못 고친다.

## 🔑 핵심 발견 — 새 계층을 안 만들어도 된다
`Room`의 `roomId` 세터는 **`_internalState === CREATING`일 때만** 허용되고(`Room.js:118-122`),
`onCreate()`는 정확히 그 구간에서 돈다 — `MatchMaker.js:323`이 `await room.onCreate(...)`를
부른 **뒤** `:335`에서 `CREATED`로 올리고 `:336`에서 `listing.roomId`를 복사한다.
→ **`onCreate`에서 `this.roomId`를 바꾸면 그게 진짜 방 id가 된다.**
링크(`/room/${roomId}`)·`joinById`·게이트·증거노트 저장키가 **전부 그대로** 돈다.
(코드↔id 매핑 테이블·HTTP 조회 엔드포인트를 만드는 안은 그래서 **기각**했다 —
 새 계층은 게이트가 못 재는 상태를 만든다.)

## 설계
- 알파벳 **Crockford base32** `0123456789ABCDEFGHJKMNPQRSTVWXYZ` — `I`·`L`·`O`·`U`가 없다.
  `O`가 없으니 `0`이, `I`/`L`이 없으니 `1`이 **혼동 상대를 잃는다.** `U`는 욕설 회피용 관례.
- 길이 **8** → 32⁸ = **2⁴⁰**. 그 위에 생성 시 `matchMaker.query({ roomId })`로 **중복 확인**.
  (초안은 6자였다 — 아래 검수 1이 **뚫었다.**)
- 표시는 `ABCD-EFGH`처럼 **4자씩 끊어** 보여 주고, 입력은 **공백·하이픈·소문자를 받아 준다.**
  보이는 것과 칠 수 있는 것이 어긋나면 안 된다.
- 옛 형식(`nanoid`) 입력도 계속 받는다 — 정규화는 **새 코드 모양일 때만** 적용한다.

## 🔴 검수가 뒤집은 판단
검수가 게이트 결함 주입·실서버 무차별 대입·설치본 실독까지 직접 돌렸다.

1. **🔴🔴 자물쇠를 2⁵⁴ → 2³⁰으로 깎아 놓고 «같은 급»이라고 적었다.** 내 주석이
   「난수원이 `crypto`라 Colyseus 기본 `nanoid`와 같은 급을 유지한다」였는데,
   **난수원만 같고 엔트로피는 24비트(1,677만 배) 낮았다.** 검수가 실제로 뚫었다:
   localhost 병렬 20연결로 없는 코드에 `joinById` — **초당 9,615회**,
   동시 방 100개면 아무 비공개 방이나 **평균 18.6분**. 참가 실패에 레이트리밋이 없다(0건).
   → 8자(2⁴⁰)로 올려 동시 방 1000개 기준 **1.9분 → 약 34시간**.
   **여전히 옛 id보다 16,384배 약하다** — 그 사실을 주석·문서에 적고 레이트리밋을 큐 1번에 뒀다.
   **교훈: «같은 재료»는 «같은 세기»가 아니다.**
2. **🔴 게이트가 «서버가 그 코드를 쓰는지»를 안 봤다.** 검수가 결함 4종을 주입해 **전부
   조용히 PASS**시켰다 — 서버를 `Math.random` + 자기 알파벳으로 교체 · 항상 `"AAAAAA"` 반환 ·
   `% 31`(모듈로 편향) · 끊는 자리 1자. 게이트가 여는 파일이 공용 모듈 **하나뿐**이었다.
   → 서버 `assignRoomCode` **본문**을 읽고, 출력 분포(바이트 0~255)를 보고, 끊음 단위를
   독립 기준(3~4자·`LEN % GROUP === 0`)으로 본다. **결함 5종 재주입 → 전부 FAIL.**
   🔴 내가 처음 쓴 두 검사는 **항진식**이었다: 끊음은 같은 상수로 양변을 만들었고,
   모듈로는 *선언*의 `256 % 32`만 검산해 *구현*의 `% 31`을 못 봤다.
3. **🔴 Node 20에서 게이트의 절반이 사라지고도 PASS였다.** `.ts`를 직접 `import`하는데
   저장소 하한(`engines.node ">=20"`)에는 타입 스트리핑이 없다. 게다가 SKIP 줄이
   `if (!json)` 안이라 **verify가 쓰는 `--json` 경로엔 흔적조차 없었다.** → **exit 3**(판정 불가).
4. **🔴 사용자 문안이 거짓이 됐다.** 53회차가 넣은 「대소문자까지 그대로 입력했는지」는
   코드가 대문자 전용이 되면서 **원인이 될 수 없는 것을 원인으로 지목**한다.
   → 「코드 8글자를 다시 확인해 주세요」(길이는 `ROOM_CODE_LEN`에서 온다).
5. **🔴 `autocapitalize="off"`가 이제 역효과다.** 53회차의 근거(소문자 40.6%)가 사라졌고,
   `off`는 키보드를 소문자로 고정해 **매 글자 Shift**를 누르게 만든다 → `characters`.
6. **🔴 «옛 형식은 안 건드린다»가 실제로는 안 지켜졌다.** 하이픈을 **모양 판정 전에** 벗겨서
   `"xy-z1-2-3"` → `"XYZ123"`이 됐다 — **옛 링크가 조용히 남의 방으로 간다.**
   게이트 표본이 하필 `_`로 끝나 안 걸리는 것 하나뿐이었다.
   → 받는 모양을 **민값과 화면 그대로 둘로** 한정 · 하이픈 낀 옛 id 5종을 표본에 넣었다.
7. **🟠 조용한 되돌아감 둘.** 코드 뽑기 8회 소진과 `matchMaker.query` 예외가 **아무 말 없이**
   기본 id로 돌아갔다 — 이 회차가 없애려던 바로 그 상태다. → `console.warn`.
   그리고 `roomCodeFromBytes`가 `bytes[i] ?? 0`으로 짧은 입력을 삼켰다(자물쇠에 구멍) → `throw`.
8. **🟠 devMode 방 복원을 덮어쓴다.** `MatchMaker`가 넣어 준 `restoringRoomId`를 무조건
   덮었다. 지금은 devMode를 안 켜 무해하지만 켜는 순간 깨진다 → `if (isDevMode) return;`.

### 검수가 실측으로 확인해 준 것 (내 판단 중 참인 것)
`onCreate`에서 `roomId` 교체는 **안전하다** — 설치본 실독: 세터는 `CREATING`만 허용,
`await room.onCreate()` **뒤에** `CREATED`·`listing.roomId` 복사·`createRoomReferences`·
`listing.save()`가 온다. 바뀌기 전 id를 잡아 두는 곳은 없다.
`async onCreate` 허용됨(예외는 `MATCHMAKE_UNHANDLED`로 클라에 전달).
**중복 확인은 죽은 코드가 아니다**(내 가설이 틀렸다 — 살아 있는 방은 전부 `query`에 잡힌다).
모듈로 편향 없음 · 공개방 목록에 비공개 방 안 뜬다 · 재접속·리매치·진행 중 참가 전부 코드 유지.
