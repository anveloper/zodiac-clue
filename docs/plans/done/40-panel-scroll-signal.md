# plan: 「아래 더 있음」을 **진짜 스크롤바**가 말하게 한다 — 9회차 처방이 마지막 줄의 AA를 깨고 있었다

status: done(2026-08-28) · created: 2026-08-28 · src: 개선 루프 20회차

## goal
우측 컬럼 패널이 마지막 줄을 **중간에서 자른다**(증거 노트 `금고`/`젓가락`, 제안 기록표 3행).
9회차가 그 자리에 «더 있음» 신호로 **어두운 그라디언트 오버레이**를 깔았는데,
그것이 잘리는 줄의 **명암비를 AA 아래로** 떨어뜨리고 있었다.

## 진단 ① — 9회차가 피하려던 함정에 **다른 문으로** 들어갔다
9회차는 마스크(알파) 페이드를 **대비 근거로** 기각했다(「읽히면 신호가 아니고, 신호면 안 읽힌다」).
대안으로 `rgba(58,42,26,0.30)` **어두운 오버레이**를 골랐다 — 「알파를 안 건드리니 사라진다」.
**틀렸다.** `::after`는 `position: absolute`라 **글자 위**에 그려진다 — 배경만이 아니라
**글자도 같이** 어두워지고, 잘리는 줄의 대비가 내려간다.

| 오버레이 알파 | `--wds-label-alternative` 합성 대비 |
|---|---|
| 없음 | 4.77 ~ 5.94 |
| α = 0.15 (그라디언트 중간) | **4.10 ← AA 미달** |
| α = 0.30 (바닥) | **3.44 ← AA 미달** |

하필 `alternative`를 쓰는 것이 **잘리는 줄들**이다 — `.sg-combo`(제안 조합 2번째 줄) ·
`.evi-group .cat` · `.sg-n` · `.evi-memo`.
🔴 **S6는 이걸 원리적으로 못 본다** — `getComputedStyle`은 합성 **전** 색을 읽는다.
게이트가 11회차 동안 통과시켜 온 것이 «안전하다»는 뜻이 아니었다.

## 진단 ② 🔴 — 9회차의 「네이티브 스크롤바는 못 쓴다」도 **틀렸다**
9회차는 「macOS 오버레이 스크롤바는 쉬는 동안 숨는다 · `::-webkit-scrollbar` 폭이 레이아웃상 0」을
실측하고 기각했다. **그건 플랫폼 한계가 아니라 이 파일 자신의 규칙이었다.**

`index.html`에 `* { scrollbar-width: thin; scrollbar-color: … }`가 **이미 전역으로** 있고,
Chromium은 **표준 속성이 non-auto면 `::-webkit-scrollbar` 규칙을 통째로 무시한다** →
바로 그 아래 9px 도색 3줄이 **죽어 있다.** 9회차는 그 결과를 «플랫폼»으로 읽었고,
**20회차의 1차 시도(`thin` + 커스텀 색)도 같은 것을 다시 쟀다.**

실측(CDP · Chrome 151 · macOS · 스크롤바 폭 = `offsetWidth − clientWidth`):

| 지정 | 폭 | 정지 화면 도색 |
|---|---|---|
| `thin` + 커스텀 색 (= 전역 · 1차 시도) | 0px | 없음 |
| `auto` + 커스텀 색 | 0px | 없음 |
| **`auto` + `auto`** | **9px** | **엄지·트랙 그려짐** |

→ **둘 다 `auto`여야 한다.** non-auto `scrollbar-color` 하나가 오버레이를 강제한다.

## 처방
```css
.rp-body, #aiDetail { scrollbar-width: auto; scrollbar-color: auto; }
.rp-body { padding: 8px 4px 8px 12px; }   /* 오른쪽 여백 자리에 스크롤바를 세운다 */
```
표식(`↓`)보다 나은 이유: ① 글자를 안 덮으니 대비를 못 낮추고 ② «더 있다»에 더해
**얼마나·어디쯤**까지 말하며 ③ `content` 글리프가 없어 **접근성 이름을 안 더럽히고**
④ `@supports`도 `scroll-timeline`도 필요 없다(Firefox·구 Safari 포함).

### 🔴 검수가 뒤집은 것 ① — 머리글 `↓` 표식을 통째로 폐기했다
1차 구현은 `.rp-head::after { content: "↓" }`였다. 두 가지로 무너졌다:
- **접근성 이름 오염** — `opacity: 0`은 접근성 트리에서 요소를 **안 지운다.** AX 트리 실측:
  `DisclosureTriangle "▾ 🧾 제안 기록표 (모두 공개) ↓"` · `StaticText "↓"` × 3
  (셋 중 하나는 **넘치지도 않는** `#logPanel`의 것이다). 시각 전용 신호가 AT에는 순수 잡음이다.
  폐기한 `.rp-panel::after`는 `content: ""`라 이 문제가 없었다 — **이번 회차가 새로 만든 결함**이었다.
- **`.rp-head`를 flex로 바꾼 부작용** — 제목과 `(나만 봄)`이 **각자** 줄바꿈하게 된다
  (실측: 폰 긴 제목에서 `(나만 / 봄)`으로 쪼개짐 · 머리글 37 → 53px). 옆의 `.rp-fold summary`는
  이 문제를 `white-space: nowrap`으로 이미 막아 뒀는데 `.rp-head`에는 대응이 없었다.
  표식을 지우면서 flex도 되돌렸다.

### 🔴 검수가 뒤집은 것 ② — 내 대비 수치가 방법부터 틀렸다
- 「5.01~5.32 → 3.59~3.78」은 **배경만 어두워진다고 계산한 값**이다. 오버레이는 글자 위라
  글자도 같이 어두워진다 → 올바른 값은 **3.44 / 4.10**이다. (결론은 같지만 근거는 못 쓴다.)
- 「머리글 배경은 고정」도 거짓 — `.rp-head`는 자기 배경이 없어 `.rp-panel`의
  `rgba(255,248,239,0.9)`를 쓰므로 본문과 **똑같이** 뒤 캔버스에 따라 흔들린다(4.77~5.94).
  고정인 것은 「위에 아무것도 안 덮인다」 하나뿐이었다.

### 🔴 스스로 잡은 회귀 — 9px이 증거 노트 격자를 무너뜨렸다
스크롤바를 넣자 본문 폭 234 → 225가 되어 `.evi-chips`(`minmax(112px,1fr)` + gap 4 = **228 필요**)가
**2열 → 1열**로 무너지고 `.sg-combo`가 한 줄 더 접혔다(캡처로 확인).
→ 오른쪽 여백을 12px → 4px로 줄여 **스크롤바를 여백 «안에» 세웠다**. 본문 폭 233 —
원래(234)와 **1px 차이**다. 격자·줄바꿈 모두 복귀.
