# plan: «고발» → «신고» 사용자 문안 통일 (오너 확정)

status: done(2026-08-26) · created: 2026-08-26 · src: 개선 루프 7회차 · **오너 결정**(쿼카가 정한 표기)

## goal
1~6회차 내내 **버튼만 `신고하기`**이고 모달 제목·확인 버튼·결과 화면·서버 로그는 **`고발`**이었다.
`ui-copy` §2가 「개념은 고발 — 모달 제목·`❌ 고발 실패`는 **유지**」로 **의도적 유지**를 못 박았는데,
같은 문서가 「같은 것을 두 이름으로 배우게 하지 않는다」를 규약으로 들고 있어 **문서가 자기와 어긋났다.**
6회차 연속 «오너 판단 대기»로 올렸고 2026-08-26 **«신고»로 확정**됐다.

## 설계 — 두 층을 가른다
| 층 | 표기 | 근거 |
|---|---|---|
| **사용자에게 보이는 문자열** | **신고** | 1개념 1표기(§2·§8.1) |
| **내부 식별자·코드 주석** | `accuse` · `doAccusation` · `bot-accuse.ts` · 「고발」 | 사용자 문안과 코드 어휘는 **다른 층**. 식별자를 바꾸면 진단 가치 없는 대형 diff만 남는다 |

`ui-copy`의 **설계 서술 산문**에 남은 «고발»(내부 `reason` 값 · 구 문자열 대조표 · 예산 표)도 같은 이유로 유지.

## 교체한 사용자 문자열 (전수)
| 자리 | 파일 | 전 → 후 |
|---|---|---|
| 신고 모달 제목 | `main.ts` | `고발 — 진범을 지목하라` → `신고 — 진범을 지목하라` |
| 확인 버튼 | `main.ts` | `고발한다` → `신고한다` |
| 결과 화면 제목 | `main.ts` | `❌ 고발 실패` → `❌ 신고 실패` |
| 관전 배너 | `main.ts` · `index.html` | `❌ 고발 실패 · 관전 중 …` → `❌ 신고 실패 · 관전 중 …` |
| 서버 로그 | `clue-room.ts` | `❌ 고발 실패 — … 님 탈락 · 반증만 가능` → `❌ 신고 실패 — …` |


서버는 이미 `지금 신고할 수 있어요`(`clue-room.ts`)라고 말하고 있었다 — **불일치가 서버 안에도 있었다.**

### 사용자 문자열이 **아닌데** 함께 바꾼 것 1건 (분류 정정)
`narrator.ts` LLM 프롬프트 `행동: 고발 —` → `행동: 신고 —`.
초안은 이것을 «사용자 문자열 전수» 표에 넣었는데 **틀렸다** — 화면에 나가지 않는 내부 지시문이다.
**그럼에도 바꾼 채로 둔다**: 이 프롬프트의 **출력**은 말풍선으로 사용자에게 간다. 은퇴한 낱말을
생성기에 심어 두면 화면에 «고발»이 다시 나올 경로가 남는다.
`[미검증]` 검수는 「행정 어휘 «신고»가 사극 레지스터와 충돌한다」고 반대했다. 둘 다 표본이 없다 —
오프라인 고정이라 LLM 출력 표본이 0이고, 폴백 템플릿은 두 낱말 중 **어느 것도 쓰지 않는다**.
영향 없음이 확인된 것: 길이 예산 · **캐시 키**(`action/suspect/weapon/room/persona/tone/disproved/hint` —
프롬프트 문자열을 안 쓴다) · `eval-narrator`(액션 키 `accuse`로만 분기 · PASS 유지).
→ `--live` 표본이 생기면 재평가한다.

## 🔴 게이트가 문안에 묶여 있었다 (교체 직후 커버리지 8건 증발)
`gate.config.mjs`의 결과 화면 매처가 **제목 문자열로** 화면을 찾는다(`title: "고발 실패"`).
문안을 바꾸자 그 화면에 **도달하지 못해** PASS 68 → **60**, 미측정 2 → **4**로 떨어졌다.
FAIL이 아니라 **조용한 커버리지 손실**이라 «FAIL 증가 0»만 보면 못 잡는다.
→ 매처를 `"신고 실패"`로 갱신해 **PASS 67 · FAIL 2 · 미측정 2**(기준선과 동일) 복구.
**교훈: 확정 문안을 바꾸면 «그 문안으로 화면을 찾는» 게이트도 같이 본다.**
문자열 매처는 `gate.config.mjs` 결과 화면 4종의 `title` 필드뿐이다(버튼·모달은 CSS 클래스 매칭이라 무사).

## 🔴 검수가 뒤집은 판단
1. **6회차 동안 근거로 써 온 §8.1 인용이 오인용이었다.**
   1~6회차 보고와 `SKILL.md`가 「§8.1 — 같은 것을 **두 이름**으로 배우게 하지 않는다」를 근거로
   이 항목을 오너 판단으로 올렸다. **§8.1에 그런 문장은 없다.** 실제 조항은
   「같은 **사유**를 두 **문장**으로 배우게 하지 않는다」(`ui-copy.md:434 · :499 · :752`)로 **다른 명제**다.
   발원지는 `ui-copy.md:111`의 기존 ⚠️ 노트이고, 나는 그것을 **검증 없이 승계해 변경 이력에 새로 박았다**.
   → `:111`을 정정하고, 근거를 **§2 제목 «1개념 = 1표기»**로 바꿨다.
   **결론(통일해야 한다)은 그대로 옳다** — 근거만 틀렸다.
   **교훈: 저장소가 이미 하고 있던 인용도 인용하기 전에 원문을 열어라.** 이 루프의 명시 규칙인데
   («문서·게이트 인용 규칙») 6회차 동안 아무도 §8.1을 열어보지 않았다.
2. **«예산 표는 유지한다»고 써 놓고 §8.2 폴백 템플릿표를 바꿨다.** 같은 액션을 가리키는 네 자리
   (§1.5 길이표 · §8.2 실측 산문 · §11 체크리스트 · 템플릿표)가 갈라졌고, `.html`은 **인접한 두 표**가
   같은 행을 «신고»/«고발»로 다르게 불렀다. → 템플릿표를 **되돌리고** 이력 진술에 명시했다.
3. **§2 철회 서술이 자기가 들어앉은 열의 머리글과 모순됐다.** 그 셀의 열 머리글은
   **`개념어(그대로 유지)`**인데 거기에 「전부 «신고»로 통일 · 철회」를 넣었다.
   → **§2 본표에 «승리 선언 행동» 행을 신설**하고 버튼표 셀은 한 줄로 줄였다.
4. **`narrator.ts` 프롬프트를 «사용자 문자열»로 분류한 것이 틀렸다** — 위 «분류 정정» 참조.
5. **게이트 수치를 플레이크째로 기준선에 박을 뻔했다** — 위 done-criteria 참조.
6. **게이트 스크립트의 옛 문안 인용이 반쪽만 고쳐져 있었다** — `[신고한다]` 진단문만 고치고
   `gate-screen.mjs`의 결과 화면 4행 주석·F7 음성테스트 `[고발]`·«고발 모달» 10건을 남겼다. → 전부 갱신.
7. **편집한 표에 남아 있던 기존 드리프트 2건** — `.html`의 `#bonus` 라벨이 `엿보기`(구현은 `다가가기`) ·
   §9.5 앞말이 `추리 후`(개념어는 `제안`). 둘 다 이번에 만진 표라 범위 안이다.
8. **`SKILL.md` 축 교체는 별건이다** — 커밋을 갈랐다(`chore(skill)`).

### 검수를 되돌린 건 1건
`narrator.ts` 프롬프트를 **되돌리라**는 권고는 받아들이지 않았다 — 근거는 위 «분류 정정»에 적었다.
검수의 「사용자 문자열이 아니다」는 **맞고**, 「그러므로 바꾸지 말았어야 한다」는 **동의하지 않는다**:
프롬프트의 출력이 말풍선으로 사용자에게 가므로 생성기에 은퇴한 낱말을 남길 이유가 없다. 양쪽 다 미검증이다.
