## 🔎 착수 전에 다른 주제를 조사했다가 접었다 — 기록으로 남긴다
처음 고른 주제는 **번들 B1 래칫**(51.62 kB / 한도 43.65)이었다. 「영구 red인 래칫은
아무것도 감지하지 못한다」는 판단은 지금도 맞다고 본다. 그런데 **한 회차에 끝나지 않는다**:

| 초기 청크 구성(소스맵 귀속 실측) | |
|---|---|
| `src/main.ts` | **116.6 kB** |
| `src/content/clue/cards.ts` | 9.2 kB |
| `board.ts` · `view-timing.ts` · `view-motion.ts` · `move-hint.ts` | 10.3 kB |

즉 초기 청크는 **사실상 `main.ts` 한 파일**(3368줄)이고, 최소화 결과 51.62 kB다.
한도까지 가려면 **최소화 기준 ~8 kB(원본 ~18 kB)**를 빼야 한다.
`main.ts`에서 게임 화면 전용 구간은 액션 버튼·이동 패드·증거 노트·카드 모달·목표 카드·
AI 칩·제안 기록표로 **약 1718줄(51%)**이라 양은 충분하다. 문제는 **결합**이다 —
이들은 `room`·`myCards`·`memos`·`label()` 같은 모듈 스코프 상태를 공유해서, 떼어내려면
문맥 객체를 새로 설계해야 한다. **막 프로덕션에 배포한 직후**에 3368줄짜리 핵심 파일을
가르는 것은 한 회차 크기가 아니다.

→ **다회차 계획으로 넘긴다**(아래 큐 1번). 「못 줄인다」가 아니라 「이 크기로는 못 한다」다.
그동안 래칫은 red로 남고, 머지 보고에 수치를 계속 적는다(규칙 §5).

## goal
`.evi-hit` **80×20** · `.evi-memo-btn` **11.5×12**(데스크톱 실측). WCAG 2.2 **2.5.8
Target Size (Minimum) = 24×24는 AA이고 포인터 종류를 가리지 않는다.** 간격 예외도 못 쓴다 —
두 버튼이 gap 4px로 붙어 있어 24px 원이 겹친다.

**그런데 어느 게이트도 이걸 안 잰다** — S3는 `pointer: coarse` 전용이다(「마우스 전제라
44px 하한을 적용하지 않는다」). 44를 마우스에 요구하지 않는 것은 옳지만, **24는 다른 얘기다.**
고쳐도 기계가 확인해 주지 않으면 다음 회차에 다시 깨진다.

## 실측 — 넓히자마자 43건
| 화면 | 미달 |
|---|---|
| `game/desktop` | `.evi-hit` **83×20** ×21 · `.evi-memo-btn` **11.5×12** ×21 = **42** |
| `landing/desktop` | `[↻ 새로고침]`(`.mini`) **70×21** = **1** |

`.evi-memo-btn`에 24px 하한을 주면 행이 24가 되고 `.evi-hit`가 `align-self: stretch`로
**따라온다** — 한 줄로 둘이 풀린다.

## 🔴 검수가 찾은 것 ① — **24회차가 폰에서 고친 사고를 데스크톱에서 재발시켰다**
버튼을 11.5 → 24로 키우자 `.evi-hit`가 83 → **72px**이 되고 「호랑이 대감」이 **처음으로 잘렸다**
(이전 잘림 0건). 24회차가 폰에서 겪고 `margin-right: -7px`(칩 오른쪽 여백 위로 겹쳐 7px을
이름에 돌려준다)로 되돌린 **바로 그 항목**인데, 데스크톱에 보상을 안 넣었다.
→ base로 올렸다. 실측 재확인: `.evi-hit` **74.5×24** · 메모 **24×24** · 칩 높이 **34** ·
**이름 21개 중 잘림 0** · 가로 오버플로 없음. coarse 블록이 같은 값을 다시 선언하므로 폰은 무변화.

## 🔴 검수가 뒤집은 것 ② — «간격 예외를 못 쓰는 이유»가 틀렸다
세 곳에 「24px 원이 서로 겹쳐서」라고 적었다. **규범문은 «원이 다른 타깃과 교차하지 않을 것»**인데
두 **중심**은 약 51px 떨어져 **원끼리는 안 겹친다.** 못 쓰는 진짜 이유는 메모 버튼의 24px 원이
`.evi-hit`의 **바운딩 박스**를 약 2px 파고들기 때문이다.
결론(예외 못 씀)은 같지만, **그대로 뒀으면 다음 사람이 원↔원 거리로 계산해 틀린 면제를 발급한다.**

## 🔴 검수가 뒤집은 것 ③ — 44의 근거를 잘못 적었다
표에 44를 「손가락 · HIG · **WCAG 2.5.5 AAA**」로 묶어 「2.5.8만 포인터 무관」이라는
**없는 대비**를 만들었다. **2.5.5도 포인터를 안 가린다 — 등급이 AAA일 뿐이다.**
44를 손가락에만 요구하는 근거는 **HIG 하나**다.

## 🔴 검수가 찾은 것 ④ — 자기검사가 «하한이 24임»을 증명하지 못했다
`F4b`(20×20)는 24·44 **양쪽에서** 잡힌다 → `minPointerPx`를 실수로 44로 적어도 OK를 찍는다.
즉 증명하는 것은 「데스크톱을 재기는 한다」뿐이었다.
→ **`F4c-마우스24통과`**(30×30 · `shouldPass: true`) 추가 — 24는 통과하고 44라면 실패한다.
이 저장소가 F2·F8·F12·F15에서 쓰는 «무해한 것은 안 잡혀야 한다» 관용구 그대로다.

## 🔴 검수가 찾은 것 ⑤ — 마우스 쪽에 에뮬 누수 가드가 없었다
전에는 `!viewport.coarse`면 즉시 SKIP이라 무해했는데, 이제 마우스도 판정하므로
**에뮬이 새면 페이지는 44px CSS로 그려지고 판정은 24로 통과**한다 — 조용한 위양성.
→ `viewport.coarse !== data.coarse`면 **양쪽 다** SKIP.

## 그 밖에 정정한 것
- `.evi-hit` 치수가 문서마다 **80×20 / 83×20**으로 갈렸다 → 게이트 출력값 **83×20**으로 통일.
- 「42건」이 화면을 섞었다 — 42는 `game/desktop` 하나의 수이고 새로고침은 **랜딩**이다 → **43건**.
- 낡은 「S3는 `coarse` 전용」 서술 **4곳**(`agent-loop-workflow` `.md`/`.html` ·
  `mafia-content-design` `.md`/`.html`). 플랜 과제에 적어 놓고 절반만 했었다.
- `touchExempt` 주석 — 하한이 **둘**이므로 폰 사유 면제가 데스크톱 24까지 조용히 면제한다는 경고.
- `probeCfg`의 죽은 `minTouchPx` 인자 제거(페이지는 이제 안 거른다).
- `.mini`에 `min-width: 24px`도 — 지금 사용처는 하나지만 유틸리티 이름이라 두 번째가 생기면 폭 하한이 없다.
