# plan: 액션 바 3단 위계 — 되돌릴 수 없는 행동을 구분한다

status: done(2026-08-26) · created: 2026-08-26 · src: 개선 루프 2회차 (플랜 21 «다음 회차 후보» 5번)

## goal
액션 바 6개 버튼이 **전부 같은 채움색**이라, 오답 시 **즉시 탈락**하는 [신고하기]와 안전한
[내 턴 종료]가 구분되지 않았다. 신규 유입이 1턴에 [신고하기]를 눌러 탈락하는 것은
Q2 «혼자서도 성립»에서 가장 비싼 첫 경험이다.

## 설계 — 채움 1단 + 색조 3단
| 단 | 대상 | 표기 |
|---|---|---|
| 주 행동 | `#suggest` 추리하기 | **채움**(primary) — 바에서 유일 |
| 위험 | `#accuse` 신고하기 | 중립과 **같은 바탕** + 위험색 글자·테두리 |
| 중립 | `#endTurn` · `#passage` · `#bonus` · `#helpBtn` | bg-alternative + line-normal 테두리 + label-strong |
| 비활성 | `.is-off` | 테두리 **없음** + label-alternative + `cursor: not-allowed` |

**위험에 채움을 주지 않는다.** 검수가 잡은 실측이 근거다: 모든 플레이어는 방 밖에서 시작하고
(`clue-room.ts` `spawnPoint` · `p.room = ""`), 그때 [추리하기]는 `.is-off`다. 즉 **모든 판 모든 사람의
첫 턴**에 채색 버튼이 [신고하기] 하나만 남는다 — 막으려던 사고의 바로 그 순간에 그 버튼을 가장
도드라지게 만드는 꼴이다. 이 버튼은 **커밋 지점이 아니라 진입점**이고(취소 가능한 모달이 열릴 뿐),
경고 책임은 모달이 진다(ui-copy §6.2 «2차 확인 다이얼로그는 만들지 않는다 — 경고 + 동사 버튼으로 충분»).

## 규칙 — ui-copy §6.2 옆에 새로 세운다 (확장이 아니다)
초안은 이 변경을 «§6.2 위험 스타일의 확장»이라고 주장했으나 **성립하지 않는다.** §6.2의 실제 구현
(`.modal .danger`)은 **솔리드 빨강 채움 + 흰 글자**이고, 새 `.act-danger`는 그것과 다른 렌더링이다.
세우는 규칙은 이것이다:
> **커밋 지점**(모달 확인)은 채움 위험색. **진입점**(바의 버튼)은 종류만 표시(글자·테두리).

## 검수가 잡은 것 (기록)
1. **위험 칩의 채움을 뺐다** — 위 «설계» 참조. 목적과 결과가 정반대였다.
2. **`border: transparent`가 죽은 선언을 되살렸다** — `.hud-ctrl button.is-off`(모바일)의
   `border-color: line-normal`은 기본이 `border: 0`이던 시절 **아무것도 그리지 않던 코드**였다.
   전 버튼에 1px을 깔자 살아나서, 폰에서 «중립 활성»과 «비활성»의 테두리·바탕이 같아졌다
   (바탕 대비 ≈1.01:1 → 구분이 글자색 하나로 축소). 관전 중에는 **유일하게 누를 수 있는 [?]가
   못 누르는 5개와 똑같아 보였다.** → `transparent`로 껐다.
3. **하드코딩 hex 2개**(`#F0CACA`·`#E8D8BE`)가 토큰 레이어 계약을 깼다 →
   `--wds-bg-alternative-strong` 토큰 신설로 흡수.
4. **특이도 계산이 틀렸다** — `(0,2,0)`이 아니라 `(0,3,1)`(타입 선택자 포함 · `:not()`은 인자
   특이도를 더한다). 모바일 override와는 **동점**이라 소스 순서로만 이겨 왔다는 사실도 주석에 남겼다.
5. **주석의 근거가 틀렸다** — `border: transparent`의 이유를 «폰 6칸 그리드 줄바꿈»이라 썼는데
   모바일 규칙에 `white-space: nowrap`이 있어 줄바꿈은 애초에 없다. 진짜 이유는
   **데스크톱 flex 폭 안정**(테두리가 붙었다 떨어지면 전환마다 바가 흔들린다).
6. **§6.2 확장 주장 철회** — 위 «규칙» 절로 재서술.
