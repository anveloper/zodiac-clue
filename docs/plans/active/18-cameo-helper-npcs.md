# 18 — 팀 카메오 계략 NPC (쿼카 · 안드로이드) (07-30)

## goal
기존 계략(엿보기) NPC 슬롯 **6개 중 2개를 고정 카메오**(쿼카·안드로)로 교체. 나머지 슬롯은 남은 십이지.
owner(anveloper) 지시 · **동결 예외 승인**(촬영 08-01 영상에 카메오 노출 목적).

## 왜 안전한가 (밸런스·게이트 무영향)
- 계략 총수·엿보기 횟수(6)는 **그대로** — 2개를 «추가»가 아니라 «교체». 밸런스 충격 0.
- 헬퍼의 **캐릭터 정체성은 표현 계층** — 엿보기 내용(`pool`=다른 플레이어 손패)은 헬퍼 값과 무관(`clue-room.ts` handleUseBonus). 카메오도 같은 1장 엿보기.
- `sim-balance.mjs`는 계략을 모델에 안 넣음(§주석 "계략 ±1.8%p 노이즈라 제외") → 밸런스 게이트 무영향.
- `eval-narrator.mjs`는 `SUSPECTS`(십이지 12)만 열거 → 112,752 코퍼스 불변. **카메오 대사는 코퍼스 밖**(동일 scheme 경로 재사용 + voice 문자열은 카드명 없이 클린하게 저작).
- 렌더러 3종(동결)은 헬퍼를 **값 기반 일반 렌더** → 파일 미수정. `makeBadge`는 배지 없으면 `[]`(크리터는 회색). 데이터만 추가.

## 설계
- 카메오 = 비-십이지 값 `"quokka"`·`"android"`. 고정 좌표·`bonus: "peek"`(1장).
  - quokka: (3,7) 정지↔사랑방(좌) · android: (20,13) 사랑채↔서재(우)
- 남은 자리 = 남은 십이지. 카메오 2칸 제외 후 `leftover.length − 2`명만 배치(2 corner strong + 나머지 mid).
- 결정성: 카메오는 상수(고정) → 시드 재생 불변. 십이지는 기존대로 `seededShuffle`.

## 미결·유의
- **실명 미노출(확정)**: owner가 "이름은 넣으면 안 된다"고 지시 → 라벨을 "쿼카"·"안드로이드"로 확정, 실명은 게임·공개 저장소 어디에도 넣지 않는다.
- **쿼카 이모지 부재**: 표준 이모지에 quokka 없음 → 🦫(비버)로 임시. EMOJI 한 줄이라 교체 쉬움.
- **eval 코퍼스 밖**: 카메오 대사는 환각검증 전수 대상 아님(동일 scheme 경로 + 클린 voice). 필요 시 후속에 코퍼스 확장(단 112,752 기준선 변동).
- **cvd·색**: 카메오는 십이지색·색각 큐 없음 → 중립색. 이모지·배지로 식별.
