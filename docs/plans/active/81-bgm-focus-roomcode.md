# 배경음 팝오버가 방 코드 위에서 열린다 — 열린 폭을 좁힌다

## goal
`#bgmCtrl:focus-within`이 열리면 컨테이너가 60 → **162**가 되어 `n320 320×568` 대기실에서
`#roomCode`를 **39.3×8px 덮는다**(`p553` 여유 15.7 · `phone` 79).
방 코드는 「옆 사람에게 불러 주고 받아 적게 하는 값」(53회차 `protect`)이라 **열어 둔 채로
읽을 수 없으면 못 쓴다.** 플랜 80 큐 1번 — «넣는 것과 고치는 것을 같은 회차에».

## 실측 (게이트 S14 · 착수 전)
| 뷰포트 | 열린 폭 | `#roomCode` |
|---|---|---|
| `n320 320×568` | 162 | **39.3×8px 덮음** |
| `p553 375×553` | 162 | 여유 15.7px |
| `phone 390×844` | 162 | 여유 79px(세로로 비켜 있다) |

**왜 여덟 회차를 살았나** — 52회차가 만든 S14 `focusPairs[0].vs`에 `#roomCode`가 없었다.
53회차가 방 코드를 대기실 1층으로 올리며 S1 `protect`에는 넣었는데 **S14에는 안 따라 들어왔다.**
41·44회차의 `#hostHint`와 같은 구멍이다.

## 기각한 처방
- **세로로 연다**(52회차의 짧은 화면 처방을 `max-width`로 확장) — 52회차가 이미 실측했다:
  `n320`·`p553`의 `[복사]` 여유가 **16 → −4px**(=덮음). 여백을 조여도 6px에 그쳤다.
- **거터를 더 판다** — 60회차가 머리글에 39px을 뺐다. 열림은 102px 더 필요해 거터로는 못 막는다.

## 처방
```css
@media (max-width: 490px) {
  body:not(.no-scroll) #bgmCtrl:hover .bgm-vol,
  body:not(.no-scroll) #bgmCtrl:focus-within .bgm-vol { width: 44px; }
}
```
슬라이더 92 → 44 ⟹ 컨테이너 162 → **114**(패딩 12+4 + 슬라이더 44 + UA 마진 4 + gap 6 + 아이콘 44).

**식** — 여유 `= L − 8 − 컨테이너폭 − 189.3`.
`#roomCode` 오른쪽 **189.3** = 카드 왼쪽 16 + 테두리 1 + 패딩 20 + 라벨 49 + gap 8 + 코드 **95.3**.
`L ≤ 412`면 카드가 `L − 32`라 왼쪽이 **16으로 고정**되므로 폭에 안 변한다.
코드 폭 95.3 = `9 × 9.633`(Menlo 16px) + `9 × 0.96`(`letter-spacing: 0.06em` — **마지막 글자 뒤에도 붙는다**).
글자 수는 결정적이다(`ROOM_CODE_LEN` 8 + 하이픈 = 9 · 등폭).
⟹ 162면 `L − 359.3`(실측 −39.3 / +15.7 — **소수점까지 일치**) · 114면 `L − 311.3` ↳ `n320` **8.7px**.

**44를 고른 근거** — 폭 하한 320에서 여유 8(관용치 `minOverlapEdgePx: 4`의 2배 · 60회차 규약)을
요구하면 컨테이너 ≤ **114.7**, 슬라이더 ≤ **44.7**. 44는 그 최댓값이면서 **52회차 짧은 화면
분기가 이미 쓰는 값**이라 새 상수를 안 만든다. 경계 490도 60회차 것을 재사용한다.

## 🔴 검수가 뒤집은 판단
1. **「최악은 좁고 짧은 쪽」이 거짓**. 높이 ≥720이면 코드 20px·패딩 24라 `#roomCode` 오른쪽이
   **217.2**, 가로 여유 `L − 339.2` → **320~339에서 최대 19.2px 겹친다.** 안 우는 이유는
   그때 카드가 위에 붙어 코드 줄 top 74 vs 버튼 바닥 62로 **세로 12px** 벌어지기 때문이다.
   60회차가 「폰은 세로로만 비켜 있다」로 정정한 것과 **같은 종류의 사실**을 새 tier에서 반복했다.
   → 주석·문서 정정 + 큐. (12는 카드가 이미 위에 고정돼 **더 안 줄어드는 바닥값**이라 이번엔 안 고친다.)
2. **화면도 축이다.** 초안은 화면 조건 없이 걸어 **게임 화면의 슬라이더까지** 반토막 냈다.
   거기서는 컨트롤이 `left: 16`에서 오른쪽으로 열려 덮을 상대가 없고(우측 컬럼이 열리면
   `display:none`), 결함은 카드 화면에서만 실측됐다. → `body:not(.no-scroll)`((1,3,1) > (0,3,0)).
3. **52회차 블록을 손대지 마라.** 초안은 폭 규칙을 그 블록에서 «떼어 내» 조건을 넓혔는데,
   그러면 그 블록의 특이도 주석이 근거를 잃고 짧은 화면 형상까지 이 회차 책임이 된다.
   → 새 규칙은 **더하기만** 한다.
4. **`F32`의 지문 `/그때 폭 162/`가 약했다.** S14 FAIL 줄이 `vs`(선택자 **전체**)를 찍어서
   「162로 되돌아갔고 뭔가를 덮었다」까지만 증명했다 — `#startBtn`이 대신 울어도 초록이다.
   → **S14가 최악 상대의 이름을 인쇄하도록 먼저 고치고**(`hit`) 지문을 `/#roomCode를/`로 못 박았다.
   덤으로 지문이 이 수리가 통제하지 않는 상수(평상 92 · 아이콘 44)에 안 묶인다.
5. **낡은 수 넷을 이 변경이 거짓으로 만들었다** — `gate.config.mjs`의 「S14 `vs`에 `#roomCode`가
   없다」(같은 파일 안 자기모순) · `index.html`의 「60 → 162 · `h1` 97×29」 ·
   `ui-copy.md`/`.html`의 「왼쪽으로 **97px** 커진다」(실제 **102** · 폭 ≤490 카드 화면은 54).
   → 전부 정정.
6. **머리글은 열린 상태에서 46×29px 덮인다.** 52회차의 `vs` 철학(「반드시 쓸 수 있어야 하는
   것만 · 스스로 연 팝오버가 스치는 것은 결함이 아니다」)에 따라 **의도적으로 `vs` 밖**에 뒀다 —
   60회차가 계약을 준 것은 **평상 상태**다. 다만 **지금 안 잰다는 사실**을 세 곳에 적었다.
7. **「분기 경계는 하나여야 한다를 지킨다」는 과장.** 490은 60회차가 만든 **두 번째** 축이고
   양쪽에 계측 뷰포트가 없다 → 「새 경계를 **안 만든다**」로 문장을 낮췄다.
8. **식에 안 적은 항 둘** — `letter-spacing`이 마지막 글자 뒤에도 붙어 8.64px을 차지한다
   (여유 8.7px과 거의 같은 크기 · `0.08em`이면 5.8px) · 헤드리스는 `env(safe-area-inset-*)`이 0이라
   「0이다」가 아니라 **「0이라 가정한다」**가 정확하다.
