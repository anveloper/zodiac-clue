# 뷰 선택기 숨김 — 제출용 빌드는 뷰1(2D) 단일 고정

> 작성 2026-07-30(다희 스펙) · 대상: `apps/client/index.html` · 반영 2026-07-31(gecko)
> 배경: 뷰1~4 4종 렌더러 유지 비용이 드러남 — 직전 두 스펙(이동 발견성·내 캐릭터 마커) 작업 중
> 뷰마다 코드를 3중으로 손대야 했고, 그 과정에서 뷰4(`pixel-scene.ts`)에 `myId`가 없던 것을 발견·수정.
> 마감(2026-08-10)까지, 심사자가 안 볼 가능성 높은 기능(드롭다운) 검증 대신 심사 축(AI 경계)에 시간 재배분.
> **코드는 삭제하지 않는다.** `iso-view.ts`·`pixel-scene.ts`·`VIEWS` 배열 등은 그대로, **선택 UI만 숨겨 뷰1 고정.**

## 삭제가 아니라 숨김인 이유
- 가역: CSS 한 줄 삭제로 즉시 복원. 삭제는 재작성·재검증 필요.
- 리스크 0: 추가 코드 0줄, DOM 표시만 변경. 마감 임박에 새 버그 위험 없음.
- 번들: 뷰2·3·4는 이미 지연 로드 청크라, 선택 UI가 없으면 그 청크는 애초에 요청되지 않는다(§9.1 스플리팅 그대로) — 삭제와 동일 효과.

## 숨겨도 안전한 근거(코드 확인)
- `.hud-view`(뷰 선택 컨테이너, index.html 430)는 `position: fixed` → `display:none` 해도 다른 HUD 재배치 없음.
- 뷰 전환 경로는 `main.ts`의 `#viewToggle`/`#viewList` 클릭 핸들러 한 곳뿐(URL 파라미터·단축키 없음). 이 DOM만 숨기면 도달 불가.
- 뷰1(`2d-emoji`)은 이미 기본 시작 뷰(main.ts 697 주석) — 기본값 고정 코드 불필요.

## 변경 (index.html CSS)
```css
.hud-view { display: none !important; }
```
- `!important`: 821행 모바일 override가 다시 `display`를 건드릴 수 있어 어떤 화면에서도 확실히 숨김.

## 손대지 않는 것
- `VIEWS` 배열·뷰 전환 함수·뷰2/3/4 로더·`iso-view.ts`·`pixel-scene.ts`·JS 클릭 핸들러 — 전부 유지.
