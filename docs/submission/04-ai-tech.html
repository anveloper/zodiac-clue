0. 핵심 원칙 — AI를 두 층으로 나눠 쓴다

층담당AI 종류없으면
진실 계층정답 봉투·카드 분배·반증·고발 판정없음(순수 규칙)게임 성립 안 함
에이전트 계층빈 좌석 NPC의 추리·의사결정결정론 추론 엔진게임 성립 안 함(혼자 접속하면 상대 0명)
표현 계층NPC 대사·연출LLM(Gemini)게임은 굴러가나 캐릭터가 사라짐

AI 없으면 게임이 성립 안 되는 지점 = 에이전트 계층. 심사자는 링크를 눌러 혼자 플레이하는데, 클루는 상대가 없으면 반증 자체가 안 된다. 봇의 좌석 충원은 연출이 아니라 게임 성립 조건이다.

왜 판정에서 LLM을 배제했나 — 설계 판단 4근거

  • 환각이 곧 규칙 위반. 반증은 전칭 판정이라 LLM이 없는 카드로 반증하면 정답이 도달 불가능 — 게임이 "틀리는" 게 아니라 끝나지 않는다.
  • 재현성 없으면 검증도 없다. 진실값을 규칙 함수로 고정했기에 판을 오프라인에서 1만 번 재생·시뮬할 수 있다.
  • 치트 불가는 "안 준다"로만 증명. solution은 private이고 스키마에 없어 동기화 자체가 안 된다. 프롬프트에도 넣지 않는다 — 주지 않은 정보는 인젝션으로도 못 샌다.
  • 무료티어에서 판정은 못 산다. 판정을 LLM에 걸면 호출이 행동에 비례해 폭증, 429 한 번에 게임이 멈춘다. 표현에만 걸면 429는 말투가 단조로워질 뿐.

→ LLM을 표현에 가둔 것은 능력 부족이 아니라 검증 가능성과 가용성을 사기 위한 설계 비용이다. 그래서 이 문서의 본론은 "AI를 어떻게 넣었나"가 아니라 "AI를 어떻게 지휘·검수했나"다.

1. 디렉팅 — LLM은 결정에 참여하지 않는다

NPC 대사는 narrate() 하나가 만든다. 입력 필드는 전부 규칙엔진이 이미 확정한 값(화자 이름·행동·제안 3장·페르소나·말투)이다. LLM은 그 결정을 사람이 읽을 문장으로 바꿀 뿐이다.

절대 넘기지 않는 값

값LLM 전달
정답 봉투 solution없음 (전 경로) — 입력 타입에 필드 자체가 없다
임의 플레이어 손패 / 봇 후보집합 / 대사 히스토리없음 — 히스토리 없음 = 인젝션 표면 0

단 하나의 예외 — 계략(귓속말)의 hint: 규칙엔진이 이미 그 사용자에게 공개하기로 결정한 카드 라벨만 넘기며, 그 출력은 동일 수신자에게만 전송된다. LLM이 카드를 고르지 않는다.

2. 환각 검증 — 사람 눈이 아니라 기계로 판정

"LLM이 진실값을 바꾸지 않았는가"를 pnpm eval:narrator(오프라인·Gemini 호출 0)가 기계로 판정한다. 커밋마다 통합 게이트 pnpm verify에서 돈다.

검사내용
C1~C3한 줄 · 길이 상한 · 마크업/머리말 금지
C4 (blocking)진실값 치환 없음 — 제안 카드를 바꿔 말하면 FAIL(로그와 대사가 모순되면 오추리 유발)
C5 (blocking)미제공 카드·금지어(정답/봉투/손패…) 누출 없음
C6 (blocking)계략: hint 외 다른 손패 라벨 등장 시 즉시 FAIL

실측(2026-07-28, seed 고정): 스위트 A 36케이스·문안 130 + 폴백 전수 112,752문장 — C1~C6 위반 0. 판정기 자기검사(알려진 위반 11건이 실제 FAIL로 잡히는지)도 함께 통과.

정직한 한계. 위 112,752 전수 PASS는 전부 폴백(결정론 템플릿) 경로다 — 구조상 환각이 불가능한 생성기를 검사한 것이라 거의 항진명제에 가깝다. 정작 위험한 실제 Gemini 출력에 대한 C4·C5 표본은 아직 0이다(--live 36콜을 돌리면 처음 생긴다). 경로·지연 분포(C7)도 무료 쿼터를 소모하므로 미판정으로 남겼다 — 추정치로 채우지 않았다.

3. 관측 가능성 — AI가 돌았다는 증거를 화면에

문제: 대사가 어디서 왔는지가 화면에 없으면, 심사자가 플레이해도 AI 흔적이 0이고 이 문서의 주장이 입증 불가다(실제로 2026-07-27 라이브에서 대사 5/5가 폴백이었는데 화면상 신호가 없었다).

구현(2026-07-28):

  • narrate() 반환에 경로·지연·모델·폴백사유(6종) 동봉. 대사 줄마다 배지(✨LLM · ♻캐시 · ⚙폴백) + 지연(✨ 0.9s).
  • AI 카운터 칩 기본 노출(✨LLM · ♻캐시 · ⚙폴백) — 쿼리 파라미터 게이팅 없이. 심사자는 파라미터 없는 URL로 들어온다.
  • 서버 GET /health → AI 상태·모델·호출/폴백/쿼터오류 수. 전부 폴백이어도 숨기지 않고 사유와 함께 표시 — 값을 감추는 칩은 계측이 없는 것과 같다.
  • 운영 메타는 게임 상태(스키마)에 넣지 않았다 — "AI가 판정에 관여한다"는 오독 방지.

실측 1판: 23제안·24발화 = LLM 19(평균 923ms) · 캐시 0 · 폴백 4. 이 계측이 우리 문서의 주장 2건을 반증하기도 했다("왕복 ~1.2초"→실측 926ms, "캐시가 완충"→히트 0/24).

사람이 AI에 위임하지 않은 결정권

AI가 코드를 썼다는 사실보다, 무엇을 AI에게 맡기지 않았는지가 이 프로젝트의 설계다.

  • 게임 주제·컨셉·스코프 확정(회의록) · 진실값 경계 규약 자체(AI가 자기 권한을 정하지 않는다).
  • D-14 신규 기능(자유 심문) 기각 · 제출 형태(개인/팀) 결정.
  • API 키 발급·과금(.env는 gitignore, 에이전트는 키를 본 적 없다) · main 병합·프로덕션 배포 승인.
  • 실제 플레이 영상 촬영(AI 합성 금지 → 사람이 직접 녹화) · 공개 문서 범위.

다인 라이브 디렉팅 — 디스코드 · 브랜치별 워크트리 · 브랜치별 프리뷰 URL

커밋 계정이 1개인 것은 git 아티팩트다. 실제 디렉팅은 여러 팀원이 각자 디스코드 채널로 에이전트에 실시간 지시하는 다인 루프다.

  • 다인 디스코드 루프: 팀원이 요청(스펙·에셋 첨부) → 에이전트가 구현·검증·배포 → 진행도·캡처·URL을 디스코드로 회신 → 사람이 화면 보고 다음 지시.
  • 브랜치별 워크트리 격리: 팀원마다 전용 브랜치 + 독립 git worktree. 에이전트는 지시받은 브랜치 밖으로 나가지 않는다.
  • 브랜치별 프리뷰 URL: 브랜치 서브도메인 별칭으로 프로덕션과 분리된 화면에서 즉시 확인. 오너 승인 뒤에야 main→prod.
  • 병합·배포 승인은 전부 사람(오너) 결정 — 에이전트는 스스로 병합·배포하지 않는다.
