# 설계: 게임형 카메라 + 플로팅 HUD

> ref plan: docs/plans/active/05-camera-and-hud.md · human view: 20260720-camera-and-hud.html
>
> **갱신 2026-07-21**: 초기 설계안이라 실제 구현과 어긋난 부분을 ~~취소선~~ + 갱신줄로 반영. 구현 상수는 `apps/client/src/scenes/game-scene.ts` 기준.

## 문제
현재는 왼쪽 보드 + 오른쪽 사이드패널(단서/로그) 레이아웃이라 "게임"보다 "대시보드"처럼 보인다. 보드가 뷰포트에 다 들어와 몰입감이 없다.

## 목표(UX)
1. 보드가 화면보다 크고, **내 캐릭터 기준 탑뷰**로 확대되어 보인다.
2. 이동 시 카메라가 내 캐릭터를 부드럽게 따라온다.
3. **휠 스크롤로 줌 인/아웃**.
4. **특수키(hold) 자유시점** — 놓으면 내 캐릭터로 복귀.
5. 단서 패/증거 체크/로그는 **화면 모서리 플로팅 UI**로만 노출(사이드패널 제거).

## 접근(Phaser 3) — 구현 반영
- **레이아웃**: `Scale.RESIZE`, `#game`을 100vw×100vh. index.html의 사이드패널을 DOM 오버레이(position:fixed)로 대체. ✅
- **카메라 추적**: ~~`cam.setBounds(...)` + `startFollow(myDisc, 0.12, 0.12)`(내 토큰만 추적)~~
  - (구현) **setBounds 미사용**(우측 패널만큼 화면을 밀어도 되도록). 시작 시 `setZoom(INIT_ZOOM)`·`centerOn(중앙)`. `startFollow`로 추적하되 **추적 대상 = 현재 턴 캐릭터**(내 턴이면 나, 아니면 그 NPC/상대). 내 토큰은 `room.sessionId`로 식별.
  - **턴 전환 시 지연 팬**: 턴이 바뀌면 바로 스냅하지 않고 `CAM_SWITCH_DELAY=900ms`(내 턴은 150ms) 뒤 `cam.pan()`으로 부드럽게 이동 → 반증을 먼저 인지하고 덜 어지럽게. 추적 lerp = 내 턴 `CAM_LERP=0.12`, 남 턴 `SLOW_LERP=0.06`.
  - **우측 패널 인셋 보정**: `followOffset.x`를 우측 패널 폭만큼 줘서 대상이 "보이는 영역" 중앙에 오게.
- **줌**: 휠로 `clamp(zoom*(dy>0?0.9:1.1), MIN, MAX)`. ~~기본 1.6~2.0배, MIN≈0.6, MAX≈3~~
  - (구현) **INIT_ZOOM=1.0, MIN_ZOOM=0.4, MAX_ZOOM=1.25**.
    <!-- 2026-08-29 정정: 0.3 → 0.4. `board-cell-face-tokens` 플랜이 셀 40→80과 함께 올렸는데
         이 문서만 옛 값에 남아 있었다. -->
  - **초기 줌은 `fitZoom(짧은 변, INIT_ZOOM, MIN_ZOOM)`** — 짧은 변에 `INIT_MIN_CELLS=17`칸을
    넣으려 시도하되 `MIN_ZOOM`으로 clamp한다.
    - **데스크톱 1440×900 → 짧은 변 900 → 줌 0.662.** 기본 줌 1.0에 clamp되지 **않는다** —
      즉 **데스크톱 줌을 정하는 것이 바로 이 상수**이고 짧은 변에 정확히 17칸이 들어온다.
      (옛 문서의 「1.32 → clamp 1.0 · 데스크톱은 영향 없음」은 `CELL_PX=40` 시절 값이다.)
    - ⚠️ **`short < 0.4×17×80 = 544px`이면 `MIN_ZOOM`이 이겨 17칸이 실현되지 않는다** —
      게이트 폰 뷰포트 **390**에서는 **12.2칸**이다(그 외 폭은 미확인).
    - ⚠️ 도입 시점(`a5a9e31`)에는 `CELL_PX=40`·`MIN_ZOOM=0.3`이라 폰 줌 0.574로 **상수가 지배했다.**
      무효가 된 것은 `eff7c0f`(셀 40→80·`MIN_ZOOM` 0.3→0.4)가 **조용히 무효화**했기 때문이다.
- **보드 위 «라벨»은 줌을 따라 작아지지 않는다 `[2026-08-29]`** — 방 명패는 컨테이너에
  `min(1/zoom, PLAQUE_MAX_SCALE=2)` 역스케일을 걸어 **화면 크기를 고정**한다(zoom≥0.5에서 정확히 30px).
  그 전에는 폰(zoom 0.4)에서 칩 30→**12px**, 이름 18→**7.2px**로 「여기가 어느 방인가」가 안 읽혔다.
  **데스크톱도 줌 0.662라 배율 1.511이 걸린다** — 이 변경은 데스크톱에서도 명패를 51% 키운다.
  - 명패는 **아래변 기준**으로 자라 문(방 경계)을 덮지 않는다(위로만).
  - 깊이 `PLAQUE_DEPTH=3` — 문(1)·장물(2) 위, **깊이 3군의 일시 표기**(`focusRoom`·`pulseCell`·워프
    잔상)와는 같은 깊이라 삽입 순서로 갈린다(명패가 먼저 생기므로 일시 표기가 위). 4는 과했다.
  - **토큰 `TOKEN_DEPTH=5`** — 그전에는 `setDepth`가 없어 **0**이라 내 말이 장물(2)·문(1) 뒤로
    들어갔다. 명패를 올리면서 함께 푼다. 말은 판에서 가장 앞이다.
  - **윗벽 문 3방(안방·행랑채·별당)의 `🚪`는 방 안쪽으로 뒤집는다** — 바깥 `🚪`(y=1406)가
    명패 띠 안이라 배율 1.511에서도 **통째로 가려졌다**. 아랫벽·옆벽 문은 그대로 둔다.
  - 상한 2배의 근거는 **복도 한 줄** 하나다: `(80−6)/30 = **2.467**`. 배율 2에서 같은 행 이웃과
    최소 **432px**(정지(부엌)↔대청마루) 떨어진다. ~~「보드 밖으로 나간다」~~ 는 근거가 못 된다 —
    복도는 안 칠하고 DOM 잔디가 비쳐 `y=−1`과 `y=+1`이 시각적으로 같다.
  - ⚠️ **윗줄 3방은 카메라 위치에 따라 상단 HUD 뒤로 들어갈 수 있다.** `applyCamBounds`는
    `ins.right`·`ins.bottom`만 보상하고 `HudInset`에 **`top`이 없다**. 말풍선이 쓰는
    `hudSafe()`가 상단 밴드를 이미 알므로 경로는 있다(플랜 51 큐).
  - **나머지 라벨도 같은 규칙을 받는다 `[2026-08-29 · 32회차]`** — 토큰 이름표 묶음(이름·색
    스트라이프·탈락 파선·색각 큐) · 「나」 배지 · 계략 태그 · 🃏 · 「잔치상」.
    상한은 **`LABEL_MAX_SCALE = 1 / MIN_ZOOM = 2.5`** — `world × min(1/z, 1/MIN_ZOOM) × z`는
    `z ≥ MIN_ZOOM`에서 항상 `world`이므로 **줌 전 구간에서 화면 크기가 정확히 고정**된다.
    명패만 2.0인 것은 **복도 한 줄** 제약이 명패에만 있기 때문이다.
    폰(z=0.4)에서 이름표 **5.2px**(역스케일 전) → **13px 고정**.
    ⚠️ 대가 — 이름표 **월드 폭**이 2.5배가 된다. 한 칸 80px이라 같은 방에 모이면 겹친다
    (배율 1에서도 이미 넘었으므로 새 종류의 문제는 아니고 폭이 커진다).
  - **「잔치상」은 나무 칩 위에 얹는다** — 맨 글자를 음식 그림 위에 두면 안 읽힌다.
    반투명 `#000000aa`는 최악(흰 음식) 합성에서 실효 배경 `#555555`라 `feastText` **4.23(AA 미달)**,
    불투명 `BOARD.plaque`면 **9.03**이다. 장소 라벨의 시각 언어가 방 명패와 하나가 된다.
  - 🔴 **`MIN_ZOOM`을 내려 판을 한눈에 — 지금 구조로는 안 된다**(32회차 계산).
    상한이 `1/MIN_ZOOM`이라 `MIN_ZOOM`을 내려도 **화면 크기는 13px 그대로**다.
    막는 것은 **월드 폭**이다(최장 이름 「호랑이 대감」 실측 base **89px**):

    | MIN_ZOOM | 보이는 칸 | 배율 | 이름표 월드 폭 |
    |---|---|---|---|
    | 0.400 (현재) | 12.2 | 2.50 | 223px = **2.8칸** |
    | 0.287 | 17.0 | 3.48 | 310px = **3.9칸** |
    | 0.203 (전체) | 24.0 | 4.93 | 438px = **5.5칸** |

    한 칸이 80px이라 줌아웃할수록 이름표가 **판을 뒤덮는다.**
    ⚠️ **구조를 바꾸면 길이 있다** — ① **화면 공간 라벨**: 말풍선(`placeBubble`)이 이미
    하는 방식(월드 앵커를 화면 좌표로 투영 + 역스케일 + 안전영역 클램프)이면 라벨 크기와
    월드 점유가 **분리**되고 겹침은 2D 배치(declutter) 문제가 된다.
    ② **LOD** — 임계 줌 아래에서 이름표를 끄고 얼굴+색만 남긴다.
    ③ **declutter** — 줌아웃 시 현재 턴·내 토큰만 이름표를 켠다.
    (초안은 「줌아웃과 인월드 라벨은 양립하지 않는다」로 단정했다 — ①을 안 본 결론이었다.)
- **자유시점**: `Space`(hold) keydown → `cam.stopFollow()`, 드래그 팬(pointermove while down) + 방향키 팬. keyup → 현재 대상으로 `startFollow` 복귀. 자유시점 동안 이동키는 팬, 캐릭터 이동은 잠금. ✅
- **HUD(DOM)**: Phaser 텍스트 대신 DOM 플로팅이 리스트/토글에 유리.
  - 좌하: **내 단서 패**(받은 카드 이모지+라벨).
  - 우측: **증거 체크리스트** — 용의자/~~흉기~~장물/장소 전 항목을 표로, 클릭 토글(있음/없음/의심) 로컬 메모(서버 전송 X, 개인 추리 노트). <!-- 갱신 2026-07-21: 흉기 → 장물(훔친 것) -->

  - 우하: **로그/알림**(제안·반증·대사), 접이식.
  - 상단: **턴 배너 + 순서 스트립(구현 추가)** — 현재 턴 상태(내 턴이면 남은 이동) + `turnOrder`를 **현재→다음… 방향**으로 이모지 칩 나열(현재 강조, 끝에 `↺` 순환). 배너 클릭 시 **원형 순서 오버레이**(라운드 테이블·시계방향·현재/다음 배지)로 전체 순서를 한눈에.
- **NPC 말풍선(구현 추가)**: 캐릭터 위에 **타자기 효과 말풍선**(`TYPE_MS=55ms`/글자, 완료 후 `BUBBLE_HOLD_MS=2600ms` 유지). 봇 제안 대사가 타이핑되는 동안엔 턴을 넘기지 않아 카메라가 튀지 않음(서버 `SPEAK_HOLD`). 계략 귓속말은 당사자에게만 전문 말풍선.
- **마우스 팬(구현 추가)**: 우클릭/휠클릭 드래그로 화면 이동(Space 없이). 컨텍스트메뉴 차단. 모든 뷰 단계(뷰1/2/3) 공통.
- **조작 안내**: 최초 진입 시 하단 얇은 바 — 이동(WASD/방향키/ㅈㅁㄴㅇ) · 줌(휠) · 화면이동(우클릭드래그/Space) · 입구로 진입 후 제안/고발.

## 주의
- 자유시점과 이동키 충돌: 자유시점 활성 중에는 `room.send("move")` 억제.
- 줌·팬은 클라 로컬 상태(서버 무관) → 네트워크 영향 없음.
- 증거 체크는 개인 노트라 서버 스키마에 넣지 않음(로컬스토리지 캐시 가능).
- 리사이즈 시 HUD 위치 재계산(카메라는 setBounds 미사용).

## 롤아웃 순서
풀스크린 캔버스 → 추적 카메라 → 줌 → 자유시점 → HUD(단서/증거/로그) → 조작안내 → 반응형.
