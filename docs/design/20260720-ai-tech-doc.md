## 0. 핵심 원칙 — 이중 계층: 결정론적 진실 계층 + LLM 표현 계층

이 게임은 **AI를 두 층으로 나눠 쓴다.** 한 층은 게임이 성립하기 위해 반드시 있어야 하고(load-bearing), 다른 한 층은 그 결정을 사람이 읽을 수 있는 말로 바꾼다.

| 층 | 담당 | 구현 | AI 종류 | 없으면 |
|---|---|---|---|---|
| **진실 계층** | 정답 봉투·카드 분배·반증·고발 판정 | `apps/server/src/rooms/clue-room.ts` | 없음(순수 규칙) | 게임이 성립 안 함 |
| **에이전트 계층** | 빈 좌석을 채우는 NPC의 **추리·의사결정** | `clue-room.ts` `runBotTurn` / `botSuggestPhase` / `initBotKnowledge` | **결정론적 추론 엔진** | **게임이 성립 안 함** — 심사자가 혼자 접속하면 상대가 0명 |
| **표현 계층** | NPC 대사·연출 | `apps/server/src/ai/narrator.ts` | **LLM (Gemini)** | 게임은 굴러가나 **캐릭터가 사라진다** |

### 0.1 무엇이 load-bearing인가
상류 정의(`docs/archive/planning/brainstorming/20260714-game-ideas.md`)는 **"AI 없으면 게임이 성립 안 되는 설계"**를 요구한다. 이 프로젝트에서 그 조건을 지는 것은 **에이전트 계층**이다.
- 07-18 회의에서 **"심사자는 링크를 눌러 혼자 플레이한다"**는 제약이 확정됐다. 클루는 3~6인 불완전정보 게임이라 **상대가 없으면 규칙 자체가 작동하지 않는다.**
- `addBot()`이 빈 좌석을 십이지 캐릭터로 채우고, 각 봇은 **자기만의 지식 상태**(후보집합)로 소거 추리를 수행한다. 이 층을 빼면 1인 게임이 되어 **제출물 ①(플레이 가능한 빌드) 요건 자체가 무너진다** → load-bearing.
- 표현 계층(LLM)은 load-bearing이 아니다. **그렇게 설계했다.** 이유는 §0.2.

**초판이 틀린 지점**: 초판은 "load-bearing AI = 표현 전용"이라 썼다. 상류 용어를 뒤집어 쓴 것이며, 같은 문서의 "LLM 장애와 무관하게 게임은 정상"과 자기모순이었다. §0.3에서 정정한다.

### 0.2 왜 판정에서 LLM을 배제했는가 — 설계 판단 4근거
1. **환각이 곧 규칙 위반이 된다.** 반증은 "내 카드 중 제안 3장과 일치하는 것"이라는 전칭 판정이다. LLM이 이를 하면 없는 카드로 반증(위양성)하거나 가진 카드를 놓치는(위음성) 순간 **정답이 도달 불가능해진다.** 게임이 "틀리는" 게 아니라 **끝나지 않는다.**
2. **재현성이 없으면 검증도 없다.** `temperature 0.95` 생성기는 같은 입력에 같은 출력을 주지 않는다. 판정이 여기 걸리면 버그 재현이 불가능하고 밸런스 시뮬레이션(1만 판)도 원리적으로 못 돌린다. 진실값을 규칙 함수로 고정했기에 **판을 오프라인에서 1만 번 재생할 수 있다.**
3. **치트 불가능성은 "안 준다"로만 증명된다.** `this.solution`은 `private`이고 `GameState` 스키마에 없어 **동기화 자체가 안 된다.** 손패도 서버 전용 Map에 두고 해당 클라에게만 전송한다. LLM 프롬프트에도 넣지 않는다(예외 1건은 §2.2). **"정답을 알려주고 말하지 말라고 지시"하는 방식은 인젝션 한 번에 무너지지만, 주지 않은 정보는 새어나갈 수 없다.**
4. **무료티어에서 판정은 못 산다.** 판정을 LLM에 걸면 호출이 행동에 비례해 폭증하고 429 한 번에 **게임이 멈춘다.** 표현에만 걸면 429는 **말투가 단조로워지는 것으로 끝난다.**

> **LLM을 표현에 가둔 것은 능력 부족의 인정이 아니라, 검증 가능성과 가용성을 사기 위해 지불한 설계 비용이다.** 그래서 본 문서의 본론은 "AI를 어떻게 게임에 넣었나"가 아니라 **"AI를 어떻게 지휘·검수했나"**(§2·§3·§7)다.

## 1. 계층 구조 (실측 파일 맵)

### 1.1 진실 계층 — 규칙엔진 (`clue-room.ts`, 1937줄)
전부 결정론 함수. LLM 호출 0.
- **정답 봉투**: 용의자·장물·장소 각 1 → `this.solution`(private, 스키마 밖)
- **덱 18장**: 참여 캐릭터 6−1=5 · 장물 6−1=5 · 장소 9−1=8. 전부 비정답
- **솔로 완화**: 사람 1명이면 딜 전 2장을 `commonCards`로 공개(정답 아님)
- **이동**: 2d6 · `canCross()`(방↔방 직접 이동 불가, 입구 1칸으로만) · 비밀 통로 3쌍
- **제안**: 용의자·장물 토큰을 방 `summon` 앵커로 소환 → 시계방향 첫 매치 1장 반증
- **고발**: 3필드 완전 일치만 승리, 불일치면 `eliminated = true`(반증만 가능)
- **비밀 격리**: `solution`·`hands`·`botKnowledge` 전부 private. `GameState`에 없음

  > **조치**: 검사 기준을 손패 → `seenOf(id)`(내 손패 ∪ 공통 단서 ∪ 내가 받은 반증 카드)로 교체.
  > 이 집합이 정확히 «내가 정답 아님을 아는 값»이고, 그것이 이 추론이 요구하는 전제다.
  > 정답 값은 `markSeen` 4개 콜사이트 중 어느 경로로도 `seenOf`에 들어갈 수 없으므로
  > **막히는 고발은 전부 오답이었던 것**이다(20,000판 실측 — 정답 제안이 막힌 건 0건).
  >
  > **언제 생겼나 — 「0.0%」는 쓰인 시점엔 참이었다.** 재진입 잠금이 없으면 후보 방 집합이
  > 비지 않아 `anyRoom` 폴백이 **도달 불가**다. 실측(20,000판·시드 20260728)이 그대로 보여준다:
  >
  > | 변형 | 재진입 | 봇 탈락 판(수정 전 → 후) |
  > |---|---|---|
  > | ①②③④ | ✗ | **0.0% → 0.0%** |
  > | ⑤ (상한 60) | ✓ | 0.2% → **0.0%** |
  > | ⑥ (상한 75) | ✓ | 0.3% → **0.0%** |
  > | ⑦ (+도박 고발) | ✓ | 6.8% → 6.4% |
  >
  > 즉 **1개월 묵은 거짓말이 아니라 07-28 재진입 규칙(§7.5.2) 추가의 부작용**이다.
  > 위 「봇 탈락 판 0.2% → 7.0%」의 **0.2%가 바로 이 버그**이고(⑥ 기준), 진단문의 0.0%는
  > **재진입 이전** 규칙셋의 값이다 — 서로 다른 규칙을 잰 두 숫자라 모순이 아니다.
  >
  > **밸런스**: ⑦ 사람 승률 21.45% → **20.88%**(−0.57%p) · 밴드 ±2%p 안 → **기준선 불변**.
  > 단 이 −0.57%p를 «규칙 변경의 효과»로 읽지 마라. **봇 좌석에만** 적용하면 −0.13%p로
  > 표준오차(±0.29%p) 미만이다. 나머지 −0.44%p는 **시뮬 HUMAN 모델**이 함께 똑똑해진 몫이다
  > (서버엔 사람 자동 고발이 없다). 평균 라운드 7.23 불변 · 제안 p95 67 불변 ·
  > 상한 도달률 0.06% → 0.09%(ceiling 2%).
  >
  > **도박 고발(위)과는 다른 경로다** — 그쪽은 *의도된* 확률적 리스크이고, 이쪽은 «확신»을
  > 자처하던 결정론 경로였다. ⑦의 6.8% → 6.4%는 이 몫의 제거량이 **아니다**(봇 좌석에만
  > 적용하면 6.8%로 남는다) — 판 궤적이 흔들려 도박 분포가 바뀐 결과다. 깨끗한 수치는 ⑥의 0.3% → 0.0%다.

### 1.3 표현 계층 — LLM (`ai/narrator.ts`, 544줄)
`narrate()` 하나가 전부. 실패하면 `text: null`을 돌려주고 호출부가 `fallbackLine()`으로 대체한다. **호출 지점 5곳**, 액션 3종.

> **07-28 정정 — "4곳"은 틀렸다.** 심사자 시선 검수에서 세어 보니 `speak()` 콜사이트가 4개(`clue-room.ts` 제안·미반증 즉시 고발·후보 수렴 고발·**도박 고발**)이고 `helperWhisper()`가 1개다. 누락된 것은 §1.2 (b) 해소 때 새로 생긴 **도박 고발**이다 — 기능을 넣고 그 기능이 LLM을 부른다는 사실을 문서에 반영하지 않았다. 액션은 여전히 3종이다(도박 고발도 `action: "accuse"`).

## 2. 디렉팅 명세 (Directing Spec)

### 2.1 입력 계약 — 규칙엔진이 이미 확정한 필드만
**모든 필드는 결정이 끝난 값이다. LLM은 결정에 참여하지 않는다.**

| 필드 | 출처(누가 확정했나) |
|---|---|
| `name` | `label(suspect)` |
| `action` | 규칙엔진의 턴 판단 (`suggest`/`accuse`/`scheme`) |
| `suspect`/`weapon`/`room` | `botSuggestPhase`가 후보집합에서 확정한 한글 라벨 |
| `hint` | `peek` 결과 카드 라벨. **`scheme` 전용** (§2.2) |
| `persona`/`tone` | `PERSONA`/`VOICE[*].tone` 상수 |
| `intro`/`outro` | `VOICE` 추임새. **폴백 전용**(LLM 경로 미사용) |
| `disproved` | `doSuggestion()`의 반환값 |

호출 지점 **5곳**: `speak()` ← ①제안 ②미반증 즉시 고발 ③후보 수렴 고발 **④도박 고발**(§1.2 b) / `helperWhisper()` ← ⑤계략 귓속말. `speak()`가 화자의 `suspect`로 말투를 자동 주입하므로 콜사이트는 말투를 몰라도 된다. **④는 규칙 함수 `gambleAccusation()`이 먼저 판정하고 대사는 그 뒤에 붙는다** — 대사가 고발 여부를 정하지 않는다.

### 2.2 절대 넘기지 않는 값

| 값 | LLM 전달 | 근거 |
|---|---|---|
| **정답 봉투** `solution` | **없음(전 경로)** | 입력 타입에 대응 필드 자체가 없다 |
| 임의 플레이어의 손패 `hands` | **없음** | 동일 |
| 봇 후보집합 `botKnowledge` | **없음** | "무엇을 아직 모르는지"는 표현에 불필요 |
| `revealed` 전역 집합 | **없음** | 봇의 내부 지식이지 대사 소재가 아님 |
| 이전 대사 히스토리 | **없음** | 대화 문맥 없음 = **인젝션 표면 0** |

**단 하나의 예외 — `scheme`의 `hint`.** 계략 사용자에게 규칙엔진이 **이미 공개하기로 결정한** 카드(모서리 2장/그 외 1장)의 라벨이 LLM에 전달된다. 경계 위반이 아닌 이유:
1. **결정은 이미 끝났다** — 어떤 카드를 볼지는 규칙엔진의 셔플이 정한다. LLM은 고르지 않는다.
2. **수신자가 이미 아는 정보다** — 같은 카드가 `peek` 메시지로 평문 전달된 뒤에 대사가 나간다.
3. **출력이 봉인된다** — LLM 문장은 **당사자에게만** 가고 나머지 전원에게는 **`"(귓속말)"`만** 브로드캐스트된다. 흘려도 **도달 대상은 이미 그 정보를 가진 1명뿐**이다.
4. 그 카드들은 **정의상 전부 비정답**이다(덱은 정답 3장을 제외하고 구성된다).

### 2.3 출력 계약
**systemInstruction 요지**: 사극풍 NPC. "결정된 행동"을 **대사 한 문장으로만** 변환. 머리말/설명/선택지/마크다운/따옴표 전부 금지, 규약 길이 **12~40자**, **정답이나 남의 손패를 아는 척 금지, 주어진 정보만 사용.**

> **07-28 3차 — 목표 길이를 내렸다(상한 40은 불변).** 라이브 실측에서 **원문의 22%가 40자를 넘겨 폐기**되고 있었다(§4 구현 결과). 상한을 올리는 대신 **모델에게 주는 목표**를 내렸다.
> - **32자 유도**: 관측된 최대 원문 50자 = 상한 40 대비 **초과율 1.25배**. 같은 초과율이 유지된다면 목표를 `LINE_MAX / 1.25 = 32`로 두었을 때 최악의 원문이 40자 안에 들어온다(`LINE_TARGET_LOUD`). 제안은 페이싱 예산(§6.2)이 더 빡빡해 **25자**(`LINE_BUDGET_SUGGEST`)를 그대로 쓴다.
> - **어절 앵커**: **모델은 글자를 못 세지만 어절은 센다.** 목표를 글자 수와 함께 «어절 N개 이하»(`target / 4`, 한국어 어절 ≈ 3자 + 공백)로 주고, 시스템 지시에 **실제 길이 예시 3개**("그 셈속이 훤히 보이는구먼 = 14자" 등)를 넣었다. 문구를 베끼지 말라고 못 박아 대사 다양성은 유지한다.
> - **규약을 느슨하게 한 것이 아니다.** 상한 `LINE_MAX 40`·하한 `LINE_MIN 12`·`LINE_BUDGET_SUGGEST 25`는 전부 그대로다. 바뀐 것은 **프롬프트가 요구하는 목표**뿐이다 — 지키기 쉬운 목표를 준 것이지 통과 기준을 내린 것이 아니다.
> - ⚠️ **1차 시도가 C4를 깼고 실측이 그것을 잡았다.** 짧게 쓰라는 압력으로 «세 요소를 다 읊지 말고 한둘만 집어라»를 넣었더니 **8콜 중 2콜이 라벨을 하나도 넣지 않아** §3 C4(진실값 유지)가 **6/8로 떨어졌다.** 짧게 쓰라는 압력과 "결정된 값을 말하라"는 계약은 같은 문장에서 못을 박아야 한다 → **"최소 하나는 준 글자 그대로"**로 고정해 **8/8 복구**. 프롬프트 변경이 진실값 계약을 무너뜨릴 수 있다는 것을 문서가 아니라 계측이 보여줬다.

**생성 파라미터** — `temperature 0.95` · `maxOutputTokens 64` · `AbortController` 4000ms. **`thinkingConfig`는 보내지 않는다.**
> 이력: 초기에는 `thinkingBudget: 0`을 보냈다. flash 계열이 thinking 모델이라 끄지 않으면 생각 토큰이 64 예산을 먹고 빈 응답이 왔기 때문이다(`docs/logs/20260720-npc-llm-persona.md`).
> 그러나 2026-07-28 시점에 `gemini-flash-lite-latest` 별칭이 **해당 파라미터를 거부하는 세대로 이동**해 `400 INVALID_ARGUMENT`가 되었고, 그 400이 폴백으로 흡수돼 전 대사가 규칙 대사로 나갔다(§4.1).
> 현재는 미지정으로 두며 64토큰 예산에서 빈 응답 없이 정상 동작한다(실프롬프트 5/5 · 라이브 12/12).
> **모델 별칭은 계약이 아니다** — `-latest`는 언제든 파라미터 수용 범위가 바뀔 수 있으므로 §3의 C7(경로 분포)이 회귀 검사 역할을 한다.

**사후 정규화** — 프롬프트를 신뢰하지 않고 코드로 강제: ① 첫 줄만 ② **따옴표·별표·밑줄·해시·백틱 제거(양끝 + 문장 중간)** ③ **상한 초과 시 3단 절단(문장 → 절 → 어절), 어느 단계도 못 자르면 폐기 후 규칙 폴백**(07-28 3차. 그 전은 문장 경계 1단, 초판은 80자 하드컷·양끝 한정).

> **07-28 3차 — 1순위 절단은 원리적으로 발동할 수 없었다.** 라이브 계측이 답을 이미 갖고 있었다: `ops {drop: 9}`인데 **`truncate`가 단 1건도 없다.** 프롬프트가 «한 문장만»을 요구하므로 종결부호는 문장 맨 끝에 하나뿐이고, **원문이 상한을 넘겼다는 말은 곧 그 유일한 경계가 상한 밖**이라는 뜻이다. 그래서 초과분 100%가 폐기로 떨어졌다 — 우연이 아니라 구조였다.
> - **넓힌 것은 경계 후보이지 규약이 아니다.** 문장 경계가 없으면 **절**(`, · ;` 등) → 그것도 없으면 **어절**로 후보를 내리고, 미완결 문장은 `…`로 닫는다. 절·어절 두 후보 중 **더 많이 살리는 쪽**을 쓴다(잘려나간 뒷부분에 3요소 라벨이 있을 수 있다).
> - **어절 중간은 어느 단계에서도 자르지 않는다.** 공백이 하나도 없는 덩어리는 자를 곳이 어절 중간뿐이므로 **여전히 폐기**한다. 결과 문장은 항상 `LINE_MAX` 이내다.
> - **살린 문장에는 `truncate`가 남아 준수율(cleanRate)의 분자에서 빠진다.** 통과시킨 것이 아니라 **못 지킨 사실을 기록한 채 문장을 살린 것**이다.
> - **상한 인상은 기각했다.** 40 → 50이면 `bubbleLifeMs`가 늘어 봇 1턴 **+550ms**, 판당 **+15.4초**다(§6.2 페이싱 예산). 계산상 손해라 버렸다.
> - 이 불변식은 §3 **P6**(절단 구제)가 기계로 감시한다.

> **07-28 — 정규화 발동을 계측한다.** `narrate()`가 `rawLen`(원문 길이)과 `norm`(`oneline`/`markup`/`truncate`/`drop`)을 함께 돌려준다. **빈 배열 = 원문 그대로 통과 = 프롬프트 준수**이므로 이 둘로 **준수율**이 계산된다(§3.4 L1 해소).
> ⚠️ **원문 텍스트는 저장하지 않는다** — 계측이 유출 경로가 되지 않게 길이와 발동 종류만 남긴다. `NormalizeResult`에 원문을 담을 필드 자체가 없다. 따라서 §3.1의 "원문과 정규화본을 둘 다 기록"은 **"원문의 길이·정규화 발동을 기록"으로 정정**한다.
> 지우는 문자 집합은 **§3 C3 판정 사전과 일치**시켰다 — 검사기가 잡는 문자를 정규화가 남기면 실호출에서 상시 FAIL이 된다. 낫표 `「」`·말줄임표·물결·가운뎃점은 **남긴다**(폴백 문안이 실제로 쓰고 C3 사전에 없다).

### 2.5 폴백 결정 트리
```
narrate(input)
├─ AI_NARRATE=off ─────────────► null   (reason: disabled · 폴백 회귀 확인용 킬 스위치)
├─ GEMINI_API_KEY 없음 ─────────► null   (reason: nokey · 기동 로그 "폴백(규칙)")
├─ 캐시 히트 ──────────────────► cached (API 호출 0)
├─ 4000ms 초과 → AbortError ───► null
├─ res.ok=false (429/5xx) ─────► null
├─ candidates 텍스트 비어 있음 ─► null   (과거 thinking 미차단 시 발생)
└─ 성공 → 정규화 → 캐시 저장 → 반환
호출부: text === null → fallbackLine(input)  ※ 대사가 비는 경로는 존재하지 않는다
```
`cacheKey` = `[action, suspect, weapon, room, persona, tone, disproved, hint]` — **진실값 조합이 키다.** LRU 200.

> **07-28 3차 — 캐시 적중률 0%는 고장이 아니라 설계가 예측하는 값이다.** 키가 진실값 조합이므로 키 공간은 용의자 12 × 장물 6 × 장소 9 × 페르소나 12 × `disproved` 2 = **15,552**이고 한 판의 발화는 **약 30건**이다 → 기대 충돌 **0.03건**. 한 판에서 캐시가 맞을 일이 원리적으로 거의 없다.
> - **적중률을 올리려면 3요소를 키에서 빼야 하는데, 그러면 캐시된 문장이 다른 제안의 라벨을 말하게 된다** — 정확히 §3 **C4**가 blocking으로 막는 위반이다. 그래서 **의도적으로 올리지 않았다.** 캐시는 "적중률 지표"가 아니라 **같은 진실값 조합이 반복될 때의 호출 절약 장치**다.
> - `GET /health`에 `cache{size, max, lookups, keyFields}`를 노출한다 — **`hits: 0`만으로는 "고장"과 "칠 일이 없었다"가 구분되지 않는다.** `lookups`(조회 시도 = 적중률의 분모)와 `keyFields`(무엇이 키인가)를 함께 내보내야 0이 설명된다.
> - 같은 이유로 `/health`에 `normalizeTiers`(절단이 **어느 단계에서** 문장을 살렸는가 · `sentence`/`clause`/`word`/`drop`)를 추가했다. 폐기율 0%가 "안 잘렸다"인지 "잘 잘랐다"인지를 숫자가 말한다.

**폴백의 설계 의도와 그 대가 (정직 항목)**: 추임새는 LLM이 죽어도 캐릭터색을 유지하기 위한 것이다. 그 결과 **폴백과 LLM 출력이 육안으로 구분되지 않는다.** 2026-07-27 라이브 실측에서 대사 5/5가 폴백이었음에도 "AI가 꺼져 있다"는 사실이 화면에 전혀 드러나지 않았다(§4.1에서 원인 규명·해결). **가용성을 위한 설계가 관측 가능성을 죽인 것이다.** → §4가 해소를 요구사항으로 규정한다.

### 3.1 실행 절차
- **입력**: 12캐릭터 × 3액션 = **36케이스**. 각 케이스의 3요소는 **시드 고정 RNG**로 뽑아 재현 가능하게 한다. 페르소나는 `cards.ts` 실값 사용(테스트 전용 문자열 금지).
- **캐시 무시**(키에 실행 nonce) — 36콜 전부 실제 API. 무료 쿼터 보호를 위해 **1회만** 실행하고 리포트를 커밋.
- **원문과 정규화본을 둘 다 기록** — 정규화가 몇 번 발동했는지가 프롬프트 준수율이다.

### 3.2 판정 규칙 5종
공통 사전: `LABELS` 한글 라벨 **27종**(용의자 12·장물 6·장소 9). 케이스별 **허용 라벨 집합 `A`** = 그 호출에 실제로 넣은 라벨들.

> `--live` 1회(36콜)를 돌리면 C7과 함께 **LLM 실출력의 C4·C5 표본이 처음 생긴다.**
> 실행 여부는 무료 쿼터를 먹으므로 **사람이 결정**한다(실행 계획 §7.2 ⑤). **[요구사항]**

**C5 ①의 기계 판정**: 27종 라벨을 부분문자열로 스캔해 `A`에 없는 것이 하나라도 나오면 FAIL(라벨·원문·케이스 id 기록).
- **왜 부분문자열로 충분한가**: 라벨 27종은 서로 부분문자열 관계가 없다(`사랑방`/`사랑채`는 어느 쪽도 다른 쪽을 포함하지 않는다).
- **오탐 후보 1건을 미리 격리**: `후원`은 장소 라벨이자 "뒷받침하다"의 일반 명사다. 자동 FAIL이 아니라 **수동 확인 큐**로 분리하고 **리포트에 그대로 인쇄**한다(예외를 조용히 두면 검사 자체가 무의미해진다).
- **금지어 사전**: `정답 / 봉투 / 손패 / 내 패 / solution / envelope / 카드를 가지고 있`.

**C4가 잡아내는 것** — 입력 `뱀 무녀 / 술동이 / 후원`에 대해
- "낄낄, 후원서 술동이를 훔쳤다니 볼만하구먼!" → **PASS**
- "낄낄, 후원서 **떡시루**를 훔쳤다니 볼만하구먼!" → `A`에 없는 장물 → **FAIL**
  = LLM이 **제안 내용을 바꿔 말한** 경우. 게임은 정상인데 **로그와 대사가 모순**되어 플레이어가 오추리한다. 표현 계층이 낼 수 있는 유일하면서 가장 치명적인 환각이며, **문서가 아니라 테스트로 막아야 하는 것**이다.

**C6(`scheme` 전용)**: `hint` 외 다른 플레이어의 손패 라벨이 등장하지 않았는지 실제 `hands` 스냅샷과 대조 → 등장 시 **즉시 blocking FAIL**(프롬프트에 없던 정보를 지어낸 순수 환각).

## 4. 관측 가능성 — **2026-07-28 구현 완료**

**문제**: `broadcast("say")`에 **그 문장이 어디서 왔는지가 없다.** 그 결과 2026-07-27 라이브 실측에서 대사 5/5가 폴백이었음에도(폴백 접미 5건 바이트 동일 · 지연 0.2~0.6초 · `temperature 0.95`에서 불가능한 반복) 화면상 아무 신호도 없었다. **심사자가 링크를 눌러 플레이하면 AI 흔적이 0이고, 이 문서의 모든 주장이 입증 불가다.**

**요구사항**
1. `narrate()` 반환을 `{ text, source: "llm"|"cache"|"fallback", ms, model }`로 확장
2. `speak()`/`helperWhisper()`가 메타를 동봉해 브로드캐스트
3. 클라: 로그 배지 `✨`/`♻`/`⚙` + **AI 카운터 칩 기본 노출**(`✨LLM 12 · ♻캐시 3 · ⚙폴백 0`). **쿼리 파라미터 게이팅 금지** — 심사자는 파라미터 없는 URL로 들어온다
4. 서버 `GET /health` → `{ ai, model, llmCalls, fallbackCalls, quotaErrors }`
5. 429 수신 시 **"AI 대사 일시 폴백" 배지** — 조용한 성능 저하가 조용한 감점이 되는 것을 막는다

**경계 확인**: 추가 필드는 전부 **운영 메타데이터**이며 게임 상태가 아니다. `GameState` 스키마는 변경되지 않는다. **진실값 경계 불변.**

#### ✅ 구현 결과 (2026-07-28)
요구사항 5개 전부 구현했다. 설계에서 바꾼 것과 그 이유:

| # | 구현 | 설계에서 바뀐 점 |
|---|---|---|
| 1 | `narrate()` → `{text, source, ms, model, reason?}` | **폴백 사유 6종을 추가**했다 — `timeout`·`http`·`empty`·`toolong`·`nokey`·`disabled`. §4.1 장애를 즉시 잡았을 조건이 "폴백이다"가 아니라 "왜 폴백인가"였다. 또 `narrate()`가 **더 이상 throw하지 않는다**: 예외로 새면 호출부 catch가 사유를 삼켜 같은 장애가 재현된다 |

**07-28 4차 정정 — 패널을 판 시작과 동시에 띄운다.** 원래는 "**측정이 하나도 없으면 패널을 띄우지 않는다**"였다. 근거는 옳았지만(빈 스냅샷으로 `0·0·0`을 그리면 서버가 하지 않은 주장을 화면이 대신한다) **첫 LLM 호출까지 27초가 걸린다** — 45초 안에 판단하는 심사자가 계측을 아예 못 보고 나갈 수 있다. 심사축 1위의 증거가 "있는데 늦게 뜨는" 상태였다.
- **자리는 띄우되 값은 말하지 않는다.** `0·0·0`은 여전히 그리지 않고, 값 자리는 확정 문안의 **`—` 관례**로만 채운다. "아직 측정이 없다"와 "0건이었다"는 다른 주장이고 화면이 후자를 말하면 안 된다.

### 4.1 실제 장애 사례 — 이 절이 요구사항인 이유 (2026-07-28 해결)

라이브에서 NPC 대사가 **100% 규칙 폴백**으로 나가고 있었고, 화면에도 로그에도 아무 신호가 없었다.

- **원인**: `generationConfig.thinkingConfig.thinkingBudget: 0`이 **`400 INVALID_ARGUMENT`**로 거부됐다. `gemini-flash-lite-latest` 별칭이 해당 파라미터를 받지 않는 세대로 이동했기 때문이다. 그 400을 `if (!res.ok) return null`이 흡수해 전 호출이 폴백으로 빠졌다.
- **키·쿼터는 정상이었다** — 모델 목록 조회 `200`, 동일 모델에 `thinkingConfig`만 빼면 `200`과 정상 대사(5/5). 즉 **운영 문제가 아니라 요청 파라미터 문제**였다.
- **왜 늦게 발견됐나**: 실패 로그가 `[narrate] HTTP 400`으로 **상태코드만** 남겨 사유가 없었다. 그리고 폴백이 §2.5의 설계대로 "캐릭터색을 유지"하므로 **육안으로 구분되지 않았다.**
- **조치**: `thinkingConfig` 제거 + 실패 로그에 응답 본문 앞부분 포함. 배포 후 라이브 재검증 **12/12 LLM · 폴백 0건**.

이 사건이 §4의 5개 요구사항을 정당화한다. **가용성을 위한 폴백은 관측 가능성을 갖추지 않으면 장애를 숨기는 장치가 된다.** `source`/`ms` 계측과 AI 카운터 칩이 있었다면 첫 판에서 드러났을 문제다.

**운영 선행 조건(사람 담당)**: 무료 쿼터는 심사 기간 내내 다수 심사자가 소모하는 구조이므로, 심사 기간에는 쿼터 잔량을 주기적으로 확인한다 — **`GET /health`가 구현돼(위 표 #4) `llmCalls`·`fallbackCalls`·`quotaErrors`를 서버 로그 없이 확인할 수 있다.**

- **키 관리**: `apps/server/.env`만 사용, gitignore. `.env.example`은 키 이름·발급 URL·모델 기본값만. 클라 번들·로그·커밋 어디에도 키가 없다
- **스트리밍 미사용** — 64토큰 단문에 스트리밍은 오버헤드

## 6. 사람다운 템포 (엔진 규약)
- **NPC 딜레이 = 사용자 평균 턴 시간의 절반.** `clamp(avg/2, 800, 1600)`, 데이터 없으면 3000
- EMA `avg = avg×0.6 + dur×0.4`, **사람 턴만 표본에 넣는다**(봇 턴을 섞으면 봇이 자기 속도를 자기가 정하는 되먹임이 생긴다)
- 턴 내 2박자: 이동 → `BOT_ACT_GAP` 600 → 제안 → **대사 길이에 비례한 홀드**. 타이핑 중 턴을 넘기면 카메라가 튄다

### 6.1 07-28 정정 — 고정 `SPEAK_HOLD`는 폐기됐다
초판은 `SPEAK_HOLD` **2400 고정**이었다. 그런데 클라 말풍선 수명은 `bubbleLifeMs(text) = max(1800, 글자수×55 + 2600)`이라
**모든 대사에서 서버가 먼저 턴을 넘겼다** — 40자 대사면 4800 대 2400으로 2배 어긋난다. 위 "타이핑 중 턴을 넘기면 카메라가 튄다"는
경고를 문서가 적어두고 **코드가 100% 위반**하고 있었던 셈이다.

조치: `SPEAK_HOLD` 상수를 삭제하고 `speak()`가 실제 방송한 문장을 반환하게 바꿔, 문장이 도착한 뒤 `bubbleLifeMs(line)`으로 타이머를 건다.
`bubbleLifeMs`는 `packages/shared`에 DOM 의존 없이 두어 **서버·클라가 같은 함수를 쓴다**(정합을 문서가 아니라 코드로 보증).

**대가**: 봇 1턴이 실측 7.6초가 되어 `BOT_ACT_GAP` 1300→600으로 번 시간을 정합 비용이 그대로 상쇄했다.
`npcDelay` 상한을 7000→1600으로 낮춰도 솔로 1판이 4.4~5.7분이었다.

### 6.2 07-28 후속 — 남은 레버는 대사 길이였다 (해소)
문서가 **"12~40자"를 규약으로 명시**해놓고 폴백 제안 대사가 **평균 47자**였다. 규약을 어긴 것은 프롬프트가 아니라 우리가 쓴 템플릿이었다.

- 홀드 타이머를 거는 것은 **제안 대사뿐**이다(고발·계략은 즉시 다음 동작으로 간다). 그래서 제안만 25자 예산으로 조이고 고발·계략은 규약 상한 40자까지 열어 **클라이맥스 대사의 캐릭터색을 지켰다.**
  제안 **47.1자 → 21.3자**(최대 71 → 25). 추임새는 "길면 통째로 버린다"가 아니라 예산 안에서 들어가는 만큼 붙인다(부착률 88.6%).
- `BUBBLE_HOLD_MS` **2600 → 1200.** 2600은 뷰별 인라인 리터럴을 옮겨 적은 값이라 유도 근거가 없었다. 한국어 읽기 속도 12자/초에서 타자기가 이미 소비하는 몫을 빼면 `(83−55)×40 = 1120` → 1200. `TYPE_MS 55`는 **AI 활용의 유일한 가시적 증거**라 불변.
- **결과: 봇 1턴 7.6초 → 3.8초**(실측 80표본 평균 3,784ms, 계산식과 11ms 오차).

⚠️ **남은 간극**: LLM이 켜져 있으면 Gemini 왕복이 홀드 **앞에** 붙어 봇 1턴이 늘어난다. 대사 길이가 아니라 `narrate()`를 await한 뒤 방송하는 **구조 비용**이다.

> **2026-07-28 계측 정정 2건.** 위 문장은 원래 "왕복 ~1.2초이며 **캐시 히트 시엔 사라진다**"고 적었다. 계측을 붙여 재보니 둘 다 틀렸다.
> - 왕복 실측 **평균 926ms**(756~1194ms) — 1.2초보다 낮다.
> - 🔴 **캐시 히트 0건 / 24발화.** `cacheKey`가 제안 3요소 + `disproved` 조합이라 한 판에서 같은 조합이 거의 재현되지 않는다. **완충 논리가 실제로는 발동하지 않으므로 왕복은 상시 비용이다.** → **07-28 3차 후속**: 이것은 고장이 아니라 **키 공간 15,552 대 판당 발화 30**이 예측하는 값이며, 올리려면 C4를 깨야 하므로 **의도적으로 올리지 않기로 확정**했다(§2.5).
> - 🟠 함께 드러난 것: **LLM 응답의 17%(4/24)가 40자를 넘겨 폐기**됐고, 살아남은 문장도 31~39자로 제안 예산 25자를 크게 넘었다. **페이싱의 실질 레버는 왕복보다 출력 길이 강제일 수 있다.** → **07-28 3차에 그 레버를 당겼다**: 목표 길이 인하 + 3단 절단으로 폐기 **22% → 0%**, 최대 원문 50 → **34자**(§2.3). 상한을 40 → 50으로 올리는 반대 방향은 **봇 1턴 +550ms · 판당 +15.4초**라 기각했다.
>
> 해법 후보는 "폴백 먼저 방송 → LLM 도착 시 교체" 또는 다음 턴 대사 선(先)생성인데, 07-28 라운드에서 **의도적으로 착수하지 않았다**:
> 홀드 기점을 LLM 도착 시각으로 옮기면 총 턴시간은 그대로이고, 폴백 방송 시각에 고정하면 **LLM 문장의 화면 노출 시간이 그만큼 깎인다** — LLM 문장이 곧 AI의 가시적 증거인데 그것을 줄이는 거래다. 선생성은 `disproved`가 `doSuggestion` 이후에야 정해져 **규칙 엔진 결정을 앞당기거나 이벤트당 2콜**이 필요하다. [요구사항 — 결정 필요]

- **[요구사항→해소]** 다인 플레이에서 `avg`가 **모든 사람의 단일 EMA**라 가장 느린 한 명이 모두의 봇 딜레이를 끌어올리던 문제는 `avg/(2×humans)`로 해석해 해소했다(사람 1명이면 기존과 동일).

§7 서두의 «커미터 1명»은 **git 아티팩트**다(커밋 계정 1개). 실제 디렉팅은 **여러 팀원이 각자 디스코드 채널로 에이전트에 실시간 지시**하는 다인 루프다 — 「누가 무엇을 지시했는가」는 **브랜치 분리 + 디스코드 로그**로 추적된다.

- **다인 디스코드 루프**: 팀원이 디스코드 채널로 요청(스펙·에셋 첨부) → 에이전트가 구현·검증(`typecheck`·build·화면게이트)·배포 → **진행도·캡처·URL을 디스코드로 회신** → 사람이 화면을 보고 다음 지시. LLM은 진실값을 만들지 않는다는 경계(§0)는 이 루프에서도 동일하게 적용된다.
- **브랜치별 워크트리 격리**: 팀원마다 **전용 브랜치 + 독립 git worktree**(`zodiac-clue-<브랜치>/`). 한 팀원의 작업이 다른 팀원·`main`과 섞이지 않고, 워크트리라 브랜치 전환 없이 동시 진행된다. 에이전트는 **지시받은 브랜치 밖으로 나가지 않는다.**
- **브랜치별 프리뷰 URL**: 각 팀원 브랜치를 Vercel 프리뷰로 배포하고 **브랜치 서브도메인 별칭**(`…-<브랜치>.vercel.app`)을 걸어 **프로덕션과 분리된 화면**에서 자기 지시 결과를 즉시 확인한다. 오너 지시로 검증·정렬한 뒤에야 `main`→prod.
- **검증은 브랜치에서도 유지**: 브랜치 작업도 `pnpm -r typecheck` · client build · 화면게이트(S1~S8)를 통과해야 커밋한다. 회귀 게이트(§7.1)는 브랜치·`main` 공통이다.

**사람 검토 지점**: 브랜치 권한 부여 · `main` 병합 · 프로덕션 배포 승인은 전부 **오너(사람) 결정**이다. 에이전트는 병합·배포를 스스로 결정하지 않는다(§7.2와 같은 원칙 — «무엇을 맡기지 않았는가»).

## 8. 본행사 계승 — 자유 심문 · 거짓말/뇌물 축

07-18 회의에서 확정한 차별점 중 **자유 심문(자연어 질의) · 정직|뇌물(거짓말) 축**은 사전과제 빌드에 **구현되지 않았다.** 숨기지 않고, 왜 미루었고 어떻게 얹을지를 명시한다.

### 8.1 왜 사전과제에서 하지 않았나
1. **자유 심문은 진실값 경계를 LLM 쪽으로 옮긴다.** 자연어 질의를 규칙에 비추어 판정하려면 **판정 결과가 LLM 출력에 의존**하게 된다. **경계를 먼저 세우고 검증 프로토콜을 갖춘 뒤**에 넘어가야 할 순서지, 반대가 아니다.
2. **검증 없는 기능 추가는 감점 요인이다.** D-14에 새 축을 넣으면 §3의 검사 5종을 전부 새로 설계해야 하고 실행할 시간이 없다. **검증할 수 없는 기능은 넣지 않는다**가 이 프로젝트의 규칙이다.
3. **무료티어 모델이 깨진다.** 현재는 "이벤트당 1콜 + 캐시"라 상한이 있다. 자유 심문은 **사용자 입력당 1콜**이며 자연어라 캐시도 듣지 않는다.

### 8.2 본행사에서 어떻게 얹는가 — 3단 파이프라인
**경계를 옮기는 게 아니라, LLM을 경계의 양쪽 끝에 두 번 쓴다.**
```
사용자 자연어 "너 어제 후원에 있었지?"
 ├─① 질의 정규화 (LLM · 표현→구조)
 │    출력은 자연어가 아니라 고정 스키마 슬롯:
 │    { target, category: suspect|weapon|room, value: <27 라벨 중 하나> | null }
 │    ▸ 스키마·사전 밖 값은 즉시 폐기 → "무슨 말인지 모르겠소" 폴백
 │    ▸ LLM이 여기서 낼 수 있는 최악은 "질문을 잘못 알아듣는 것"이지 게임 상태 변경이 아니다
 ├─② 판정 (규칙엔진 · LLM 없음)
 │    슬롯을 hands/solution에 대조 → truth. 정직/거짓 상태와 뇌물 자원도 규칙엔진이 결정.
 │    ▸ 거짓을 말하기로 정해지면 **거짓 답변의 내용까지 규칙엔진이 후보에서 고른다.**
 │      LLM이 거짓 내용을 창작하면 그 거짓은 환각과 구분할 수 없고 §3의 C4·C5가 원리적으로 작동하지 않는다
 └─③ 표현 (LLM · 현재 narrate() 확장)
      { persona, tone, answer: 확정된 답변값, deceptive } — deceptive면 "확신에 찬 태도" 연기 지시만 추가
```
**검증 확장**: C8 슬롯 스키마 준수 100% / C9 정직 지시 시 진실 일치 100% / **C10 거짓 지시 시 규칙엔진이 지정한 값 외 등장 0건(blocking)** / C11 뇌물 자원 정합 100%.

**얻는 것**: 자유 심문은 "규칙 하드코딩이 불가능 → LLM만 가능"한 영역이라 상류가 요구한 load-bearing 조건을 **표현 계층 바깥에서도** 충족한다. 동시에 **판정은 여전히 규칙엔진에만 있다.** 사전과제의 경계를 버리는 게 아니라, **그 경계를 지킨 채로 LLM의 책임 범위를 넓히는 것**이 본행사 스코프다.
