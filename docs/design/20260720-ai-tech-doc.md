## 0. 핵심 원칙 — 이중 계층: 결정론적 진실 계층 + LLM 표현 계층

이 게임은 **AI를 두 층으로 나눠 쓴다.** 한 층은 게임이 성립하기 위해 반드시 있어야 하고(load-bearing), 다른 한 층은 그 결정을 사람이 읽을 수 있는 말로 바꾼다.

| 층 | 담당 | 구현 | AI 종류 | 없으면 |
|---|---|---|---|---|
| **진실 계층** | 정답 봉투·카드 분배·반증·고발 판정 | `apps/server/src/rooms/clue-room.ts` | 없음(순수 규칙) | 게임이 성립 안 함 |
| **에이전트 계층** | 빈 좌석을 채우는 NPC의 **추리·의사결정** | `clue-room.ts` `runBotTurn` / `botSuggestPhase` / `initBotKnowledge` | **결정론적 추론 엔진** | **게임이 성립 안 함** — 심사자가 혼자 접속하면 상대가 0명 |
| **표현 계층** | NPC 대사·연출 | `apps/server/src/ai/narrator.ts` | **LLM (Gemini)** | 게임은 굴러가나 **캐릭터가 사라진다** |

### 0.1 무엇이 load-bearing인가
상류 정의(`docs/planning/brainstorming/20260714-game-ideas.md`)는 **"AI 없으면 게임이 성립 안 되는 설계"**를 요구한다. 이 프로젝트에서 그 조건을 지는 것은 **에이전트 계층**이다.
- 07-18 회의에서 **"심사자는 링크를 눌러 혼자 플레이한다"**는 제약이 확정됐다. 클루는 3~6인 불완전정보 게임이라 **상대가 없으면 규칙 자체가 작동하지 않는다.**
- `addBot()`이 빈 좌석을 십이지 캐릭터로 채우고, 각 봇은 **자기만의 지식 상태**(후보집합)로 소거 추리를 수행한다. 이 층을 빼면 1인 게임이 되어 **제출물 ①(플레이 가능한 빌드) 요건 자체가 무너진다** → load-bearing.
- 표현 계층(LLM)은 load-bearing이 아니다. **그렇게 설계했다.** 이유는 §0.2.

**초판이 틀린 지점**: 초판은 "load-bearing AI = 표현 전용"이라 썼다. 상류 용어를 뒤집어 쓴 것이며, 같은 문서의 "LLM 장애와 무관하게 게임은 정상"과 자기모순이었다. §0.3에서 정정한다.

### 0.2 왜 판정에서 LLM을 배제했는가 — 설계 판단 4근거
1. **환각이 곧 규칙 위반이 된다.** 반증은 "내 카드 중 제안 3장과 일치하는 것"이라는 전칭 판정이다. LLM이 이를 하면 없는 카드로 반증(위양성)하거나 가진 카드를 놓치는(위음성) 순간 **정답이 도달 불가능해진다.** 게임이 "틀리는" 게 아니라 **끝나지 않는다.**
2. **재현성이 없으면 검증도 없다.** `temperature 0.95` 생성기는 같은 입력에 같은 출력을 주지 않는다. 판정이 여기 걸리면 버그 재현이 불가능하고 밸런스 시뮬레이션(1만 판)도 원리적으로 못 돌린다. 진실값을 규칙 함수로 고정했기에 **판을 오프라인에서 1만 번 재생할 수 있다.**
3. **치트 불가능성은 "안 준다"로만 증명된다.** `this.solution`은 `private`이고 `GameState` 스키마에 없어 **동기화 자체가 안 된다.** 손패도 서버 전용 Map에 두고 해당 클라에게만 전송한다. LLM 프롬프트에도 넣지 않는다(예외 1건은 §2.2). **"정답을 알려주고 말하지 말라고 지시"하는 방식은 인젝션 한 번에 무너지지만, 주지 않은 정보는 새어나갈 수 없다.**
4. **무료티어에서 판정은 못 산다.** 판정을 LLM에 걸면 호출이 행동에 비례해 폭증하고 429 한 번에 **게임이 멈춘다.** 표현에만 걸면 429는 **말투가 단조로워지는 것으로 끝난다.**

> **LLM을 표현에 가둔 것은 능력 부족의 인정이 아니라, 검증 가능성과 가용성을 사기 위해 지불한 설계 비용이다.** 그래서 본 문서의 본론은 "AI를 어떻게 게임에 넣었나"가 아니라 **"AI를 어떻게 지휘·검수했나"**(§2·§3·§7)다.

## 1. 계층 구조 (실측 파일 맵)

### 1.1 진실 계층 — 규칙엔진 (`clue-room.ts`, 1030줄)
전부 결정론 함수. LLM 호출 0.
- **정답 봉투**: 용의자·장물·장소 각 1 → `this.solution`(private, 스키마 밖)
- **덱 18장**: 참여 캐릭터 6−1=5 · 장물 6−1=5 · 장소 9−1=8. 전부 비정답
- **솔로 완화**: 사람 1명이면 딜 전 2장을 `commonCards`로 공개(정답 아님)
- **이동**: 2d6 · `canCross()`(방↔방 직접 이동 불가, 입구 1칸으로만) · 비밀 통로 3쌍
- **제안**: 용의자·장물 토큰을 방 `summon` 앵커로 소환 → 시계방향 첫 매치 1장 반증
- **고발**: 3필드 완전 일치만 승리, 불일치면 `eliminated = true`(반증만 가능)
- **비밀 격리**: `solution`·`hands`·`botKnowledge` 전부 private. `GameState`에 없음

### 1.2 에이전트 계층 — NPC 추리
각 봇은 후보집합 3개를 들고 자기 손패와 자기 제안의 반증 결과를 소거한다. 턴은 2박자: 이동 → `BOT_ACT_GAP` 1300ms → 제안 → `SPEAK_HOLD` 2400ms → 판단.

**알려진 결함 2건 (현재 코드 그대로. 은폐하지 않는다.)**
- **(a) 봇 간 정보 공유** — `private revealed`는 룸 전역이며 반증으로 드러난 카드가 **모든 봇**의 소거에 쓰인다. 사람은 자기에게 보인 카드만 안다.
  → **조치**: 봇별 `seen`으로 분리. 수렴은 **공개 정보만 쓰는 추론**("패스한 사람은 그 3장을 안 가짐")으로 대체 — 사람도 로그로 도달 가능하므로 비대칭이 아니다. 근거: `20260727-improvement-roadmap.md` §1.1·§7.5
- **(b) 봇은 수학적으로 오답 고발이 불가능하다** — 소거에서 빼는 값이 전부 비정답이라 정답은 항상 후보에 남는다. **봇 탈락 판 0.0%**, 탈락 리스크는 사람만 진다.
  → **조치**: `BOT_NERVE[suspect]` 페르소나 상수 + **시드 RNG**로 후보가 좁혀졌을 때 확률적 도박 고발. 시드 고정이므로 **결정론·재현성 유지**(§0.2-2 위배 없음). 호랑이 대감은 성급히 고발하고 양 목동은 안 한다 → **페르소나가 대사뿐 아니라 의사결정에도 반영된다.** [요구사항]

### 1.3 표현 계층 — LLM (`ai/narrator.ts`, 175줄)
`narrate()` 하나가 전부. 실패하면 `null`을 돌려주고 호출부가 `fallbackLine()`으로 대체한다. 호출 지점 4곳, 액션 3종.

## 2. 디렉팅 명세 (Directing Spec)

### 2.1 입력 계약 — 규칙엔진이 이미 확정한 필드만
**모든 필드는 결정이 끝난 값이다. LLM은 결정에 참여하지 않는다.**

| 필드 | 출처(누가 확정했나) |
|---|---|
| `name` | `label(suspect)` |
| `action` | 규칙엔진의 턴 판단 (`suggest`/`accuse`/`scheme`) |
| `suspect`/`weapon`/`room` | `botSuggestPhase`가 후보집합에서 확정한 한글 라벨 |
| `hint` | `peek` 결과 카드 라벨. **`scheme` 전용** (§2.2) |
| `persona`/`tone` | `PERSONA`/`VOICE[*].tone` 상수 |
| `intro`/`outro` | `VOICE` 추임새. **폴백 전용**(LLM 경로 미사용) |
| `disproved` | `doSuggestion()`의 반환값 |

호출 지점: `speak()` ← ①제안 ②미반증 즉시 고발 ③후보 수렴 고발 / `helperWhisper()` ← ④계략 귓속말. `speak()`가 화자의 `suspect`로 말투를 자동 주입하므로 콜사이트는 말투를 몰라도 된다.

### 2.2 절대 넘기지 않는 값

| 값 | LLM 전달 | 근거 |
|---|---|---|
| **정답 봉투** `solution` | **없음(전 경로)** | 입력 타입에 대응 필드 자체가 없다 |
| 임의 플레이어의 손패 `hands` | **없음** | 동일 |
| 봇 후보집합 `botKnowledge` | **없음** | "무엇을 아직 모르는지"는 표현에 불필요 |
| `revealed` 전역 집합 | **없음** | 봇의 내부 지식이지 대사 소재가 아님 |
| 이전 대사 히스토리 | **없음** | 대화 문맥 없음 = **인젝션 표면 0** |

**단 하나의 예외 — `scheme`의 `hint`.** 계략 사용자에게 규칙엔진이 **이미 공개하기로 결정한** 카드(모서리 2장/그 외 1장)의 라벨이 LLM에 전달된다. 경계 위반이 아닌 이유:
1. **결정은 이미 끝났다** — 어떤 카드를 볼지는 규칙엔진의 셔플이 정한다. LLM은 고르지 않는다.
2. **수신자가 이미 아는 정보다** — 같은 카드가 `peek` 메시지로 평문 전달된 뒤에 대사가 나간다.
3. **출력이 봉인된다** — LLM 문장은 **당사자에게만** 가고 나머지 전원에게는 **`"(귓속말)"`만** 브로드캐스트된다. 흘려도 **도달 대상은 이미 그 정보를 가진 1명뿐**이다.
4. 그 카드들은 **정의상 전부 비정답**이다(덱은 정답 3장을 제외하고 구성된다).

### 2.3 출력 계약
**systemInstruction 요지**: 사극풍 NPC. "결정된 행동"을 **대사 한 문장으로만** 변환. 머리말/설명/선택지/마크다운/따옴표 전부 금지, **12~40자**, **정답이나 남의 손패를 아는 척 금지, 주어진 정보만 사용.**

**생성 파라미터** — `temperature 0.95` · `maxOutputTokens 64` · `thinkingConfig.thinkingBudget 0` · `AbortController` 4000ms.
`thinkingBudget:0`은 선택이 아니라 필수다 — flash 계열은 thinking 모델이라 끄지 않으면 **생각 토큰이 64 예산을 전부 먹고 빈 응답**이 온다(실제로 겪은 결함, `docs/logs/20260720-npc-llm-persona.md`).

**사후 정규화** — 프롬프트를 신뢰하지 않고 코드로 강제: ① 첫 줄만 ② 앞뒤 따옴표·별표 제거 ③ 80자 하드컷.

**알려진 간극 (정직하게 기재)**

| 간극 | 내용 | 판단 |
|---|---|---|
| 길이 상한 불일치 | 프롬프트 "12~40자" vs 코드 상한 **80자**. 41~80자는 통과 | 의도적 여유(40자 하드컷은 문장을 중간에서 자른다). §3 C2가 분포를 계측 |
| 마크업 제거가 양끝 한정 | 문장 **중간**의 `**`·`_`는 남는다 | §3 C3 계측 후 결정 [요구사항] |
| 최소 길이 미강제 | 12자 미만 가드 없음 | 말풍선 최소 수명으로 완화 [요구사항] |
| 조사 미처리 | **폴백 경로**에 종성 판정이 없어 `"떡시루이 사라졌던걸"` 발생(실측) | 조사 헬퍼 15줄 [요구사항 · P0] |
| 재현성 | `temperature 0.95`라 LLM 출력은 매번 다르다. 캐시 히트 시에만 동일 | 표현 계층이므로 허용. **진실값은 캐시와 무관하게 동일**하다는 것이 §3 C4의 검사 대상 |

### 2.4 페르소나 12종 — `packages/shared/src/cards.ts` (단일 소스)
동일 상수가 **랜딩 성격 도감 · LLM 프롬프트 · 폴백 추임새 3곳에 공용**으로 쓰인다. 캐릭터가 세 화면에서 갈라지지 않는다.

| id | 라벨 | 직업 뜻풀이 | 성격 | 말투(→LLM) | 추임새(→폴백) |

### 2.5 폴백 결정 트리
```
narrate(input)
├─ GEMINI_API_KEY 없음 ─────────► null   (기동 로그 "폴백(규칙)")
├─ 캐시 히트 ──────────────────► cached (API 호출 0)
├─ 4000ms 초과 → AbortError ───► null
├─ res.ok=false (429/5xx) ─────► null
├─ candidates 텍스트 비어 있음 ─► null   (thinkingBudget 미차단 시 발생)
└─ 성공 → 정규화 → 캐시 저장 → 반환
호출부: text === null → fallbackLine(input)  ※ 대사가 비는 경로는 존재하지 않는다
```
`cacheKey` = `[action, suspect, weapon, room, persona, tone, disproved, hint]` — **진실값 조합이 키다.** LRU 200.

**폴백의 설계 의도와 그 대가 (정직 항목)**: 추임새는 LLM이 죽어도 캐릭터색을 유지하기 위한 것이다. 그 결과 **폴백과 LLM 출력이 육안으로 구분되지 않는다.** 2026-07-27 라이브 실측에서 대사 5/5가 폴백이었음에도 "AI가 꺼져 있다"는 사실이 화면에 전혀 드러나지 않았다. **가용성을 위한 설계가 관측 가능성을 죽인 것이다.** → §4가 해소를 요구사항으로 규정한다.

### 2.6 4뷰 공통 전달 계약 — 표현 계층은 렌더러에 독립이다
서버는 렌더러를 모른다. `broadcast("say", { id, from, text })` 하나만 내보내고 **4개 뷰가 전부 동일한 `showBubble(id, text)` 시그니처**를 구현한다(뷰1 `game-scene.ts` / 뷰2·3 `iso-view.ts` 공용 / 뷰4 `pixel-scene.ts`). 라우팅은 `main.ts` 한 곳뿐.
- `id`는 플레이어 세션 id 또는 십이지 값(고정 헬퍼)이며 4뷰가 동일한 폴백 순서로 해석한다 → 계략 귓속말이 헬퍼 토큰 위에 뜨는 동작이 뷰를 바꿔도 유지된다.
- **의미**: 결정/표현 분리가 서버에서 끝나지 않고 **렌더 계층까지 관통한다.** 뷰5를 붙여도 표현 계층은 손대지 않는다. 반대로 뷰를 4개나 만들 수 있었던 것은 표현 계층이 렌더러를 모르기 때문이다.

**알려진 간극**: 타자기 효과가 뷰1·2·3은 `TYPE_MS 55`인데 **뷰4는 없고** 유지 시간도 2600 vs **3200 인라인**이다. → 상수를 `packages/shared/src/view-consts.ts`로 승격해 4뷰+서버가 같은 값을 보게 하고, 서버 `SPEAK_HOLD`(2400)와 말풍선 수명의 정합을 한 곳에서 계산한다(어긋나면 **봇이 말하는 도중 턴이 넘어가 카메라가 튄다**). 설계: `20260727-view-contract-spec.md` [요구사항]

## 3. 환각 검증 프로토콜

> **"LLM이 진실값을 바꾸지 않았는가"를 사람 눈이 아니라 기계로 판정한다.**
> 실행체: `scripts/eval-narrator.mjs` [요구사항 · 미구현] → `docs/design/eval-narrator-report.md` 자동 생성

### 3.1 실행 절차
- **입력**: 12캐릭터 × 3액션 = **36케이스**. 각 케이스의 3요소는 **시드 고정 RNG**로 뽑아 재현 가능하게 한다. 페르소나는 `cards.ts` 실값 사용(테스트 전용 문자열 금지).
- **캐시 무시**(키에 실행 nonce) — 36콜 전부 실제 API. 무료 쿼터 보호를 위해 **1회만** 실행하고 리포트를 커밋.
- **원문과 정규화본을 둘 다 기록** — 정규화가 몇 번 발동했는지가 프롬프트 준수율이다.

### 3.2 판정 규칙 5종
공통 사전: `LABELS` 한글 라벨 **27종**(용의자 12·장물 6·장소 9). 케이스별 **허용 라벨 집합 `A`** = 그 호출에 실제로 넣은 라벨들.

| # | 검사 | 기계 판정 | 통과 기준 |
|---|---|---|---|
| **C1** | 한 줄 | 개행 미포함 | **36/36** |
| **C2** | 길이 | 원문 `12 ≤ len ≤ 40` / 정규화본 `≤ 80` | 원문 **≥33/36** · 정규화본 **36/36** |
| **C3** | 마크업·머리말 | 따옴표·별표·해시·`NPC:`·리스트 머리 전부 미매치 | **36/36** |
| **C4** | **진실값 치환 없음** | ① `A`의 라벨 최소 1개 포함 ② `A`에 없는 라벨 중 **같은 카테고리**의 것이 0개 | **36/36 — blocking** |
| **C5** | **미제공 카드·금지어 누출** | ① 27종 스캔 결과 ∖ `A` = ∅ ② 금지어 사전 미매치 | **36/36 — blocking** |

**C5 ①의 기계 판정**: 27종 라벨을 부분문자열로 스캔해 `A`에 없는 것이 하나라도 나오면 FAIL(라벨·원문·케이스 id 기록).
- **왜 부분문자열로 충분한가**: 라벨 27종은 서로 부분문자열 관계가 없다(`사랑방`/`사랑채`는 어느 쪽도 다른 쪽을 포함하지 않는다).
- **오탐 후보 1건을 미리 격리**: `후원`은 장소 라벨이자 "뒷받침하다"의 일반 명사다. 자동 FAIL이 아니라 **수동 확인 큐**로 분리하고 **리포트에 그대로 인쇄**한다(예외를 조용히 두면 검사 자체가 무의미해진다).
- **금지어 사전**: `정답 / 봉투 / 손패 / 내 패 / solution / envelope / 카드를 가지고 있`.

**C4가 잡아내는 것** — 입력 `뱀 무녀 / 술동이 / 후원`에 대해
- "낄낄, 후원서 술동이를 훔쳤다니 볼만하구먼!" → **PASS**
- "낄낄, 후원서 **떡시루**를 훔쳤다니 볼만하구먼!" → `A`에 없는 장물 → **FAIL**
  = LLM이 **제안 내용을 바꿔 말한** 경우. 게임은 정상인데 **로그와 대사가 모순**되어 플레이어가 오추리한다. 표현 계층이 낼 수 있는 유일하면서 가장 치명적인 환각이며, **문서가 아니라 테스트로 막아야 하는 것**이다.

**C6(`scheme` 전용)**: `hint` 외 다른 플레이어의 손패 라벨이 등장하지 않았는지 실제 `hands` 스냅샷과 대조 → 등장 시 **즉시 blocking FAIL**(프롬프트에 없던 정보를 지어낸 순수 환각).

## 4. 관측 가능성 — 요구사항 [P0 · 미구현]

**문제**: `broadcast("say")`에 **그 문장이 어디서 왔는지가 없다.** 그 결과 2026-07-27 라이브 실측에서 대사 5/5가 폴백이었음에도(폴백 접미 5건 바이트 동일 · 지연 0.2~0.6초 · `temperature 0.95`에서 불가능한 반복) 화면상 아무 신호도 없었다. **심사자가 링크를 눌러 플레이하면 AI 흔적이 0이고, 이 문서의 모든 주장이 입증 불가다.**

**요구사항**
1. `narrate()` 반환을 `{ text, source: "llm"|"cache"|"fallback", ms, model }`로 확장
2. `speak()`/`helperWhisper()`가 메타를 동봉해 브로드캐스트
3. 클라: 로그 배지 `✨`/`♻`/`⚙` + **AI 카운터 칩 기본 노출**(`✨LLM 12 · ♻캐시 3 · ⚙폴백 0`). **쿼리 파라미터 게이팅 금지** — 심사자는 파라미터 없는 URL로 들어온다
4. 서버 `GET /health` → `{ ai, model, llmCalls, fallbackCalls, quotaErrors }`
5. 429 수신 시 **"AI 대사 일시 폴백" 배지** — 조용한 성능 저하가 조용한 감점이 되는 것을 막는다

**경계 확인**: 추가 필드는 전부 **운영 메타데이터**이며 게임 상태가 아니다. `GameState` 스키마는 변경되지 않는다. **진실값 경계 불변.**

**운영 선행 조건(사람 담당)**: OCI 호스트의 `GEMINI_API_KEY` 확인. 기동 로그가 이미 `NPC 대사: Gemini ON | 폴백(규칙)`을 찍는다. 무료 쿼터는 심사 기간 내내 다수 심사자가 소모하는 구조이므로 **키를 켜는 것만으로는 부족하다.**

## 6. 사람다운 템포 (엔진 규약)
- **NPC 딜레이 = 사용자 평균 턴 시간의 절반.** `clamp(avg/2, 1800, 7000)`, 데이터 없으면 3000
- EMA `avg = avg×0.6 + dur×0.4`, **사람 턴만 표본에 넣는다**(봇 턴을 섞으면 봇이 자기 속도를 자기가 정하는 되먹임이 생긴다)
- 턴 내 2박자: 이동 → `BOT_ACT_GAP` 1300 → 제안 → `SPEAK_HOLD` 2400. 타이핑 중 턴을 넘기면 카메라가 튄다
- **[요구사항]** 규칙 개선 후 판이 3.1→6.8라운드로 길어지므로 `BOT_ACT_GAP` 1300→600, `npcDelay` 상한 7000→1600. 근거: 로드맵 §7.5.4
- **[요구사항]** 다인 플레이에서는 `avg`가 **모든 사람의 단일 EMA**라 가장 느린 한 명이 모두의 봇 딜레이를 끌어올린다 → 사람 수로 나누는 해석 필요(로드맵 §8.2)

## 8. 본행사 계승 — 자유 심문 · 거짓말/뇌물 축

07-18 회의에서 확정한 차별점 중 **자유 심문(자연어 질의) · 정직|뇌물(거짓말) 축**은 사전과제 빌드에 **구현되지 않았다.** 숨기지 않고, 왜 미루었고 어떻게 얹을지를 명시한다.

### 8.1 왜 사전과제에서 하지 않았나
1. **자유 심문은 진실값 경계를 LLM 쪽으로 옮긴다.** 자연어 질의를 규칙에 비추어 판정하려면 **판정 결과가 LLM 출력에 의존**하게 된다. **경계를 먼저 세우고 검증 프로토콜을 갖춘 뒤**에 넘어가야 할 순서지, 반대가 아니다.
2. **검증 없는 기능 추가는 감점 요인이다.** D-14에 새 축을 넣으면 §3의 검사 5종을 전부 새로 설계해야 하고 실행할 시간이 없다. **검증할 수 없는 기능은 넣지 않는다**가 이 프로젝트의 규칙이다.
3. **무료티어 모델이 깨진다.** 현재는 "이벤트당 1콜 + 캐시"라 상한이 있다. 자유 심문은 **사용자 입력당 1콜**이며 자연어라 캐시도 듣지 않는다.

### 8.2 본행사에서 어떻게 얹는가 — 3단 파이프라인
**경계를 옮기는 게 아니라, LLM을 경계의 양쪽 끝에 두 번 쓴다.**
```
사용자 자연어 "너 어제 후원에 있었지?"
 ├─① 질의 정규화 (LLM · 표현→구조)
 │    출력은 자연어가 아니라 고정 스키마 슬롯:
 │    { target, category: suspect|weapon|room, value: <27 라벨 중 하나> | null }
 │    ▸ 스키마·사전 밖 값은 즉시 폐기 → "무슨 말인지 모르겠소" 폴백
 │    ▸ LLM이 여기서 낼 수 있는 최악은 "질문을 잘못 알아듣는 것"이지 게임 상태 변경이 아니다
 ├─② 판정 (규칙엔진 · LLM 없음)
 │    슬롯을 hands/solution에 대조 → truth. 정직/거짓 상태와 뇌물 자원도 규칙엔진이 결정.
 │    ▸ 거짓을 말하기로 정해지면 **거짓 답변의 내용까지 규칙엔진이 후보에서 고른다.**
 │      LLM이 거짓 내용을 창작하면 그 거짓은 환각과 구분할 수 없고 §3의 C4·C5가 원리적으로 작동하지 않는다
 └─③ 표현 (LLM · 현재 narrate() 확장)
      { persona, tone, answer: 확정된 답변값, deceptive } — deceptive면 "확신에 찬 태도" 연기 지시만 추가
```
**검증 확장**: C8 슬롯 스키마 준수 100% / C9 정직 지시 시 진실 일치 100% / **C10 거짓 지시 시 규칙엔진이 지정한 값 외 등장 0건(blocking)** / C11 뇌물 자원 정합 100%.

**얻는 것**: 자유 심문은 "규칙 하드코딩이 불가능 → LLM만 가능"한 영역이라 상류가 요구한 load-bearing 조건을 **표현 계층 바깥에서도** 충족한다. 동시에 **판정은 여전히 규칙엔진에만 있다.** 사전과제의 경계를 버리는 게 아니라, **그 경계를 지킨 채로 LLM의 책임 범위를 넓히는 것**이 본행사 스코프다.
