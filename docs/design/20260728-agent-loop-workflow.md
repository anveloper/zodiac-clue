# 에이전트 루프 워크플로 — 다관점 병렬 검수·생산

> 작성 2026-07-28 · 사람용 `.html` 동봉 · 2026-07-27 6라운드(에이전트 18개) 실행 경험을 규약화.
> `CLAUDE.md`/`AGENTS.md`의 plans 워크플로 **위에서 도는 상위 절차**다. 문서 규약은 그대로 따른다.

## 0. 무엇을 푸는가
단일 세션은 **자기가 방금 내린 결론에 갇힌다.** 07-27 검수에서 실제로 드러난 것:
- 1차 검수가 "⑤ 팀원 문서는 개인 참여니 생략"으로 확정 → **2차가 회의록을 읽고 3인 팀임을 발견**(심사 제외 위험)
- 1차가 "계략과 정보대칭성을 같이 넣으면 밸런스 반전" 경고 → **2차 시뮬레이션이 계략은 레버가 아님(+1.8%p)을 실측**
- 3라운드까지 전부 1인 플레이 기준이었음 → **4차가 멀티에서 이탈 1건이 판을 사고사시킴을 발견**

즉 **관점을 갈아끼우지 않으면 같은 사각지대가 반복**된다.

## 1. 구조

```
오케스트레이터(메인 세션)
 ├─ 라운드 시작: brief.md(에이전트용) + ledger.md(내부용) 읽기
 ├─ 서브에이전트 3개 병렬 — 서로 다른 렌즈
 │    (a) 공모 심사 축   (b) 플레이 경험   (c) 4뷰 디자인·연출
 ├─ 결과 통합: 중복·이미 반영된 것 제거, 채택/반려 판정
 ├─ 문서·코드 반영 → 검증 → 커밋
 ├─ brief.md "현재 상태" 갱신 · ledger.md 라운드 행 추가
 └─ Discord 라운드 요약
```

- **brief.md**: 에이전트에게 **인라인으로 그대로 전달**되는 컨텍스트. 공모 요건 + 현재 프로젝트 상태 + 확정된 것 + 제약.
- **ledger.md**: 오케스트레이터 전용 원장. 라운드별 채택/반려/반영 파일, 사용자 액션. **에이전트에게 주지 않는다.**
- 둘 다 **저장소가 아닌 세션 스크래치패드**에 둔다 — 진행 상태는 산출물이 아니다.

## 2. 핵심 규칙

### 2.1 에이전트에게 루프의 존재를 알리지 않는다
매 라운드를 **"지금 이 시점의 프로젝트를 개선해달라"는 새 의뢰**로만 제시한다.
"N번째 라운드"라고 알리면 에이전트가 **이전 회차를 존중하려 들어** 반증을 주저한다.
실제로 2차가 1차 결론 2건을 뒤집을 수 있었던 것은 그것이 "이전 결론"이 아니라 **그냥 현재 문서**로 제시됐기 때문이다.

### 2.2 중복 방지는 오케스트레이터 책임
에이전트가 이전 라운드를 모르므로 같은 것을 다시 제안할 수 있다.
이를 막는 방법은 **경고가 아니라 상태 갱신**이다 — 채택된 개선을 brief.md의
"현재 프로젝트 상태 / 이미 확정된 것"에 녹여두면, 다음 라운드 에이전트는 **자연히 그다음 것**을 제안한다.
brief에 `**중복 제안 금지. 이 위에서 더 나아간 것 / 빠진 것 / 틀린 것을 지적하라.**`를 명시한다.

### 2.3 진단이 포화되면 생산으로 렌즈를 돌린다
07-27에는 3라운드에 진단 28건이 쌓였고 구현은 0이었다. 그 시점에 렌즈를
**"파일을 고치지 말고 초안 텍스트를 반환하라"**로 바꿔 영상 콘티·UI 카피·4뷰 명세를 한 라운드에 생산했다.
**진단 → 초안 생산 → 구현**으로 단계를 옮기는 판단은 오케스트레이터가 한다.

### 2.4 에이전트의 주장도 검증한다
에이전트는 근거를 대지만 **틀린다.**
- 4뷰 매트릭스 집계를 `6/10/6/6`(합 28)으로 썼는데 표는 25행 → 다른 에이전트가 재검산해 `3/10/9/3` 정정
- "라이브 LLM 미동작"의 원인을 "키 미설정 또는 쿼터 소진"으로 추정 → **실제로는 요청 파라미터 400**

**수치·인과는 실측으로 확인**하고, 확인 못 한 것은 문서에 "추정"으로 표기한다.

### 2.5 사람만 결정할 수 있는 것은 에스컬레이션한다
제출 형태(개인/팀), 과금, 촬영, 배포 승인. 에이전트가 이를 임의 확정하면
**"판단 비용 제거"처럼 보이지만 실은 되돌릴 수 없는 리스크**다. 미결로 남기고 기한·담당을 적는다.

## 3. 개발 라운드 (2026-07-28~)
문서에서 코드로 넘어가면 병렬 에이전트가 **같은 파일을 동시에 고칠 위험**이 생긴다.

### 3.1 파일 스코프 분할
라운드마다 에이전트에게 **서로 겹치지 않는 파일 집합**을 배정한다. 기본 분할:

| 슬롯 | 담당 영역 | 주요 파일 |
|---|---|---|
| A | 서버 규칙·에이전트 계층 | `apps/server/src/**` |
| B | 클라 HUD·DOM·온보딩 | `apps/client/index.html` · `apps/client/src/main.ts` |
| C | 렌더러 3종·공용 상수 | `apps/client/src/scenes/**` · `packages/shared/**` |

- 한 라운드에서 **두 에이전트가 같은 파일을 만지지 않는다.** 겹치면 그 항목은 다음 라운드로 미룬다.
- 문서 갱신(`.md`/`.html` 짝)은 **오케스트레이터가 통합 시점에** 한다 — 에이전트마다 같은 문서를 고치면 충돌한다.

### 3.2 작업 큐
`docs/design/20260727-execution-plan.md`의 날짜별 순서가 큐다.
**의존성 위반 금지** — 계획서가 명시한 선행 조건(예: `ZODIAC_COLOR` → 뷰4 실루엣,
`hudInset` 가드 → 패널 추가, 타이머 프리미티브 인자화 → 턴 클럭)을 건너뛰면 같은 파일을 두 번 연다.

### 3.3 검증 게이트 (통과 못 하면 커밋하지 않는다)
1. `pnpm -r typecheck`
2. `pnpm --filter @zodiac-clue/client build`
3. 규칙을 바꿨으면 **동작 확인**(솔로 1판 실행 또는 시뮬)
4. 초록이면 **기능별 커밋** → 푸시(배포 트리거)

**진실값(정답·판정·결정) 변경은 규칙 엔진에서만.** LLM은 표현 전용 — 이 경계는 라운드와 무관하게 불변이다.

### 3.4 되돌릴 수 있게 둔다
라운드마다 커밋을 남긴다. 한 라운드가 잘못되면 그 커밋만 되돌린다.
**여러 라운드를 모아 한 번에 커밋하지 않는다** — 어제 8시간치를 미커밋으로 쌓았다가
노출 위험을 마지막에 발견했다(운 좋게 커밋 전이라 막았다).

### 4.4 화면 검증 — 게이트 · 스크린샷 · 사람
디자인·연출을 바꾼 라운드는 **실제로 띄워서 찍는다.** typecheck·build는 화면이 맞는지 말해주지 않는다.

> **두 문장을 항상 쌍으로 쥔다.**
> ① **스크린샷은 근거이지 측정이 아니다.** ② **측정은 자기가 물은 것만 답한다.**
> ①만 있으면 수치가 없고, ②만 있으면 **묻지 않은 것은 영원히 안 보인다.**
> 07-28 실기 iPhone 스크린샷이 잡은 3건(액션 바 가림·문서 세로 스크롤·뷰4 얼어붙음)은
> 전부 이 절의 헤드리스 절차가 **390×844로 재고도 통과시킨 것**이다(로드맵 §9.7.1).
> 그래서 ②쪽에 **묻는 항목을 고정한 기계 판정**을 붙였다 — 아래 화면 게이트.

#### (1) 기계가 판정하는 것 — 화면 게이트 `pnpm gate:screen`
`scripts/gate-screen.mjs` + 기대값 `scripts/gate.config.mjs`의 `SCREEN`. 실제로 서버·클라·Chrome을 띄운다.

| 검사 | 무엇을 묻는가 | 왜 그 방법인가 |
|---|---|---|
| **S1 겹침·가림** | 화면별 «가려지면 안 되는 요소»와 «서로 가리면 안 되는 **쌍**» | 가려진 요소도 `getBoundingClientRect()`는 정상 크기를, `visibility`는 `visible`을 **그대로 보고한다.** 가림은 요소의 속성이 아니라 **요소 쌍의 관계**다. 기하 교차만 보면 오탐이 나므로(투명 래퍼·의도된 모달) **`elementFromPoint` 히트 테스트**로 «실제로 남이 덮었는가»까지 본다. 서브픽셀 접선은 가로·세로 양쪽 최소 변을 넘어야 센다 |
| **S2 세로 스크롤** | 게임 화면은 잠금, 랜딩·대기실은 허용 | 우리가 잰 것은 `scrollWidth vs innerWidth`(**가로**)뿐이었다. 기대값을 **화면별로** 둔다 — 한 기준을 전 화면에 밀어붙이면 곧 아무도 못 믿는 게이트가 된다 |
| **S3 터치 타깃** | `pointer: coarse` 에뮬에서 최소 변 44px | 이 저장소의 D-패드·하한은 전부 `@media (pointer: coarse)` 안이라 켜지 않으면 **심사자가 보는 화면과 다른 화면을 재게 된다.** 제외한 것은 **사유별 개수까지 인쇄**한다 |

- **음성 테스트 `--self-test`** — 런타임에 결함을 주입해 게이트가 **실제로 FAIL을 내는지**, 그리고 **무해한 겹침을 오탐하지 않는지**까지 확인한다. **전건 PASS 리포트는 «아무것도 안 잡는 검사기»와 구분되지 않는다.**
- **`--quick`에는 넣지 않는다.** 브라우저·서버·클라를 실제로 띄워 **기본 ≈40초 / `--full` ≈53초**가 걸린다(커밋 게이트 전체가 ≈3초). **push·촬영·제출 전 전체 모드 전용**이고 `pnpm verify`의 마지막 항목이다.
- **S4 뷰 간 HUD 동일성** — 4뷰가 같은 HUD를 쓴다는 것은 지금까지 **주장**이었다. 뷰를 실제로 전환한 뒤 보호 요소의 상자를 뷰1과 2px 허용으로 대조한다. 캔버스 픽셀은 재지 않는다(GPU 조건이 실기와 다르다) — **재는 것은 DOM/HUD뿐**이라 헤드리스에서도 유효하다.
- **결과 화면은 «확률»이 아니라 «규칙»으로 도달한다.** 탭 6개로 좌석을 전부 사람으로 채우면 덱 18장이 6명에게 3장씩 정확히 나뉜다 → 각 탭이 **남의 손패 카드**로 고발하면 그 카드는 정의상 정답이 아니므로 **오답이 구조적으로 보장**되고, 6명 손패의 여집합이 **정답 봉투 하나**로 확정된다. 확률 1/324가 아니라 실패 확률 0이다. 이 방식으로 결과 화면 6종 중 **4종**을 잰다.
- 포트는 **빈 포트를 스스로 고른다** — 2567·5173은 남의 것이라 쓰지 않고, 끝날 때 자기가 띄운 프로세스만 정리한다.
- 판정 불가(Chrome·서버 기동 실패)는 **FAIL이 아니라 SKIP**이고 사유를 인쇄한다. **통과로 세지 않는다** — 은폐된 미측정이 회귀보다 위험하다.
- 이 게이트는 **만들어진 첫 실행에서 우리가 만든 위반을 잡았다**(D-패드 46→42px · 뷰 선택 칩 25px → 로드맵 §7.12, 커밋 `17d008b`). 자기 저장소의 규칙을 깨는 것은 남이 아니라 **직전 라운드의 우리**다.

#### (2) 기계가 **못** 재는 것 — 사람이 봐야 하는 것
미(美)·정렬·읽힘은 기계가 못 잰다. 게이트는 실행할 때마다 **§사람 확인 목록을 인쇄한다 — 그 목록을 지우지 마라.**
- 여백·정렬·색의 조화 / 폰에서 **읽히는가**(44px은 «누를 수 있다»이지 «읽힌다»가 아니다) / **45초 동선**(가려지지 않은 것과 «다음에 무엇을 눌러야 할지 안다»는 다르다) / 의도된 겹침 목록이 지금도 맞는가 / **실기 1회**(주소창 접힘·노치·홈 인디케이터는 실기에서만 나온다).
- ⚠️ **안 재는 것과 못 재는 것을 섞지 않는다.** 결과 화면(정답 봉투가 동기화 상태에 없어 «고발 성공»을 결정론적으로 만들 수 없다)과 뷰2·3·4(헤드리스 소프트웨어 WebGL)는 **측정 못 한 화면**으로 사유와 함께 **상시 인쇄**된다. 조용히 빠지면 «통과»로 읽힌다.

#### (3) 스크린샷 (헤드리스 CDP) — 근거 첨부용

- `pnpm dev`(서버 2567 + 클라 5173)를 백그라운드로 띄우고, Chrome을 `--headless=new --remote-debugging-port=<포트>`로 실행해
  **CDP에 직결**한다(`ws` 모듈은 `node_modules/.pnpm/ws@*/node_modules/ws`에 있다). 러너는 세션 스크래치패드에 둔다.
- 찍을 것: **뷰1~4 각각**(`#viewList li[i].click()`) · 모바일 에뮬(`Emulation.setDeviceMetricsOverride` 390×844) ·
  `Tab` 입력 후 포커스 링 · 이번 라운드가 고친 경로(예: 패널 `display:none` 후 카메라 붕괴 여부).
