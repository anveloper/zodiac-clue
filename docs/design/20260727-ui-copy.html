NPC 대사는 자연스러운 사극 문장이어야 해서 조사를 못 피한다. 반면 UI·로그는 라벨형이 오히려 스캔이 빠르다 — 회피는 타협이 아니라 개선이다.

1.3 문장 규칙

  • 1문장 = 1행동. 안내문이 두 가지를 시키지 않는다.
  • 금지 상태에는 반드시 "그래서 뭘 하면 되는지"를 붙인다. 방 안에서만 가능해요. → 방 안에서만 제안할 수 있어요. 입구(🚪)로 들어가세요.
  • 느낌표는 판 전체에서 3종만 — 승리 · 최후 생존 · 미반증(정답 후보). 그 외는 마침표.
  • 이모지는 줄 앞 1개. 연속 배치 금지(🎉🎉, ❌ ⚠).
  • 사용자 지칭은 내 / 나. "유저"·"플레이어"는 UI에 쓰지 않는다(문서 전용).
  • 오류 문구에 에러·실패를 단독으로 쓰지 않는다 → ~하지 못했어요 + 다음 행동.

1.4 진실값 경계 (CLAUDE.md 규약의 카피 측면)

  • UI 문안은 정답·타인 손패를 암시하지 않는다. 정답 후보는 규칙엔진이 계산한 공개 결과라 허용, 정답인 듯해요 같은 추측형은 금지.
  • 나만 보는 정보에는 반드시 (나만 봄) — 반증 카드, 계략 엿보기, 증거 노트.
  • NPC 대사 본문은 LLM 출력이므로 이 문서가 확정하지 않는다. 확정 대상은 폴백 템플릿(§8.2)과 접두 기호뿐.

5액션 버튼 4종 — 상태별 문안

5.0 문안보다 먼저 고쳐야 하는 것

  • disabled 속성이 붙은 버튼은 title 툴팁이 뜨지 않고 클릭 이벤트도 발생하지 않는다. 지금 비활성 사유 안내가 한 번도 실행되지 않는 이유가 이것이다.
  • 비활성은 disabled 대신 aria-disabled="true" + .is-off 클래스로 표현하고, 클릭 핸들러는 살려 둔 채 첫 줄에서 사유를 안내하고 return 한다.
  • 같은 문장을 툴팁과 클릭 피드백에 공용한다. 문안을 두 벌 만들지 않는다.
  • 클릭 피드백 출력처는 로그가 아니라 턴 배너 부제 .ti-sub 선행 — 시선은 버튼 근처에 있고 로그는 화면 반대편 끝이다.
