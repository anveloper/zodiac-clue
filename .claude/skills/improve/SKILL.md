# zodiac-clue 개선 루프 — 1회차

**매 회차는 작은 단위 1건만 완결한다.** 여러 건을 섞으면 무엇이 효과였는지 가를 수 없다.

## 축 (2026-08-26 오너 갱신)
**«실제 상용화할 수 있는 게임처럼» 만드는 것이 매 회차의 목표이고, 상용화 가능한 뷰가 최우선이다.**

- **화면 개선의 비율을 높게 가져간다.** 1~6회차가 규칙 정합성·문안·문서 정정에 치우쳤다 —
  로직은 맞아 가는데 화면이 상용 수준으로 안 올라왔다는 것이 오너 판단이다.
- 회차 주제를 고를 때 **화면 완성도를 먼저 본다**: 레이아웃·타이포·색·여백·모션·에셋.
  **문안·문서만 고치는 회차가 연속되지 않게 한다.**
- 부축(종속): 게임 로직 단순화 — 클루 정통 룰의 복잡도가 신규 유입의 이탈 지점이라는
  가설(로드맵 Q2)을 줄여 나간다. 여전히 유효하나 **이제 화면 뒤에 선다**.

## 절차

### 1. 계획 확인
`docs/plans/active/`를 **먼저** 읽는다.
- 진행 중 플랜이 있으면 그 다음 미완 항목을 수행한다.
- 없으면 `docs/plans/done/`의 최신 플랜 «다음 회차 후보»를 본다 — 이전 회차가 큐를 남겨 둔다.
- 그것도 없으면 현재 게임 화면을 분석해 **기능 명세서(플랜)를 새로 작성**하고 시작한다.
- 반드시 **한 회차에 끝나는 크기**로 쪼갠다. 플랜 포맷은 `docs/plans/README.md`
  (`goal` / `tasks` / `done-criteria`, 압축 `.md`만).

### 2. 디자인 및 코드 구현
- 화면을 **눈으로 본다.** `pnpm gate:screen`이 실판 캡처를 남긴다
  (경로는 게이트 출력의 `PNG:` 줄). 필요하면 `pnpm dev` 후 직접 확인한다.
- 개선 전/후를 대조한다. 에셋이 필요하면 이미지 생성도 포함한다.
- **색·문안을 바꿀 때는 명암비를 직접 계산한다**(WCAG AA 4.5:1). 눈대중 금지.
- 문안은 `docs/design/20260727-ui-copy.md`가 **단일 출처**다. 구현만 고치지 말고 명세도 고친다.

### 3. 서브에이전트 검수
구현 후 서브에이전트에게 코드·UX 검수를 받는다. 프롬프트에 반드시 넣을 것:
- 변경 내용과 **내가 근거로 삼은 판단**(그 근거가 틀렸는지 검증하게 한다)
- 「칭찬 금지. 틀린 것·놓친 것·더 나은 방법만. 각 지적에 `파일:줄`과 근거.」
- **지적을 받으면 직접 코드로 재확인한 뒤 반영한다.** 서브에이전트도 틀린다.
- 검수가 뒤집은 판단은 플랜에 **기록**한다 — 같은 실수를 반복하지 않기 위해.

### 4. 다음 계획 작성
이번 회차 결과를 플랜에 적고 `docs/plans/done/`으로 옮긴다(`status: done(날짜)`).
**«다음 회차 후보»를 남긴다** — 다음 회차가 1번부터 다시 찾지 않게.

### 5. 커밋 · 브랜치 푸시
- 미머지 체인 **끝 브랜치**에서 `feat/<주제>`를 딴다.
  (규칙상 `main`이지만, `main`에는 이전 회차가 없어 거기서 따면 **게이트 기준선이 무너져**
   이번 회차가 무엇을 깨뜨렸는지 판정할 수 없다. 머지되면 `main`으로 돌아간다.)
- 기능별로 묶어 커밋. **Conventional Commits. AI 협력 문구 제외.**
- `pnpm -r typecheck` + `pnpm verify:quick` 통과 후 푸시. 실패하면 사유를 플랜에 적고 **푸시하지 않는다.**
- **`main` 머지는 하지 않는다.** main push = 프로덕션 자동배포(Vercel + OCI)이고 무인 배포는
  승인되지 않았다. 회차 끝에 «머지 대기 브랜치 목록 + 요약»을 보고하고, 사용자가
  «머지해줘»라고 하면 그때 머지한다.

## 제약
- 저장소 규칙: `CLAUDE.md` / `AGENTS.md` / `docs/plans/README.md`.
  문서 이원화 — `.md`(압축) + `.html`(수기 디자인) **양쪽 다** 고친다. `.html` 누락이 반복 사고다.
- **렌더러는 Phaser 하나.** 3D·Three.js·뷰 선택기를 되살리지 않는다.
- **진실값(정답·판정·승패)은 서버 규칙 엔진에만.** LLM은 표현 전용.
- **게이트 래칫·기준선을 완화하지 않는다.** 고칠 거면 실제로 고친다.
  현재 알려진 red: `right-column` S8(로그 패널 최소 몫 · 레이아웃 설계 결함) ·
  번들 B1 래칫. `roomlist-ended` S7은 **플레이크**다(120초 방 잠금 타이밍 — 재실행하면 갈린다).

## 문서·게이트 인용 규칙
게이트 설정과 문서의 **실측 주석은 작성 시점의 코드**를 말한다. 인용하기 전에 **현재 코드로
재확인**한다. (1회차에 `#1f2b3a`라는 낡은 실측을 그대로 옮겨 적고 그 위에 결정을 세웠다가
검수에서 뒤집혔다. 저장소도 같은 규칙을 안다 — 「`파일:줄` 인용은 커밋 해시와 함께 읽어라」)

## 오너가 이미 정한 것 (다시 묻지 말 것)
- ✅ **승리 선언 용어 = «신고»** (2026-08-26 확정 · **쿼카가 정한 표기**). 1~6회차 대기 항목이었다.
  사용자에게 보이는 문자열은 전부 `신고`. **내부 식별자(`accuse`·`doAccusation`·`bot-accuse.ts`)와
  코드 주석의 «고발»은 도메인 용어로 그대로 둔다** — 사용자 문안과 코드 어휘는 다른 층이다.
  새 문안에 «고발»이 사용자 눈에 닿는 자리로 들어가면 잘못이다.
